# 战斗投射、角度与基元生效阶段详细规格

> **GDD 章节号（FG0-DOC-01 注）：** 本文件里的"GDD §x"都指生物机械版 GDD（0.1 及更早），原文见 [ProjectA_GDD_bio-mechanical_archived-2026-09-18.md](../Archive/ProjectA_GDD_bio-mechanical_archived-2026-09-18.md)，与现行 GDD 0.2（`../ProjectA_GDD.md`）的章节不对应。

> 适用：玩家直控、友军 AI、敌军、Alpha、器官/基因、近战、弹体、场地、光环、召唤与表现预览。

## 1. 核心结论

同一个装配无论由玩家、友军 AI、敌方还是 Alpha 使用，都先编译为同一种 `AbilityRecipe`，再带着当前身体的 `EmissionContext` 投射到同一模拟世界。控制者只决定何时用、朝谁用和愿意承担多少风险，不能决定它“变成另一种攻击”。

每个效果必须回答两个问题：

1. **何时生效**：装配、预留、发射、飞行、接触、终点、持续、回返或事后；
2. **在哪里生效**：发射者、器官挂点、弹体、命中目标、命中点、指定场地点或召唤物。

回答不出就不能交给程序猜默认值。

## 2. 坐标与发射上下文

### CP-REQ-001 世界平面

当前 ProjectA 战斗真相使用世界 XZ 平面，模拟向量以 `float2(x,z)` 表示；Unity Y 只用于表现高度。抛投可以在表现层显示弧线，但命中和落点仍由同一弹体状态/轨迹参数确定。未来若切换完整三维碰撞，必须升级规格版本，不能局部把 Y 混入某些技能。

### CP-REQ-002 EmissionContext

每次释放创建不可变发射上下文，至少包含：

- `SourceEntityId`、`SourceFaction`、`ControllerKind`；
- `AbilityRecipeId`、装配签名、模板版本；
- `BodyPosition`、`BodyRadius`、`BodyForward`；
- `EmitterSocketId`、`EmitterPosition`、`EmitterForward`；
- `AimMode`、`AimDirection`、可选 `TargetEntityId/TargetPart/TargetPoint`；
- 发射时目标位置/速度快照与可见性；
- 资源事务 ID、随机种子、攻击序号；
- 友伤规则、目标阵营掩码；
- 当前暂停/时间尺度只读状态。

后续飞行不得再读取“全局玩家位置”或“当前激活器官”来补数据，否则切换身体后弹体会串体。

### CP-REQ-003 发射点

优先级：

1. 当前身体上该器官的真实挂点；
2. 底盘声明的同类型标准挂点；
3. 身体中心沿 `EmitterForward` 前推 `BodyRadius + ProjectileRadius + Clearance` 的兼容位置。

炮口 VFX、弹体碰撞、声音和后坐力都读取同一个发射点。挂点在身体内部、障碍物内部或越界时，沿发射方向做最短安全推出；失败则拒绝释放并返回 `EmitterBlocked`，不能把弹体瞬移到目标旁边。

### CP-REQ-004 身体朝向

每个可作战实体保存最后有效身体朝向。移动、瞄准或动画可以更新它，但零向量不能把朝向重置为世界 +X/+Z。无鼠标、无目标、无移动时沿用最后有效朝向；首次生成由底盘/出生点声明，调试入口才可使用统一默认值。

## 3. 瞄准方向与发射角

### CP-REQ-010 玩家直控

1. 指针射线与当前战斗平面相交得到 `TargetPoint`；
2. `AimDirection = normalize(TargetPoint - EmitterPosition)`，不是从全局玩家中心计算；
3. 若锁定具体接点，目标点取发射帧接点世界位置；软吸附只能在玩家可调角度内修正；
4. 指针无法投影或与发射点重合时，沿用最后有效瞄准方向，再退到身体朝向；
5. 移动方向不是常规瞄准后备，除非当前输入方案明确为手柄双摇杆缺失模式；
6. UI 预览线使用即将提交的同一 `EmissionContext`。

### CP-REQ-011 AI 瞄准

AI 从教义允许的目标集合选择目标，再按投送类型求方向：

- 瞬时/近战：指向目标当前可攻击点；
- 直线弹体：用目标速度和弹速求一次拦截提前量，解不存在时瞄当前位置；
- 追踪弹体：初始方向仍需朝目标允许角度内发射，追踪不是全向自动命中；
- 抛投/场地：瞄向预测落点，考虑最短/最大射程和阻挡；
- 无合法目标：不释放攻击；守备压制可朝玩家明确指定区域盲射，但要支付资源并产生暴露。

AI 误差必须来自明确的精度/压力参数并进入种子，不能通过读取不同数值管线制造差异。

### CP-REQ-012 多发与扇角

`SpreadAngle` 是以 `AimDirection` 为中轴的总张角，`Count` 是本次发射的发数/段数：

- `Count = 1`：严格沿中轴发射；只有独立的 `AccuracyJitter`/失控状态才能产生偏差；
- `Count > 1` 且 `SpreadAngle = 0`：同向发射，可由枪口位置或极小防重叠偏移区分；不得自动改成 360° 环射；
- `Count > 1` 且 `SpreadAngle > 0`：在 `[-SpreadAngle/2, +SpreadAngle/2]` 内确定性均分；奇数包含中轴，偶数左右对称；
- 环射必须由 `Radial`/`OrbitEmission` 等明确空间基元声明；
- 所有角度以度存储、在单一纯函数内转换；预览、AI、模拟和表现不得各写公式。

### CP-REQ-013 转向与旋转

- `Homing`：飞行阶段逐帧限制角速度地转向，不是发射瞬间改落点；
- `Spin`：弹体自身或近战动作的旋转率，作用对象由投送形态声明；
- `Orbit`：相对宿主/弹体/命中点的轨道半径，必须带 `OrbitAnchor`；
- `Bounce`：接触障碍的反射，入射角和法线来自真实碰撞；
- `Return`：终点/命中后进入回返阶段，目标为发射者当前合法接收点；发射者死亡时按配方销毁、落地或转为自由弹体。

## 4. 统一阶段链

### CP-REQ-020 阶段枚举

封闭枚举：

1. `Compile`：器官/基因编译、冲突代数、派生参数；
2. `Reserve`：检查失能、冷却、代谢、过载债、弹药/召唤容量并预留；
3. `Emit`：取得发射上下文、生成弹体/扇形/场/光环/召唤请求；
4. `Travel`：速度、寿命、重力/阻力、追踪、旋转、轨道、拖尾、障碍；
5. `Contact`：命中目标/接点、穿透、状态、击退/牵引、连锁起点；
6. `Terminate`：到寿命、撞墙、命中终止或手动引爆；
7. `Impact`：爆炸、残留、场地生成、分裂子事件；
8. `Sustain`：光环、区域、召唤物、持续伤害的周期结算；
9. `Return/Post`：回返、吸血、退款、击杀触发、冷却提交与因果记录。

同一事件可以经过多个阶段，但每个字段只由声明的阶段消费一次。重复消费属于回归。

### CP-REQ-021 基元声明

每个基元目录项至少声明：

`PrimitiveId / Phase / Anchor / TargetRule / StackRule / CostRule / ChildInheritance / ProcCost / FriendlyFire / AIUse / Telegraph / FailureFallback / DeterminismKey`

属性混合可以开放组合；但空间与生命周期语义不能只藏在注释或宿主 if/else 中。

## 5. 投送形态

### CP-REQ-030 Projectile

- 在发射点生成真实弹体；
- `Damage/Status` 通常在 Contact，`Explosion/Residue/Split` 在 Impact；
- `Trail` 沿真实已走路径按距离或时间采样；
- 弹体的判定与渲染读取同一 `ProjectileState`；
- 高速命中使用整段 sweep，不只判帧终点；
- 穿透后保持入射方向与剩余预算，不能隔空补一个命中点。

### CP-REQ-031 Melee/Cone

- 锚点为器官挂点或身体接点；
- 方向为发射上下文中轴；
- 范围由触及距离、扇角和厚度共同定义；
- `Count` 默认解释为有节奏的多段，而不是同一帧把伤害乘 N；
- 每段可被打断，并按配方决定是否再次支付资源；
- 近身豁免、背后命中和接点选择必须显式定义。

### CP-REQ-032 Field

- 必须有 `PlacementRule`：指定点、抛投落点、沿路径或附着目标；
- 发射阶段只创建投放请求，效果在落点/持续阶段生效；
- 到达前目标点失效时按配方落地、跟随最后位置或取消退款；
- `SpreadAngle` 可形成多个投放点，但每个点仍来自同一角度规则。

### CP-REQ-033 Aura

- 默认锚定发射者并随其移动；若锚定召唤物/目标必须声明；
- `Scale/AuraRadius` 改真实作用范围；
- `Count` 解释为每次脉冲的离散段，`TickRate` 控制持续频率，两者不可重复乘算；
- 发射者死亡、器官失能或断供时按配方立即结束或衰减。

### CP-REQ-034 Summon

- 必须生成真实实体并使用 `SummonId`、数量、阵营、所有者、位置、装配、寿命/维护成本和容量；
- 不能用伤害区、日志或 VFX 代替召唤通过验收；
- 召唤点由发射上下文与投送规则决定；位置无效时寻找最近合法点或拒绝并退款；
- 召唤物死亡/解散遵守资源和样本规则，不能形成召唤—回收套利。

## 6. 常用基元的生效锚点

### CP-REQ-040 封闭基线表

| 基元 | 默认阶段 | 默认锚点 | 说明 |
|---|---|---|---|
| Damage/Heal/Poise/Status | Contact/Sustain | 命中目标 | 无目标的 Field/Aura 在范围查询后逐目标应用 |
| Count | Emit 或动作序列 | 发射上下文 | 按投送形态生成多发/多段，不默认乘总伤害 |
| Scale | Compile | 弹体/范围/触及几何 | 不只缩放 VFX |
| SpreadAngle | Emit | 瞄准中轴 | 单发不随机偏移，环射需独立声明 |
| Speed/Lifetime/Gravity | Travel | 弹体 | 同时决定射程与终点，预览共用 |
| Homing/Spin/Orbit | Travel | 弹体或声明锚点 | 必须改变真实轨迹和命中时机 |
| Pierce/Bounce | Contact | 弹体 | 消耗次数/过程预算 |
| Chain | Contact/Post | 首个命中目标 | 重新按阵营、距离和已命中集合选目标 |
| Pull/Knockback | Contact/Sustain | 命中目标 | 改真实位置/速度；仅贴状态图标不算完成 |
| Trail | Travel | 已走路径 | 沿路径结算，不在终点补算 |
| ExplodeOnHit | Impact | 实际命中/终止点 | 撞墙、寿命结束是否爆炸由配方声明 |
| SplitOnHit | Impact | 命中点 + 入射方向 | 子弹角度围绕入射方向，不围绕世界轴 |
| Linger/Residue | Impact/Sustain | 命中/终止点 | 生成真实持续场或地形记录 |
| Return | Return | 发射者接收点 | 发射者无效走显式降级 |
| Summon | Emit/Impact | 声明的召唤点 | 生成真实实体 |
| 自身位移/后坐 | Emit | 发射者 | 不误作用于被击目标 |
| 吸血/击杀触发 | Post | 发射者/资源账 | 只按真实已结算伤害或击杀触发 |

新增基元必须加入此表或通过目录生成同等信息。

## 7. 开放组合与递归预算

### CP-REQ-050 默认可组合

器官和基因默认进入通用阶段链。只要字段语义不矛盾，组合必须有确定结果；不能因为当前内容目录未列 pair 就拒绝。

### CP-REQ-051 显式冲突

允许的冲突理由只有：互斥的唯一锚点、互斥投送形态、无法同时满足的所有权/目标规则、预算为零或产品明确的生理排斥。冲突必须返回原因、指出冲突节点并允许玩家调整顺序。

### CP-REQ-052 子事件继承

分裂、连锁、爆炸、回返和召唤死亡可能产生子事件。每个事件携带：

- `Generation`；
- `ProcBudget`；
- 已消费的一次性触发集合；
- 来源链；
- 随机子种子。

子事件默认继承物质、伤害类型、阵营、表现主题和允许继承的运动参数；会再次生成自身的触发需要消费预算。预算耗尽时保留基础结算、停止继续生成，不能崩溃、卡死或无限递归。

### CP-REQ-053 顺序

基因有序。编译器必须展示顺序造成的变化；交换顺序若结果相同，也要由代数证明，而不是因为宿主忽略字段。

## 8. 资源、冷却与控制者

### CP-REQ-060 同一本身体账

资源、冷却、过载债、器官失能与召唤容量按身体/装配归属。切换玩家与 AI 不重置。AI 与玩家调用同一 `Reserve → Commit/Refund` 事务；玩家可覆盖安全阈值，AI 默认遵守教义阈值。

### CP-REQ-061 提交时机

- 发射请求被模拟接受后提交基础成本；
- 因非法目标、阻挡炮口、资源不足而未发射则全额退款/不扣；
- 已生成弹体后未命中通常不退款；
- 持续/引导动作按配方预留并逐段提交，中断释放未消费部分；
- 暂停不推进冷却或持续消费。

## 9. 阵营、目标和手术接点

### CP-REQ-070 目标过滤

每次查询显式带阵营掩码、友伤策略、已命中集合和目标类型。玩家、友军、敌人、召唤物、环境器官和可中立对象不靠“默认敌人”隐式处理。

### CP-REQ-071 接点

接点是随身体朝向/动画更新的世界挂点，包含类型、半径、完整度、可提取物、装甲/暴露状态。弹体在真实 sweep 命中帧选择接点；范围攻击默认伤身体，只有明确的精确范围基元才可伤接点。

接点不能永久固定为 `Primary/Secondary` 两个占位名。原型兼容层可映射这两个槽，但正式内容从配置/骨骼挂点读取 N 个接点。

## 10. 表现与反馈

### CP-REQ-080 同源表现

瞄准预览、炮口、弹体、命中、爆炸、残留和声音均读取同一发射/弹体/命中事件。任何 Presenter 另算落点、扇角、飞行时间或随机方向都视为第二真相源。

### CP-REQ-081 拒绝反馈

至少区分：无器官、器官失能、冷却、代谢不足、过载、安全阈值、无目标、目标非法、炮口阻挡、落点非法、召唤容量、信号/权限。UI、音效和调试错误码使用同一原因。

### CP-REQ-082 可访问性

提供可调瞄准辅助、接点吸附、弹道/危险区轮廓、色彩以外的形状编码、低闪烁和低震动。辅助不能改伤害真相或偷偷提高敌人碰撞半径。

## 11. 生命周期边界

### CP-REQ-090 发射者死亡/换控

已生成弹体保持原 Source 与装配签名，不因控制权切换重写。需要持续由发射者供能的效果按配方结束；独立弹体继续。

### CP-REQ-091 目标死亡/卸载

追踪丢目标后按配方重选、沿当前方向飞行或终止；不能跳到无关阵营。附着效果落到尸体、世界点或结束的规则必须声明。

### CP-REQ-092 存读档

保存需要跨档存在的弹体/场/召唤/持续事件的阶段、位置、方向、剩余时间、来源、预算和随机状态。若设计选择腔室切换时清空，必须在切换前确定性结算或明确销毁并反馈。

## 12. 现有实现差距登记

下列是已实读的当前事实，不是批准的产品语义：

- `OrganReleaseRunner` 无有效方向时退到世界 `+X`，发射点只有身体中心前推；
- `CombatBallistics.FanDirection` 在单发且有扇角时做确定性随机偏转；无扇角多发会环射；
- `MetabolicSliceBridge` 多处仍读取全局玩家位置/方向，部分非弹道底盘使用常量落点；
- 历史契约记录过友军常数伤害、召唤用区域代替、空交互、缺少友军释放反馈；
- 手术接点仍是两个占位槽，且不随身体朝向旋转；
- `Pull/Knockback`、召唤、持续场等字段曾存在只贴状态/摘要或最小替代。

这些项目进入 `05_M1_M4_Backfill_And_Acceptance.md`，不得因“此前里程碑 Done”跳过。

## 13. 自动验收

### CP-TEST-001 角度表

固定发射点和瞄准向量，分别验证 Count 1/2/3/4、Spread 0/60/360、独立 AccuracyJitter、Radial；逐发比较方向向量，不只数弹体数量。

### CP-TEST-002 发射点

不同身体半径、旋转和器官挂点发射；断言碰撞与炮口 VFX 同点，身体内/墙内挂点安全拒绝或推出。

### CP-TEST-003 阶段与锚点

为表中每个基元构造一个能区分“发射点生效”和“终点生效”的场景：发射者与目标相距足够远，两处各放对照单位，逐状态断言只影响正确位置。

### CP-TEST-004 控制者一致

同一身体、同一装配、同一目标与种子分别由玩家入口和 AI 入口释放，逐字段比较发射上下文、ProjectileState、命中事件、资源账和冷却；只允许时机/瞄准误差来自已声明控制策略。

### CP-TEST-005 子事件预算

组合 Split + Chain + Bounce + Return + Explode + Linger，验证来源链、继承、最大事件数、无递归爆炸、相同种子指纹一致。

### CP-TEST-006 边界
