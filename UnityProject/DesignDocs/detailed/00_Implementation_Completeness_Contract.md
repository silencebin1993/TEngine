# 实现完整性与自动验收契约

> 状态：ProjectA 所有新故事、返工故事和里程碑门禁的强制执行规范。
> 目的：防止 AI 只实现任务标题或示例，留下一个“能编译但不像正常游戏”的半成品。
> 产品语义上级：`../ProjectA_GDD.md`（GDD 0.2）。实施顺序上级：`../ProjectA_FullGame_Milestones.md`（0.2）；Demo 阶段为 `../ProjectA_Milestones.md`（Demo 版本冻结）。

## 1. 完成的定义

“完成”指玩家能通过正式入口得到完整、可理解、可恢复的体验，不指某个类、字段、按钮或测试夹具已经存在。

以下均不能单独证明完成：

- 数据结构有字段，但生产路径没有读取；
- 方法可被测试直接调用，但真实输入、AI、场景或 UI 没有入口；
- 用区域伤害代替召唤、用常数伤害代替真实装配、用日志代替反馈；
- 只测成功路径，没有死亡、断网、暂停、目标丢失、存读档和资源不足；
- 把缺失项写成“非目标”“占位”“后续再做”，却没有编号、承接里程碑和阻塞关系；
- 自动测试只证明“产生了伤害”，没有逐字段证明角度、锚点、次数、阵营、资源和状态一致；
- 白模场景可运行，但正常开局无法进入该功能。

## 2. 需求是封闭集合，示例不是

### IC-REQ-001 需求 ID

每份详细规格必须给可实现要求分配稳定 ID。每个故事必须点名自己负责的需求 ID，不得只写“参考某文档”。

### IC-REQ-002 封闭清单与扩展规则

- 标记为“封闭枚举”的列表必须逐项实现；新增项需要改规格。
- 标记为“开放集合”的系统必须给出通用解释规则、冲突代数和未知值降级，不能靠穷举当前内容。
- “例如”“包括”“可以”默认不是完整清单。实现者必须继续读取同节规则和需求 ID，不能只实现例子。

### IC-REQ-003 非目标的边界

“非目标”只能阻止当前故事顺手扩张，不能覆盖本契约的基础完整性。被延后的玩家可见功能必须登记：

`DEBT-ID / 用户会看到什么 / 为什么当前不能完成 / 临时降级 / 承接故事 / 最迟门禁 / 自动测试`

没有承接故事的“以后再做”视为遗漏。会让正常流程失效的降级必须阻塞里程碑出口。

## 3. 每个系统必须闭合的十四个面

故事 Ready 前，逐项回答；不适用也要写理由。

| # | 完整性面 | 必须回答 |
|---:|---|---|
| 1 | 玩家目的 | 玩家为什么使用，如何帮助当前生存目标或最终目标 |
| 2 | 正式入口 | 哪个输入、命令、AI 决策、场景事件或 UI 进入；谁拥有输入 |
| 3 | 数据真相 | 唯一所有者、稳定 ID、生命周期、谁只读、谁可写 |
| 4 | 状态机 | 初态、合法转换、完成、失败、中断、恢复、幂等性 |
| 5 | 空间语义 | 坐标平面、发射/交互锚点、朝向、范围、遮挡、可达性 |
| 6 | 资源事务 | 来源、预留、支付、在途、结算、取消、退款、守恒 |
| 7 | 阵营与权限 | 谁能对谁做什么，友伤、所有权、控制与抢夺 |
| 8 | AI 与直控 | 是否共用规则，AI 的选择阈值，玩家的额外精度/风险价值 |
| 9 | 时间 | 暂停、0.5×/1×/2×、冷却、延迟、离线与帧序 |
| 10 | 生命周期边界 | 死亡、卸载、槽位复用、断网、换场、退出、读档 |
| 11 | 反馈与可访问性 | 预览、成功、失败原因、危险、声音、色盲/低动态替代 |
| 12 | 确定性 | 随机种子、顺序、重放、保存哪些选择、相同输入是否一致 |
| 13 | 规模与性能 | 1 个、典型规模、压力规模；稳态分配和最坏路径 |
| 14 | 测试与可观测性 | 单元、集成、正式入口 E2E、负向、视觉证据和调试查询 |

## 4. 故事 Ready 门禁

故事开工前必须有一张短任务卡，至少包含：

1. 一句可判真假的玩家结果；
2. 精确规格路径、章节和需求 ID；
3. 当前实现事实与已知冲突，注明是代码实读还是历史文档；
4. 本故事覆盖的十四面，以及明确不适用项；
5. 正式入口调用链和唯一数据真相；
6. 正常、失败、中断、恢复、存读档和压力场景；
7. 会新增/修改的公开接口与兼容策略；
8. 自动验收脚本位置、断言名称和预期数值/状态；
9. 本故事结束后仍存在的 `DEBT-ID` 及承接任务；
10. 与前后故事的阻塞关系。

若“真实代码与规格不一致”，先登记冲突并按权威层级处理；不得用当前代码存在来反向删掉产品需求。

## 5. 实施纪律

### IC-REQ-010 单一真相

模拟、判定和表现不得各算一份角度、落点、伤害或资源结果。表现读取模拟状态/事件；预览调用与正式结算相同的纯计算，或读取同一份已生成结果。

### IC-REQ-011 正式入口与测试入口成对

允许纯函数或调试直调做快速断言，但凡需求写到按键、命令、AI 或场景入口，至少有一条自动测试通过正式入口驱动。测试夹具不能成为唯一消费者。

### IC-REQ-012 通用规则优先

开放组合系统不得按器官 ID、敌人 ID 或当前三条内容逐项硬编码。固定内容可以数据化，行为由阶段、标签、接口和预算解释。

### IC-REQ-013 Reject-to-safe 也要可见

未知内容、失效目标或坏存档可安全拒绝，但必须返回稳定原因并给玩家可理解反馈。静默无反应不是安全降级。

### IC-REQ-014 不隐藏占位

占位必须在玩家界面或开发调试中明确标记，且在对应里程碑门禁前被替换。若占位与正式语义不同，不能用它通过正式门禁。

## 6. 自动验收金字塔

每个故事按风险选择最小但完整的组合；玩家不负责逐条找漏项。

1. **纯规则测试**：角度、资源事务、状态转换、兼容代数、确定性。
2. **领域集成测试**：真实注册表、模拟世界、AI/玩家两入口、死亡与暂停。
3. **正式入口 E2E**：从输入或命令进入，到模拟结果、UI 反馈和任务完成结束。
4. **固定种子回放**：记录命令/输入流，重放后比较状态指纹、资源账、弹体和进化账本。
5. **压力场景**：典型与目标上限规模；记录 CPU、分配、卡死、命令失败率。
6. **视觉/声音证据**：只对必须看见/听见的要求进入最短 Play 流程；截图或录像必须同时附机器状态断言，不能只凭“看起来差不多”。

每条正向断言至少配一条能排除假阳性的对照。例如验证“过载单位不开火”时，同场放一名未过载同配置单位确认内核仍在工作。

## 7. 故事 Done 输出

完成报告必须包含下表，任何一行空白即不能标 Done：

| 需求 ID | 生产入口 | 代码落点 | 自动测试/场景 | 结果 | 玩家可见反馈 |
|---|---|---|---|---|---|
| 示例 `CP-REQ-021` | 直控左键 | `...` | `[xx]-projectile-angle` | 通过 | 瞄准线与真实弹道重合 |

并附：

- 修改文件；
- 新增/改变的规则真相；
- 负向与恢复场景结果；
- 性能数据和测试规模；
- 未完成债务表；
- 与上一个固定种子基线的回归差异；
- 没有覆盖的内容及其阻塞门禁。

测试数量不是 KPI。测试必须逐语义断言，不允许通过改低预期、删除旧断言或只比总数让红灯变绿。

## 8. 里程碑出口门禁

### IC-REQ-020 需求覆盖率

里程碑涉及的所有需求 ID 必须 100% 映射到代码和自动测试；标为“未来阶段”的 ID 必须不属于本出口，且有明确进入条件。不存在“覆盖了大部分所以先过”。

### IC-REQ-021 玩家旅程机器人

每个里程碑至少一条固定场景从正常入口完成完整旅程，不允许全部测试绕过 UI/输入/AI 直接调用深层方法。机器人可以使用可测试输入适配器，不要求人工点击。

### IC-REQ-022 反向旅程

至少覆盖一次资源不足、目标死亡、断网/失联、暂停、存读档或路径失败，证明玩家能理解并恢复，而非软锁。

### IC-REQ-023 体验审核的边界

功能正确性、回归、视觉状态存在性和错误反馈由 AI 自动验收。人工只在里程碑末审核乐趣、信息负担、视觉品味与最终取舍，不承担“发现 80% 没做”的功能测试工作。

## 9. M1–M4 返工适用方式

已标 Done 的故事只代表通过当时任务卡，不自动代表满足本契约。统一按 `05_M1_M4_Backfill_And_Acceptance.md` 做一次差距审计；不得改写历史完成事实，但缺口必须进入新故事并在 M4 出口前收口或被明确移交到确实依赖 M5+ 的门禁。
