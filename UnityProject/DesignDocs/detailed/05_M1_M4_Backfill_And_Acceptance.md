# M1–M4 规格补录、缺口返工与自动验收计划

> 当前基线（2026-09-15）：M1、M2、M3 已按旧任务卡标 Done；M4-01～M4-05 Done；下一原计划项为 M4-06。
> 本文件不改写历史完成事实。它定义新详细规格发布后的产品完整性复验与返工顺序。
> 强制门禁：`00_Implementation_Completeness_Contract.md`。

## 1. 执行原则

1. M4-04 与 M4-05 的原任务和证据保持不回退；它们仍按新规格参加复验。
2. 在进入 M4-06 前先执行 **M4-R00 差距审计**。
3. 审计只读，不以“测试总数绿”宣布完成；逐条映射需求 ID、生产入口、代码和断言。
4. 缺口按依赖串行修复。每个返工故事只负责一个完整玩家结果，不按“改一个类”拆碎。
5. 功能正确性由自动测试与固定旅程机器人完成；用户只在 M4-GATE 审核体验方向，不负责发现基础遗漏。
6. M5/M6/M7 才具备前置数据的内容可以移交，但必须有 ID、承接故事和当前可验证接口；不能只写“以后”。

## 2. M4-R00：需求覆盖差距审计

### M4-R00-01 建立覆盖矩阵

- **输入文档：** 本目录 00～04、`../ProjectA_GDD.md`、`../ProjectA_Milestones.md`、`../migration/` 现有契约、ComposeEngine HostApply 契约。
- **读取代码：** 只读 M1–M4 真实入口、模拟桥、装配/释放、手术、蓝图/谱系/模板、编队/教义/路径、UI 与自检。
- **交付：** `DesignDocs/migration/M1_M4_Completeness_Audit.md`。
- **每行：** `REQ-ID / 当前生产入口 / 当前实现 / 自动测试 / 完整·部分·缺失·冲突 / 用户症状 / 修复故事`。
- **硬规则：** “字段已存在”“测试可直调”“写有 TODO”只能判部分或缺失。
- **验收：** 00～03 文档内所有 M1–M4 相关 ID 均出现一次且只有一次；所有旧契约的“占位/降级/没覆盖/已知缺口”都有归属。

### M4-R00-02 生成串行返工队列

按下列优先级建 story：

1. 数据真相/身份/资源重复或串体；
2. 正式入口不存在；
3. 战斗角度、命中、阵营或成本错误；
4. 命令/AI 状态机不能闭合；
5. 死亡、暂停、存读档与失败恢复；
6. UI/表现与可访问性；
7. 性能规模与内容扩展。

若审计证明某项已经完整，记录证据后跳过对应返工故事，不为了“计划里有”重复造代码。

## 3. M1 返工包：控制身份与生命周期

### M1-R01 身份唯一性全入口复验

- **需求：** IC-REQ-010～013、CP-REQ-002、FC-REQ-001。
- **检查：** 玩家、PlayerMinion、敌方、召唤物、晚生成单位、槽位复用、控制候选、命令下达、伤害来源、UI 与相机全部使用稳定 ID/显式阵营。
- **正向：** 三名以上友军连续切换，数组重排后控制、HUD、装配和发射来源仍指同一身体。
- **负向：** 敌军、中立物、死亡/卸载实体、无信号实体返回稳定失败原因，不改变当前控制。
- **生命周期：** 死亡回弹、世界重置、换场、暂停、Resume、坏存档和旧存档。
- **完成证据：** 生产入口 E2E + 槽位复用压力，不只调用切换 API。

### M1-R02 临时脚手架清账

- 审核 `SpawnControlAllies` 写死坐标/顺序、临时信号范围与冷却、默认回退锚点。
- 每项选择：迁入正式配置/场景、由 M5 网络接管、保留为测试夹具。
- 测试夹具必须只能由测试入口创建，正常新局不能依赖生成顺序维持存档身份。
- 若正式稳定身份仍依赖 LogicId/生成顺序，建立迁移与旧存档映射后才完成。

### M1-R03 UI/输入恢复矩阵

- 战略、过渡、直控、普通暂停、战略暂停、模态面板、键鼠/手柄适配分别验证输入所有权。
- 目标晚生成、相机丢目标、控制为空、死亡回弹时 UI 和相机有明确降级。
- 连续切换 100 次，检查无双输入、血条串体、旧特效/瞄准线残留、空引用和稳态分配。

## 4. M2 返工包：同一身体的完整战斗真相

### M2-R01 通用发射上下文

- **需求：** CP-REQ-001～004、CP-REQ-090～092。
- 建立与控制者无关的 `EmissionContext` 唯一入口；移除发射后读取全局玩家位置/当前器官的路径。
- 器官挂点、身体朝向、目标/接点、阵营、资源事务、种子和装配签名一次性冻结。
- 玩家、友军 AI、敌方和测试入口都走它；旧入口只能做适配，不能继续拥有另一套默认。
- 自动测试切换控制后让旧弹体继续飞，确认来源、方向和命中不串体。

### M2-R02 发射角、投送与基元阶段

- **需求：** CP-REQ-010～053。
- 实现并只保留一份角度函数：单发中轴、多发对称扇、明确环射、独立精度偏差。
- 分别完成 Projectile/Melee/Field/Aura/Summon 的阶段和锚点；每个基元加入目录声明。
- 子事件带代际/过程预算与来源链；组合 Split+Chain+Bounce+Return+Explode+Linger 不得递归失控。
- 逐字段验收发射点、方向、飞行、接触、终点和持续位置；发射点与终点各放对照单位排除误结算。

### M2-R03 AI/玩家同装配同结果

- **需求：** CP-REQ-004、011、060～061、080。
- 同一身体由玩家和 AI 使用同一 AbilityRecipe、真实数值、冷却、代谢、过载债、弹体与状态。
- 允许差异：目标选择、瞄准误差、释放时机和玩家风险覆盖；差异必须来自明确策略字段。
- 删除/封存“友军常数伤害”和只按器官形状的半统一路径。
- 测试逐字段比较，不只比双方都能造成伤害。

### M2-R04 召唤、击退/牵引与交互转正

- **需求：** CP-REQ-034、040、070、081；FS-REQ-030。
- `Summon` 生成真实实体，具所有者、装配、容量、寿命/维护与死亡回收；区域占位不得通过。
- `Knockback/Pull` 改真实目标位置/速度并处理墙、体型和阵营；仅贴状态或摘要不得通过。
- `Interact` 接正式拾取/接口/手术目标，至少返回成功和完整失败原因；玩家本体与友军装配都有来源。
- 召唤—回收、推墙穿越、无目标交互、断网与读档均有自动负向用例。

### M2-R05 手术接点产品化

- **需求：** CP-REQ-003、071、080～082。
- 将两个 `Primary/Secondary` 占位槽迁为按原型/骨骼/器官配置的 N 接点；接点随身体朝向/动画更新。
- 正式敌人生成池使用接点配置；测试专用生成入口不再是唯一来源。
- 接点有轮廓、独立状态、命中/受损/切离反馈和可访问性辅助。
- 验证单体+Chain、Pierce、多段、范围回退、已毁接点、身体死亡与掉落。

### M2-R06 真实输入与玩家旅程

- 不用人工点击：建立可注入输入源，驱动战略选择、传入、鼠标/摇杆瞄准、主/功能/交互、退出。
- 完成 GDD 首局前两步与手术窗口；UI 可解释每次拒绝。
- 自动旅程同时验证玩家本体委托和友军释放路径，不再把其中一条留成“代码论证”。

## 5. M3 返工包：蓝图、模板与真实传播

### M3-R01 槽位与装配表达完整性

- **需求：** GDD §6.5、CP-REQ-002、060。
- 模板和个体能表达底盘、主器官、功能器官、结构器官、有序基因、教义和临时移植。
- 移动器官改变移动参数；不能因“移动恒可用”而无处装配。
- 多功能器官顺序稳定；装配签名包含所有影响行为的字段，不包含伤势/储备等个体运行态。
- UI 与编译器使用同一槽位规则与冲突原因。

### M3-R02 编译签名与任意实体投射

- 同模板静态输出只编译一次；玩家、友军、敌方和 Alpha 均可用签名 + EmissionContext 释放。
- 基因顺序变化生成新签名；临时移植只影响单体签名；身体运行态不污染共享缓存。
- 缓存失效、内容热更、读档和坏签名安全降级并可见。

### M3-R03 萌生与回巢真实状态

- 萌生、改造使用真实资源事务、地点、时间和容量；取消、腔体被毁、断网、版本再次更新不复制资源。
- 回巢单位真实脱离战斗驱动、保留允许状态并在完成后重入；“暂时移出战斗”不能只存在于字段。
- 网络、交战、携带物三项判据接真实系统；若网络尚属 M5，使用显式接口与测试替身，并由 M5 story 接管，不能恒 true/false。

### M3-R04 野生器官完整生命周期

- 正式死亡/切离事件生成物理战利品；拥有位置、来源、品质/损伤、污染、所有权和稳定 ID。
- 拾取、容量、搬运、死亡掉落、拆解、解析、保留、临时移植、拆除和存读档全链闭合。
- 同一实物不能同时被装备、搬运、拆解和解析；资源/蓝图/模板不因取消或读档复制。

### M3-R05 模板 UI 产品化

- 从调试单谱系面板迁到正常玩家入口；支持多谱系、多个表型、版本对比、成本、冲突、影响个体和回巢筛选。
- 提交前明确“只影响新生/回巢”，提交后可从个体面板追溯模板版本。
- 自动旅程完成野生器官 → 临时移植或解析 → 改模板 → 新生 V2 → 旧体回巢 → 混编不串改。

## 6. M4 返工与后续包

### M4-R01 编队模型补全

- **需求：** FC-REQ-001～004。
- 现有成员/命令/教义之外，补齐职责、阵型、路径版本、临时脱队、载荷/护送所有权、信号/续航、失败状态。
- 死亡移除接正式死亡事件，不靠查询时偶然清理；俘获、换阵营、卸载和读档同样处理。

### M4-R02 十类命令生产行为

- **需求：** FC-REQ-010～022。
- 逐项实现移动、攻击单位、攻击器官、守护、搬运、占据、伏击、撤退、暴露许可、自动提取、觅食/供养。
- 当前前置未具备的资源命令先实现接口和明确 `DependencyUnavailable`，并由 M5 接真实事务；不能用 Move 假装 Carry。
- 每项都有 Active 行为、完成、失败、中断、排队、UI 与自动 E2E。

### M4-R03 六教义执行

- **需求：** FC-REQ-030～031。
- 把只读 Profile 接入目标选择、距离、追击、队形、职责、能力许可、资源与撤退。
- 同场景切六次，行为差异由世界结果证明，不以属性值变化验收。
- 切换不清命令、不重置冷却、不传送、不丢载荷。

### M4-R04 导航与大军路径

- **需求：** FC-REQ-040～045、070。
- 保留现有圆障碍启发式作为白模适配器；在其上建立 `INavigationQuery`/路径走廊契约。
- 六队形、窄道压缩/恢复、体型宽度、职责槽、动态封路、合法不动、分级卡死恢复全部实现。
- 逐单位跟随从热更层逐帧命令迁到 AOT/Jobs 批处理；热更层只处理编队级事件。
- 按 1/2/8/64 与 4×64+512 压力矩阵验收；真实窄通道场景必须存在，不能只跑几何纯函数。

### M4-05 直控脱队与回归（补全任务卡）

- **需求：** FC-REQ-050～051、061，CP-REQ-090。
- **实施顺序：** 冻结接管快照 → 从槽位跟随排除 → 其他成员稳定补位 → 玩家移动/战斗/搬运 → 交还时校验原命令/路径/目标 → 规划汇合 → 恢复职责或执行失散策略。
- **边界：** 接管时成员正装载、占据、手术、最后护送者、路径重规划、断网、身体死亡、编队解散、目标易主。
- **验收：** 六命令态往返；成员、命令、队列、载荷、资源、冷却、生态暴露和路径均不丢不复制。

### M4-06 多线固定遭遇（补全任务卡）

- **规格：** FC-TEST-007；同时使用 FS-REQ-001/002 的职责接口，资源可用测试适配器但不能伪造搬运状态。
- **场景：** A 线护送真实载荷穿过可伏击通道；B 线压制敌巢/信号；至少一个值得接管的接点窗口；两线共享一项有限资源或信号预算。
- **方案一：** 护送队稳推，猎手队先断信号再打巢。
- **方案二：** 诱出游猎者后交换两队职责，利用环境快速突巢。
- **万能队：** 可以串行完成，但会多走路、暴露更多能力或损失更多资源；不靠隐藏加血惩罚。
- **失败恢复：** 载荷掉落可夺回，巢目标死亡/易主可重选，成员卡死有替代路线，无倒计时软锁。
- **验收：** 旅程机器人分别完成两方案和万能队对照，记录资源、损失、用时、暴露和命令失败原因。

## 7. M4-GATE：自动化里程碑总验收

### M4-GATE-01 编译与旧回归

- `tools/unity-validate.sh` 全绿；
- M1–M4 旧断言集合逐项保留，差异有解释；
- 不以总测试数相同代替断言内容比较。

### M4-GATE-02 六条固定旅程

1. 控制身份：切换、死亡回弹、读档恢复；
2. 战斗投射：精确角度、发射点、命中点、基元阶段；
3. AI/玩家一致：同身体交还后继续用同装配与资源账；
4. 蓝图传播：野生器官到模板、新生和回巢；
5. 编队路径：宽场—窄门—动态封路—重组；
6. 多线遭遇：护送/巢/接管/交还完整闭环。

每条均从生产入口或可注入输入源开始，输出状态指纹、关键 UI 事件和失败原因。

### M4-GATE-03 负向矩阵

至少覆盖：资源不足、器官失能、非法目标、目标死亡、发射者死亡、断网、暂停、路径不可达、载体死亡、编队解散、存读档。每项可理解、可恢复、无复制、无静默失败。

### M4-GATE-04 性能与长稳

按 FC-REQ-070 跑 10 分钟固定命令流；零永久堵塞、穿墙、稳态 GC、悬挂事务和控制/装配串体。记录 P50/P95/P99 帧时和路径规划时间。

### M4-GATE-05 用户只看什么

AI 自动输出一页总结与最短录像/截图索引。用户只需判断：

- 战略与直控是否像同一个游戏；
- 大军移动与信息是否可读；
- 六教义差异是否符合期望；
- 多线遭遇是否有乐趣。

任何基础功能缺失、按钮无反应、弹道错位、状态不恢复或资源复制，都应在到达用户前由自动门禁拦下。
