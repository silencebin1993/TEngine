# FG02 固件体系、反应与机身形变

> 需求前缀：`FGR-FW`；测试前缀：`FGT-FW`。里程碑：FG-M1（核心固件、形变首批）、FG-M2（全量）。
> 上游：[ProjectA_FullGame_Design.md](../ProjectA_FullGame_Design.md) 第 5 章（分层、四类包装、44 条名表、组件名表、标签）。契约：[FG00](FG00_Completeness_Addendum.md)。

---

## 1. 玩家目的

- 玩家能看懂每条固件**在每种载体上会变成什么**，并据此自己设计组合。
- 组合真的产生反应时，玩家能**看见、叫得出名字、知道是自己的哪台机器、哪条固件干的**。
- 机器的外形会跟着固件变，玩家扫一眼就知道这台机器现在"是什么"。

## 3. 需求

### 3.1 固件数据模型

**FGR-FW-001 固件字段**
每条固件在表里至少有以下字段：
- 标识、旧基因 ID（用于追溯）
- 名称和描述的文本键
- 类别：引信与弹芯 / 限制器与击发逻辑 / 流体改道 / 电磁场控
- 种类：常规 / 核心
- 协议：己方 / 中立 / 敌方加密
- 已破解标记、来源阵营、稀有度
- 负载、能耗、热量
- 每种载体的读法说明（文本键）
- 产生的状态标签
- 形变状态
- 图标
- 获取途径

**FGR-FW-002 44 条全量迁移**
- 名表以 `ProjectA_FullGame_Design.md` 5.4 为准，共 44 条：引信与弹芯 17、限制器与击发逻辑 10（其中核心 6）、流体改道 9、电磁场控 8。
- 所有名称走文本键。玩家可见文本中禁止出现生物词（细胞、器官、基因、代谢、吞噬、溶血等）；旧 ID 只存在于数据和调试层。

**FGR-FW-003 核心固件**
- 核心固件共 6 条：过载、电容蓄力、标记跳转、集群协议、反应增幅、处决。
- 判定标准：越过安全限制，或者需要核心的实时算力。
- 新增固件时，按这个标准判定种类，并写进表里。

### 3.2 读法

**FGR-FW-010 读法矩阵零死对**
- 每条固件在 5 种载体（射弹、格斗、无人机、力场、布区）上都必须有读法，沿用现有的零死对断言（`ChassisPrimitiveMatrixSmokeReport`：完全没有反应的"载体 × 固件"组合数为 0）。
- 读法按载体分类和字段来实现，禁止按固件 ID 两两写特例。

**FGR-FW-011 读法说明对玩家可见**
- 固件详情页逐条列出"装在射弹上会怎样""装在格斗上会怎样"……每种载体一句话。
- 在电路编辑器里悬停固件时，只显示与当前主组件载体对应的那一条。

**FGR-FW-012 固定底盘（炮塔）兼容**
- 作战组件与固定底盘的兼容表：
  - **不兼容**：冲刺器（依赖机体位移）。
  - **兼容，但读法调整**：推铲在炮塔上读作"击退铲"，把近身敌人推开。
  - **其余作战组件**：直接兼容。
- 不兼容的组件放不上炮塔蓝图，并给出原因。

### 3.3 机身形变

**FGR-FW-020 按类别切换状态**
- 每个作战组件有 3 套机身状态，分别对应限制器、流体、电磁三类（引信类只改弹体特效，不改机身）：
  - 限制器：散热鳍展开、枪管发红、天线升起
  - 流体：机身开出喷口、管线外露
  - 电磁：线圈发光、周围空气扭曲
- 同时存在多类固件时，各类状态**叠加显示**（每类有独立的挂点组），不互相覆盖。

**FGR-FW-021 形变由编译结果驱动**
- 表现层只读取编译结果里的类别集合，不另算（IC-REQ-010）。
- 形变有过渡动画（**初值：0.3 秒**），接入和离开都播放，完全可逆。

**FGR-FW-022 上帝视角下可辨认**
- 在默认战略缩放下，形变必须能看出来：靠轮廓变化和自发光，而不是只靠小部件。
- 性能：形变部件要能参与实例化渲染。注意已知坑：外形槽只取第一个 MeshFilter，多网格模型会静默丢件；形变部件必须拆成独立的实例化部件，或者烘焙成独立状态。

### 3.4 状态标签

**FGR-FW-030 机械化标签名**

| 旧标签 | 新名 | 旧标签 | 新名 |
|---|---|---|---|
| Fire | 燃烧 | Oil | 油污 |
| Wet | 浸湿 | Frozen | 冻结 |
| Shock | 电击 | Slow | 减速 |
| Acid | 腐蚀 | Charged | 充能 |
| Magnet | 磁化 | Blood | 回收 |
| Dark | 处决 | Mirror / Light | 偏折 |

未列出的标签（Earth、Poison、SugarFilm、Capillary、Haste、Drifting 等），在 FG-M2 的迁移 Story 里补齐名称，并写入本表。

**FGR-FW-031 标签可见**

### 3.5 具名反应

**FGR-FW-040 先核实，再命名**
- 旧反应引擎是预编译 DLL，看不到触发配对表。**在给任何旧反应起机械名、开放给玩家之前，必须先用行为探针实测它的触发配对和效果**，结果写进反应表。这条遵守已有教训：字段有差异不等于游戏里有变化，验收要真跑模拟。

**FGR-FW-041 旧反应的机械化命名（待探针核实后生效）**

| 旧名 | 机械名（提案） | 旧名 | 机械名（提案） |
|---|---|---|---|
| 蒸汽 Steam | 蒸汽 | 苛性灼烧 CausticBurn | 腐蚀灼烧 |
| 爆燃 Deflagrate | 爆燃 | 溶血 Hemolysis | 回路溶断 |
| 导电 Conduct | 短路 | 糖浆 Syrup | 胶结 |
| 碎裂 Shatter | 脆裂 | 溶解 Dissolve | 溶蚀 |
| 黏滞 Sticky | 粘滞 | 湮灭 Annihilate | 湮灭 |
| 电解 Electrolysis | 电解 | 玻化 Vitrify | 玻化 |
| 绝缘 Insulate | 绝缘 | 泥泞 Mudify | 淤塞 |
| 热震 ThermalShock | 热震 | 败血 Sepsis | 连锁锈蚀 |

环境反应 2 条：燃烧 + 浸湿 → 蒸汽残留；燃烧 + 油污 → 燃烧区。机械反应 2 条：标记跳转、熔穿过载（已有）。

**FGR-FW-042 按阵营开放**
- 具名反应不在开局一次性全部开放，而是随阵营推进逐批解锁（未解锁的照样按规则触发，只是不显示名字和图鉴）。
- 暂定分配，按探针结果调整：
  - 第一幕（静默、铸造）：标记跳转、熔穿过载、短路、热震
  - 化工：爆燃、腐蚀灼烧、胶结、溶蚀
  - 超频：电解、玻化、回路溶断、连锁锈蚀
  - 其余：蒸汽、脆裂、粘滞、绝缘、湮灭、淤塞，作为跨阵营组合的奖励，第二幕后期开放
- 每个阵营至少 2 条新反应，其中大部分需要跨阵营的固件组合才能触发。

**FGR-FW-043 反应反馈**
- 触发时弹出反应名。
- 每个存档里某条反应**第一次**触发时：短暂慢放（**初值：0.3 秒**），镜头轻推，解锁图鉴条目。慢放和镜头推动都可以在设置里关闭。
- 大量触发时聚合显示（"燃爆 ×12"），同一屏幕每秒弹字有上限（**初值：6 条**）。
- 反应日志：保留最近 50 条，每条写明触发者（机器或炮塔）、参与的固件、目标。
- 伤害归因：按反应统计每次远征和每次突袭的伤害占比，进入统计面板和离家报告。

### 3.6 混合固件（熔合产物）

**FGR-FW-050 混合固件数据**
- 由两条父固件熔合而来（配方见 FG05），同时具有两者的读法。
- 类别显示两个图标；任一父固件是核心固件，混合固件就是核心固件。
- 负载 = 两者中较大值 + 1（**初值**）。
- 两条读法修改同一个参数时（例如都影响扩散角），按"加法叠加，受上限约束"合并；合并规则写在表里，不按 ID 写特例。
- 名称来自配方表的文本键，不自动拼名字。
- **只能熔合一层**：混合固件不能再次熔合。

### 3.7 固件库界面

**FGR-FW-060 固件芯片是物品**
- 固件芯片是物品，由固件刻录台生产（FG04），存放在仓库里。
- "固件库"是所有仓库里固件芯片的统一视图。装配电路时，从任意仓库调取，由机器搬运到装配站（沿用工作单）。
- Demo 的"有限仓 8 格"约束在正式版取消，改为受仓库容量约束。

**FGR-FW-061 固件库功能**
- 筛选：类别、种类、协议、是否已破解、与某载体是否兼容、稀有度。
- 排序、搜索。
- 两条固件并排比较。
- 详情页：各载体读法、产生的标签、参与的反应、获取途径、当前数量和所在仓库。
- 锁定：锁定的固件不会被批量分解。
- 批量分解：需要确认，锁定的跳过。

## 4. 正常游戏补全清单

- 图鉴里每条固件都有条目，未获得的显示为剪影，并写明"在哪里获得"。
- 悬停固件时按一个键就能打开它的图鉴条目。
- 电路编辑器里可以直接筛选"与当前主组件兼容的固件"。
- 固件图标用形状区分类别，颜色只作辅助（色盲安全）。
- 从固件详情页可以一键"送到靶场测试"（FG05）。
- 反应日志和伤害归因支持按远征、按突袭筛选。
- 反应弹字、慢放、镜头推动都有独立的设置开关。

## 5. 负向与边界矩阵

| 场景 | 期望行为 |
|---|---|
| 探针发现某条旧反应在机械内容下永远不会触发 | 不开放命名；登记 FG-GAP，决定是改读法还是退役 |
| 同一帧触发 200 次反应 | 弹字聚合、音效限量，帧率不掉出预算 |
| 固件在仓库里，但搬运路线被堵 | 装配工作单进入"等待物料"，并说明被什么堵住 |
| 混合固件的父固件在表里被退役 | 已有的混合固件继续可用；配方不再出现 |
| 把核心固件放进炮塔蓝图 | 拒绝，原因同 FGR-SIG-012 |
| 形变过程中机器阵亡 | 形变中止，残骸保持阵亡前状态 |

## 6. 存档

- 固件实例（包括已破解状态、来源、锁定标记）。
- 每个存档里各反应的"首次触发"记录，以及图鉴解锁状态。
- 反应日志不存档（只保留本次会话），伤害归因统计要存档。

---

## 7. 性能

- 反应弹字和音效有上限，并聚合显示。
- 形变部件参与实例化，不能每台机器生成独立网格。
- 伤害归因统计在内核侧累加，热更层只读汇总。

## 9. 人工体验审核

1. 在默认缩放下，能不能一眼认出一台机器"现在是什么"？
2. 第一次看到某个反应名弹出时，玩家知不知道是自己哪台机器干的？
3. 固件详情里的读法说明，玩家读得懂吗？
