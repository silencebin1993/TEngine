## 1. 玩家目的

- 玩家能看懂每条固件**在每种载体上会变成什么**，并据此自己设计组合。
- 每条固件只管自己的功能，只声明读、写哪些端口；组合效果由端口交汇自然产生，玩家看到的是“意外，但看得懂为什么”（FG19 FGR-EMG-001）。
- 组合真的产生反应时，玩家能**看见、叫得出名字、知道是自己的哪台机器、哪条固件干的**。
- 机器的外形会跟着固件变，玩家扫一眼就知道这台机器现在"是什么"。

## 3. 需求

### 3.1 固件数据模型

**FGR-FW-001 固件字段**
每条固件在表里至少有以下字段：
- 标识、旧基因 ID（用于追溯）
- 名称和描述的文本键
- 类别：引信与弹芯 / 限制器与击发逻辑 / 流体改道 / 电磁场控
- 种类：常规 / 核心
- 协议：己方 / 中立 / 敌方加密
- 已破解标记、来源阵营、稀有度
- 负载、能耗、热量
  - （2026-09-30 用户把“战斗中扣不扣电”交给总控决定，要求不让玩家玩得难受、尽量割草爽，同时不破坏平衡。总控决定：固件在战斗中**不扣机器电池**，逐发代价只有热量一条；“能耗”字段暂留在数据层但不产生战斗效果，界面不再显示“每发耗电”。去掉耗电后几乎没有代价的固件，把原耗电折算进热量补上；过热门槛以“正常清怪很少过热、堆满强力固件才会过热”为目标，最终数值在 FG15-BAL-01 调。可逆：以后要恢复耗电，只需重新启用该字段。FG4-ECO-04 已落地：逐条核对 44 条，原本热量为 0、只靠耗电当代价的 28 条（引信与弹芯 17、电磁场控 8、标记跳转 / 蜂群 / 回收）按 1 电 = 1 热折算进每发积热，其余不变；双态预览、蓝图版本差异、电路面板摘要、固件库都不再显示耗电，ADR-ECO-004。）
- 每种载体的读法说明（文本键）
- 产生的状态标签
- 读 / 写端口声明（`fg.TbChannelDecl`，FG19 FGR-EMG-011）：至少 1 条可感知的读端、1 条非纯数值的写端，只改数值的不准入（FGR-EMG-014）
- 形变状态
- 图标
- 获取途径

**FGR-FW-002 44 条全量迁移**
- 名表以 `ProjectA_FullGame_Design.md` 5.4 为准，共 44 条：引信与弹芯 17、限制器与击发逻辑 10（其中核心 6）、流体改道 9、电磁场控 8。
- 所有名称走文本键。玩家可见文本中禁止出现生物词（细胞、器官、基因、代谢、吞噬、溶血等）；旧 ID 只存在于数据和调试层。
- 44 条固件与 30 条混合固件全部改为端口声明写法，逐条映射见 FG19A（FG19 FGR-EMG-019 双轨迁移）；名表本身不变。

**FGR-FW-003 核心固件**
- 核心固件共 6 条：过载、电容蓄力、标记跳转、集群协议、反应增幅、处决。
- 判定标准：越过安全限制，或者需要核心的实时算力。
- 新增固件时，按这个标准判定种类，并写进表里。
- 核心 / 常规与端口声明正交：核心固件同样声明读写端口、同样过准入（FG19 FGR-EMG-014）。

### 3.2 读法

**FGR-FW-010 读法矩阵零死对**
- 每条固件在 5 种载体（射弹、格斗、无人机、力场、布区）上都必须有读法，沿用现有的零死对断言（`ChassisPrimitiveMatrixSmokeReport`：完全没有反应的"载体 × 固件"组合数为 0）。
- 规则只写在端口 × 端口之间（物质 × 物质、事件 × 物质、属性 × 场……），不写在固件之间；编译器、`CarrierReadings`、战斗内核 `Main/Sim/Combat/` 与所有规则表里不得出现 `fw_` / `comp_` / `func_` / `struct_` 内容 ID 判断（FG19 FGR-EMG-013，自检 `FgEmergenceRuleAuditSelfCheck`；过渡豁免只有两条装配反应，FGR-EMG-021）。
- 零死对扩为“载体 × 端口”：每条声明在 5 种载体、程序首位 / 末位都有可观察的行为差异，每个读端口都有正常游戏可获得的写者（FG19 FGR-EMG-015）；组合层面的零反应由组合模糊测试器守住（FGR-EMG-221）。

**FGR-FW-011 读法说明对玩家可见**
- 固件详情页逐条列出"装在射弹上会怎样""装在格斗上会怎样"……每种载体一句话。
- 在电路编辑器里悬停固件时，只显示与当前主组件载体对应的那一条。
- 详情页同时列出这条固件读 / 写哪些端口，以及“与你现有的固件 / 部件可产生 N 种新交互”（FG19 FGR-EMG-191；只给信息，不排序、不推荐）。

**FGR-FW-012 固定底盘（炮塔）兼容**
- 作战组件与固定底盘的兼容表：
  - **不兼容**：冲刺器（依赖机体位移）。
  - **兼容，但读法调整**：推铲在炮塔上读作"击退铲"，把近身敌人推开。
  - **其余作战组件**：直接兼容。
- 不兼容的组件放不上炮塔蓝图，并给出原因。
- 移动底盘的读法差异见 FG19 FGR-EMG-140 底盘特性表：每种底盘 1 条特性，按底盘状态端口 / 载体类别生效，不按固件或底盘 ID 写进别处；代码现有搬运轮式 / 战斗履带 / 维修悬浮 / 固定 4 种，越野多足 / 飞行 / 船体 3 条为预留接口。固定底盘仍按本条兼容表。

### 3.3 机身形变

**FGR-FW-020 按类别切换状态**
- 每个作战组件有 3 套机身状态，分别对应限制器、流体、电磁三类（引信类只改弹体特效，不改机身）：
  - 限制器：散热鳍展开、枪管发红、天线升起
  - 流体：机身开出喷口、管线外露
  - 电磁：线圈发光、周围空气扭曲
- 同时存在多类固件时，各类状态**叠加显示**（每类有独立的挂点组），不互相覆盖。
- 叠加时真有重叠的部分按优先级显示：形变态 > 线圈态 > 喷口态（FG2-VFX-02，ADR-VFX-002，待用户复核）；名表 16 个作战组件（含炮塔能装的）都有三套状态。爆炸反应装甲（原名尖刺外装，内部 ID `func_spikes` 不变）占功能组件槽（ADR-VFX-002，待用户复核）：侧裙上一排方砖装甲块，反伤范围内的攻击者即时命中时起爆一块装甲向外反伤并放破片，炸掉的块定时补上，块数为 0 时不反伤；`thorns` 字段、反伤公式与数值不变，块数、破片与补块规则见 FG19 FGR-EMG-233（阶段 1 EMG1-FW-01 生效，生效前按旧轨不限次数反伤）（FG19 FGR-EMG-230 第 1 行、233，2026-10-26 用户批准第 3 层；三态外观与供块匣见 `production/design/build-variety-theme-fit/ART-CHANGES.md`）。
- 引信类的弹体特效（FG2-E2E-01，FG-GAP-043，ADR-QA-018）：生效固件里有引信类的武器，每次开火留下一条弹迹（炮口 → 命中点；弹体武器只有炮口闪光）与炮口装定闪光，按游戏时间停留 0.15 秒（fg.TbHomeTuning combat.fuse_trace_seconds），同时最多 128 条；表现数据不进存档。美术是占位（统一样式，DEBT-FG2E2E01-04）。

**FGR-FW-021 形变由编译结果驱动**
- 表现层只读取编译结果里的类别集合，不另算（IC-REQ-010）。
- 形变有过渡动画（**初值：0.3 秒**），接入和离开都播放，完全可逆。

**FGR-FW-022 上帝视角下可辨认**
- 在默认战略缩放下，形变必须能看出来：靠轮廓变化和自发光，而不是只靠小部件。
- 性能：形变部件要能参与实例化渲染。注意已知坑：外形槽只取第一个 MeshFilter，多网格模型会静默丢件；形变部件必须拆成独立的实例化部件，或者烘焙成独立状态。

### 3.5 具名反应

**FGR-FW-040 先核实，再命名（已由 FG19 取代）**
- 已由 FG19 FGR-EMG-085（反应去倍率化）与 FGR-EMG-220～223（组合模糊测试器）取代：每条具名交互的主结果必须是生成场地物（S）/ 改地形或通行（T）/ 改目标行为（B）/ 改弹道拓扑（P）之一，伤害只能作附带（固定伤害或倍率 ≤ 1.25，`emg.react.side_mult_cap`）；守门由行为探针改为规则表形状自检 `FgChannelRuleShapeSelfCheck` 与模糊测试器。`LegacyReactionProbe` 退役为“旧引擎对照”，FG-EMG 阶段 2 之前继续作回归。
- 以下为历史说明（FG2-FW-03 探针结论与正式版战斗内核的倍率结算公式），保留供需求映射与旧旅程回归对照，不再作施工依据：
- 旧反应引擎是预编译 DLL，看不到触发配对表。**在给任何旧反应起机械名、开放给玩家之前，必须先用行为探针实测它的触发配对和效果**，结果写进反应表。这条遵守已有教训：字段有差异不等于游戏里有变化，验收要真跑模拟。
- FG2-FW-03 已完成探针（LegacyReactionProbe，自检 FgReactionProbeSelfCheck）：旧引擎运行时注册表共 21 条规则（内置 19 + 环境 2），每条都实测“两个配料触发、只有一个不触发”；再用真实固件的旧基因在真起的 SimWorld 里比对掉血。结果写进 Luban 表 fg.TbReaction（数据源 tools/cell_tables/fgdata_reaction.py），自检逐条比对“表 = 探针”。探针结论：
  - 旧引擎里一个配料在这一发、一个在目标格上同样触发；旧引擎每一发都自带“动能”，所以脆裂见冰就碎。
  - 同名的两套写法（Burning / Fire 等）在机械内容下只有新写法会触发；蒸汽在机械内容下倍率是 ×1（Burning 写法那条 ×1.2 永远碰不到）。
  - 正式版战斗内核里，反应读的是单位身上的状态标签：单位已有的标签 ∪ 这一次挂上的标签含一对配料、且这一次至少带来其中一个就触发；这一击额外伤害 = 这一击 × (倍率 − 1)（克制类 < 1 的少掉那部分算回给目标）；消耗配料、附加标签、留下残留区域；同一次满足多条时只结算表里排在前面的一条（旧引擎注册顺序），剩下的标签留给下一击。
  - “这一击”：直接命中 / 回波 / 无人机取实际伤害；区域节拍取节拍伤害，纯状态区域取它挂的持续伤害一个节拍的量；都没有（减速网、外部挂状态）= 0，此时只靠倍率的反应不结算、不消耗、不报名字，有附加标签 / 残留区域的反应照常结算。残留区域打目标这一边（不看出手者是否还活着）。

### 3.6 混合固件（熔合产物）

**FGR-FW-050 混合固件数据**
- 由两条父固件熔合而来（配方见 FG05），同时具有两者的读法。
- 类别显示两个图标；任一父固件是核心固件，混合固件就是核心固件。
- 负载 = 两者中较大值 + 1（**初值**）。
- 两条读法修改同一个参数时（例如都影响扩散角），按"加法叠加，受上限约束"合并；合并规则写在表里，不按 ID 写特例。
- 名称来自配方表的文本键，不自动拼名字。
- **只能熔合一层**：混合固件不能再次熔合。
- FG5-RND-04 实现（ADR-RND-004）：30 条混合固件并入 fg.TbFirmwareKind（mixA / mixB / category2 列），装配结算时按两条父固件识别装配反应、编译旧引擎等价模块、计热量；读法字段用表里按上限合并好的值。名表“44 条 / 6 条核心”只数正式固件。
- 混合固件在通道制下的表示（一槽两指令）待用户确认（FG19 FGR-EMG-044，第 14 节第 2 条）；确认前本条维持原状。

### 3.7 固件库界面

**FGR-FW-060 固件芯片是物品**
- 固件芯片是物品，由固件刻录台生产（FG04），存放在仓库里。
- "固件库"是所有仓库里固件芯片的统一视图。装配电路时，从任意仓库调取，由机器搬运到装配站（沿用工作单）。
- Demo 的"有限仓 8 格"约束在正式版取消，改为受仓库容量约束。
- 掉落体系（FG8-LOOT-01）上线前的临时来源（FG2-E2E-01，FG-GAP-050，ADR-QA-018）：解析台“数据复原”——花技术数据（按稀有度，初值 4 / 8 / 12）复原获取途径为遗迹终端 / 杂兵残骸 / 精英 / 首领的固件的刻录数据（敌方加密同时视为已破解），之后在信号核刻印芯片或在蓝图里选用；要解析台有电，确认后不可撤销。去留由 FG8-LOOT-01 决定（DEBT-FG2E2E01-02）。

**FGR-FW-061 固件库功能**
- 筛选：类别、种类、协议、是否已破解、与某载体是否兼容、读 / 写端口、稀有度。
- 排序、搜索。
- 两条固件并排比较。
- 详情页：各载体读法、产生的标签、能参与的交互（两侧端口）、获取途径、当前数量和所在仓库。
- 锁定：锁定的固件不会被批量分解。
- 批量分解：需要确认，锁定的跳过。
