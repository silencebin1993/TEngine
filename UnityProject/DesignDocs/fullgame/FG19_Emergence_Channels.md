### 0.2 术语（本文与 FG19A / FG19B 统一使用）

| 术语 | 含义 |
|---|---|
| 通道族 | 第 2.3 节的 13 个涌现通道（语法、元程序、事件……节拍） |
| 端口 | 通道族里一个可被读或写的具体量，ID 形如 `mat.oil`、`evt.hit`（第 2.4～2.8 节命名总表） |
| 声明 | 一条“某内容读 / 写某端口”的表行（`fg.TbChannelDecl`）。固件、作战组件、结构模块、底盘特性、敌方单位都用同一种声明 |
| 指令 | 程序里的一条固件（混合固件展开为 2 条，FGR-EMG-044） |
| 程序 | 一把武器编译出的有序指令序列（FGR-EMG-030） |
| 载荷 / 节点 | 程序树里的一个节点 = 一种会被发射、会命中、会结束的东西（弹体、挥击、无人机子弹、力场脉冲、落区、子弹药） |
| 代 | 节点深度：根载荷 0 代，触发器放出的子载荷 1 代，再下一级 2 代；最多 2 代 |
| 斑块 | 物质层的承载单位：一块有物质、份量、温度、电荷、相态的圆形区域（FGR-EMG-081） |
| 交互 | 任意一条通道规则（端口 × 端口）真正结算一次 |
| 具名反应 | 有玩家可见名称、进图鉴的交互规则；沿用现有 `reaction_*` ID |
| 战斗事件总线 | 本文通道 3，内核里的事件队列；**不是** FG10 的“事件导演”（FGR-EMG-068） |

## 1. 目的、口径与取代清单

**FGR-EMG-001 总目标与口径**
- 总目标：固件组合的数量与意外感超过《魔法工艺》《Noita》《泰拉瑞亚》，让玩家一直想拿新固件、新部件来试。
- 衡量口径不是“有多少种”，而是“意外，但看得懂为什么”：每个效果都能追溯到哪台机器、哪条固件、哪条通道规则（第 8 节）。
- 核心原则：每条固件只管自己的功能，只声明读、写哪些端口，不认识其他固件。组合效果由端口交汇自然产生。联动规则只允许写在“端口 × 端口”之间（物质 × 物质、事件 × 物质、属性 × 场……），禁止按固件 ID 写两两特例（沿用并强化 `FG02:60-62`）。
- 题材：风格化硬表面 · 工业废土。玩家是信号 / 程序，只带固件；“把程序刷写进弹药与无人机”是核心包装。玩家可见文本禁用细胞、器官、基因、孢子、菌丝等生物词（FGR-EMG-232）。
- 数值不叠加：固件价值来自机制而非加数（FGR-EMG-017）；重复获得的实体部件 = 多一台车能装（FGR-EMG-193），不做 Mk 等级、不做同名堆叠。
- 代价代替禁止：允许破格组合，用热量、弹载容量（逐代减半 4→2→1）、刷写带宽作代价（FGR-EMG-016）；超模组合记入图鉴当奖励（FGR-EMG-194）。

## 2. 通道模型总则

### 2.1 数据形状

**FGR-EMG-010 端口注册表 `fg.TbChannelPort`**
- 所有可读、可写的量都必须先在本表注册，ID 只能用第 2.3～2.8 节命名总表里的写法。新增端口要先改本文命名总表，FG19A / FG19B 不得自行使用未注册端口（需要时在附录末尾列“新端口申请”，合并日并入本文）。不设族级端口“任一地面液体”：对任一液体斑块做 modify 的声明（蔓延、桥接、底盘拖带 / 拖挂）按 8 个液体端口各写 1 行（FG19A 申请 B1 取其备选，即 FG19A 现行写法）。
- 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 端口 ID，`<族前缀>.<名>`，小写 ASCII，如 `mat.oil` |
| `family` | enum `EmgFamily` | 13 个通道族之一（2.3 节，`prop.*` 与 `ent.*` 同属“实体”族） |
| `code` | ushort | 内核用的稳定整数码，**永不复用**。分段：语法 100～199，元程序 200～299，事件 300～399（= 300 + 事件码），物质 400～499（= 400 + 物质码），能量 500～599，实体 / 属性 600～699，场 700～799，协同 800～899，相态 900～999，底盘 1000～1099，地形 1100～1199，劫持 1200～1299，节拍 1300～1399 |
| `dirs` | flags | 可读 / 可写 / 两者 |
| `numericOnly` | bool | 只改本载荷的数字（伤害、冷却、半径、扇角、穿甲）。准入时不算“写端”（FGR-EMG-014） |
| `perceive` | bool | 是否算“感知类读端”。语法族、元程序族恒为 false |
| `carrierImpl` | bool | 写这个端口是否需要按 5 种载体各有一份内核实现（FGR-EMG-018） |
| `unit` | string | 幅度单位：秒 / 米 / 份 / 量 / 比例 |
| `nameKey` / `descKey` | string | `emg.port.<id>.name` / `.desc` |
| `shape` / `color` | string | 图标形状为主、颜色为辅（色盲安全，B15） |
| `stage` | int | 从 FG-EMG 第几阶段起可用（1～4） |

- 四列 `dirs` / `perceive` / `carrierImpl` / `stage` 不逐行手填，按下列推导规则生成（`tools/fgdata_emg.py` 生成时套用，表校验比对）；2.4～2.7 节命名总表里显式写出的值优先于推导：
  - `dirs`：2.4 节“方向”列写明的照写；其余端口一律“两者”（可读可写）。事件端口按第 4 节表：“可发出 = 是”的为两者，其余只读。
  - `perceive`：族不是语法、元程序时为 true；语法、元程序族恒为 false。
  - `carrierImpl`：族属于语法、物质、能量、场、实体（`ent.*` 生成类与 `prop.*` 写端）时为 true；事件、协同、相态、底盘、地形、劫持、节拍族为 false（由规则或内核统一结算，不按载体各写一份）；元程序族上面两类都没点名，按编译期指令（作用于下游程序段、不直接结算载荷）取 false（EMG1-DATA-01 补，待用户复核）。
  - `stage`：默认取 2.3 节族阶段（地形族取 2）；例外：`ter.obstacle`、`ter.cover`、`fld.deflect`、`chs.moving` 为 1（内核已有障碍圆、残骸、敌方偏折场与单位移动状态，FG19A 申请 A1；`chs.moving` 读哪个内核字段在阶段 1 开工时核实，否则燃迹、拖尾整条切轨会被推到阶段 3）；`grm.anchor` 为 3（随熔合接线交付，FG19A N43）；物质、能量、相态写端在阶段 1 走过渡动词（FG19A 第 3.2 节），`stage` 仍记 2。
  - `numericOnly`：只有 2.4 节标“是”的三个 `grm.mod.*` 为 true，其余全部 false。`prop.mass`、`prop.integrity`、`prop.conductive`、`prop.flammable` 作写端时 `numericOnly = false`（它们被场、撞击、传导、点燃规则读取，属跨通道量；并入 FG19A 申请 A6）。

**FGR-EMG-011 声明表 `fg.TbChannelDecl`（“声明读 / 写通道”的数据形状）**
- 固件、混合固件、作战组件、功能组件、结构模块、底盘特性、敌方单位行，全部用本表声明自己读 / 写哪些端口。一行一条声明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `owner` | string | 内容 ID，原样沿用：`fw_*`、`fw_mix_*`、`comp_*`、`func_*`、`struct_*`、`chassis_*`、敌方单位行 ID |
| `ownerKind` | enum `EmgOwnerKind` | firmware / component / structure / chassis / enemy |
| `seq` | int | 同一 owner 内的序号（从 1 起）；`(owner, seq)` 唯一 |
| `dir` | enum `EmgDir` | read / write |
| `port` | string | `fg.TbChannelPort.id` |
| `role` | enum `EmgRole` | 读：`trigger`（端口发生时执行本 owner 的写端）、`condition`（端口为真时才生效）、`sense`（读量值决定幅度）、`scope`（扩大读取范围，如中继）。写：`emit`（排放 / 产生）、`modify`（写入载荷参数）、`spawn`（生成实体或子载荷）、`inject`（注入能量或累积量）、`apply`（施加状态 / 相态） |
| `amount` | float | 主幅度，单位按端口 |
| `param2` | float | 副参数（如触发器的份数、定时秒数、近炸半径） |
| `carriers` | flags | 适用载体：射弹 / 格斗 / 无人机 / 力场 / 布区的分号组合；全部填 `all`（fg 表不许留空，按代码事实改，EMG1-DATA-01） |
| `heat` | float | 本条声明附加的每发热量（可为 0），计入 FGR-EMG-016 |
| `textKey` | string | `emg.decl.<owner>.<seq>`；读法说明由“端口 × 载体”短语生成（沿用 `tools/fgdata_firmware.py` 的 `reading_text` 生成做法），不手写 |
| `stageGate` | int | 本条从哪一阶段起生效；未生效前该 owner 继续走旧 `readFields`（FGR-EMG-019） |

- 声明表**只**描述 owner 自己；任何列里出现另一个内容 ID（除 `owner` 列）即为非法（FGR-EMG-013）。

**FGR-EMG-012 指令类别由声明推导，不另填**
- 编译器按 owner 的写端推导它在程序里是哪一类指令，优先级从高到低：
  1. 写 `grm.trig` → **触发**
  2. 写 `grm.anchor` → **接线**（只连接前后两条指令，本身不放子载荷、不结算效果，FG19A 第 4.1 节）
  3. 写 `meta.*` → **元程序**
  4. 写 `grm.mod.*` → **修饰**
  5. 其余 → **效果**（排放物质、注入能量、施加相态、生成实体、发出事件）
- 写 `grm.inherit` 的指令按第 5 条推为效果，作用域是整个程序（编译期生效，FGR-EMG-033；FG19A 申请 A11）。
- 一条固件可以同时有类别写端和效果写端。效果写端挂在这条指令所在的节点上（FGR-EMG-031）。
- 修饰类指令的读端（包括 `role = trigger` 的事件读端，如霰射、广角读 `evt.fire`，跳弹、回旋读 `evt.hit`）只决定该修饰在哪一类结算上生效：`evt.fire` = 出手时写入载荷，`evt.hit` = 命中时生效，`evt.bounce` / `evt.pierce` 同理。它不产生额外结算、不放子载荷；被继承时读端随修饰一并带上（FGR-EMG-033）。“触发器”语义只属于写 `grm.trig` 的指令（FGR-EMG-034）。

### 2.2 规则

**FGR-EMG-013 禁止固件 ID 特例**
- 编译器（`BlueprintCircuitCompiler`、新程序编译器）、`CarrierReadings`、战斗内核（`Sim/Combat/`）、所有规则表（`fg.TbChannelRule`、`fg.TbPhaseRule`、`fg.TbFieldCarrierRule`、`fg.TbChassisTrait`）都不得出现 `fw_`、`comp_`、`func_`、`struct_` 开头的 ID 判断。底盘特性按“状态端口 / 载体类别”生效，不按底盘 ID 写进别处的分支（FGR-EMG-141）。
- 自检 `FgEmergenceRuleAuditSelfCheck`：扫上述表的非 owner 列与 `Sim/Combat/`、编译器源码里的字符串字面量，命中即失败。
- 过渡豁免只有两条现存装配反应（FGR-EMG-021），不得新增。
- 审计范围按代码事实加宽（EMG1-DATA-01）：除 `fw_` / `comp_` / `func_` / `struct_` / `chassis_` 字符串字面量外，还扫组件 / 固件 / 底盘 ID 常量引用（`ComponentCatalog.*Id`、`FirmwareCatalog.*Id`、`ChassisCatalog.*Id`）与 ID 配对检测函数，按“文件 | 符号 | 出现次数”比对；扫描范围另含编译器调用的 `BlueprintCircuitBoard.cs`（热量 / 带宽函数）与 `GL/Campaign/Emergence/`。扫描发现 7 条早于 FG19 的存量判断（编译器 3 处：静默标记器、铸造重炮开火方式、散热鳍；`BlueprintCircuitBoard` 热量函数里重炮 + 过载配对积热 4 处与中继带宽 1 处；`CarrierReadings` 固定底盘分支 1 处），它们不是装配反应、不进豁免，登记 FG-GAP-169 作只减不增的存量清单，按承接卡逐条清零（编译器与热量侧最迟阶段 2 出口，中继带宽与固定底盘分支最迟阶段 3 出口）。

**FGR-EMG-014 新固件准入（现有固件改造同标准）**
- 至少 1 条读端，且端口的 `perceive = true`（事件、物质、能量、属性、相态、场、协同、底盘状态、地形、劫持、节拍）。
- 恒真事件（`evt.fire` 每次出手都发、`tmp.beat` / `evt.beat` 每拍都发，与世界状态无关）作 `trigger` 时**不计**准入读端，这条固件另需至少一条 `sense` / `condition` 感知读端（FG19A 申请 A12；FG19A 第 1 节 6 条与 N05 已按此补读端）。FGR-EMG-034 的“触发器恰好读 1 个事件端口”只管触发计数，不使恒真事件满足准入。
- 至少 1 条写端，且端口的 `numericOnly = false`。只有 `numericOnly` 写端的固件不准入。
- 感知读端与准入写端分属至少 2 个不同的通道族（用户批准口径 DESIGN F.4“至少接 2 个通道，读 1 个、写 1 个”；`prop.*` 与 `ent.*` 同属实体族，读写都在实体族内不算 2 个通道）。`FgChannelAdmissionSelfCheck` 同步判定。按此口径，扩口、桥接、处决三条都以 `evt.hit` trigger 作跨族的感知读端（FG19A 第 0.3 节口径 1、第 1 节第 12、23、36 行）：扩口另读 `prop.mass` sense，桥接另读 `prop.conductive` sense，处决另读 `prop.integrity` condition；不改读 `fld.*` / `en.*`，因为这两族阶段 2 才有，按整条切轨（FGR-EMG-019）会把这三条推迟到阶段 2。
- 读端、写端在 5 种载体上都要有落点（FGR-EMG-015）。
- 自检 `FgChannelAdmissionSelfCheck` 对 `fg.TbFirmwareKind` 全部行（含 30 条混合固件，按展开后的两条父声明判）逐条判定，不通过即失败。现有 8 条数值型（霰射、扩口、广角、装甲击穿、反应增幅、谐振、磁聚、冲击波）与 13 条混合型的改造方案在 FG19A，必须在阶段 1 结束前全部通过（`stageGate` 允许机制分阶段生效，但声明在阶段 1 就要写齐）。
- 敌方单位行、预制固件（FG08 遗迹、FG13 舰队）同样按本条准入，但分阶段判：阶段 1 只判玩家侧（44 条 + 30 条混合）；云端澄净的排放行（喷淋池、液氮池、油污爬行者油迹等迁入斑块的行，`ownerKind = enemy`）在阶段 2 随 EMG2-MAT-02 写声明并过准入；其余敌方行在阶段 4 随 EMG4-HIJ-01（敌方同程序）判；预制固件在各自的承接卡里判。

**FGR-EMG-015 零死对（载体 × 端口）**
- 规则一（实现完整）：`carrierImpl = true` 的写端口，在 `fg.TbPortCarrier`（FGR-EMG-018）里 5 种载体都有行。
- 规则二（行为可见）：固件（`ownerKind = firmware`，含混合固件展开后的两条）的每条声明在 5 种载体上都要产生可观察的行为差异；部件、结构模块、底盘特性、敌方单位行的声明只在其自身载体或宿主上验证开 / 关差异（FG19A §2“部件写端只在自身载体上有实现”）。判定沿用并扩展 `Assets/Editor/QA/FgReadingMatrixSelfCheck.cs` C 段（`:318-354`）的“读法开 / 关行为指纹必须不同”断言，扩到“声明开 / 关”与“在程序首位 / 末位”两种位置。
- 规则三（有源）：每个读端口至少有一个正常游戏可获得的写者（固件、部件、敌人、世界常驻源）。“动能无人挂所以脆裂打不出来”（FG-GAP-052）这类无源端口不得存在。已在 `fg.TbChannelPort` 注册、但没有任何声明或规则引用的端口（例：相关新固件落表前的 `meta.*`、`hij.hack` 这类只写端口，以及 `evt.ping`——既没人写也没人读，规则三的“读端有写者”判不到它们），同样算无源缺口：列入模糊测试器与表校验的“已登记缺口”清单，不得静默通过；端口 `stage` 不高于当前阶段、到该阶段出口仍无人引用即失败（FGR-EMG-221，第 12 节新固件落表）。
- 规则四（可达）：`fg.TbChannelRule` 每一行的两侧端口都有源，且模糊测试器在固定用例集里至少触发过一次（FGR-EMG-221）。

**FGR-EMG-016 代价规则**
- 三种代价，全部在编译时确定、在预览里分项显示（FGR-EMG-038），超出时降级而不是拒绝编译：

| 代价 | 计算 | 超出时 |
|---|---|---|
| 热量（每发） | Σ 指令热量（`fg.TbFirmwareKind.heat`，混合固件两父相加，沿用现规则）+ Σ 声明 `heat` + Σ 触发节点（`emg.heat.trigger_gen` × 子节点代号）+ `emg.heat.per_child` × 全树子载荷份数 + 元程序加成（FGR-EMG-042）+ 规则开火者代价（`fg.TbChannelRule.cost.heat`：本行在开火时可判定成立时记给开火者，**取代**相关指令的表值热量、不叠加；全表只有熔穿过载 P03 填 25，取代过载表值 15，不进过载声明 `heat`；P03 保留 `ReactionSpent` 门控冷却的原语义；FG19A 申请 A14、FG19B P03、FG19B 第 9 节第 16 条） | 沿用现有积热与过热停火（`Overheat`），不禁止 |
| 弹载容量 | 每个节点能装的指令数，逐代减半（FGR-EMG-032） | 装不下的指令不编译，预览写原因 |
| 刷写带宽 | 母机同时维持的“已刷写指令”总数上限（FGR-EMG-036） | 新放出的实体程序从末尾截断 |
- 暴露（FG16 §9）只按根载荷的发动计一次，子载荷与元程序重复执行不重复计暴露（待用户确认，第 14 节）。

**FGR-EMG-017 同端口幂等（数值不叠加）**
- 重复判定键 = （写端口, 角色, 生效事件, 目标 / 面过滤, 延迟）。同一节点内键完全相同的写端只生效一次，取幅度大者，第二条显示“重复修饰无效 / 重复排放无效”；键不同的各自结算，都计热量。
  - “生效事件”取该指令的事件读端（无事件读端记为“出手”）。例：腐蚀弹头（`evt.hit` 排 `mat.acid`）与酸液（`evt.expire` 排 `mat.acid`）键不同，命中、终结各排一次；锁定缓存（`evt.hit` 发 `evt.marked`）与广角（`evt.fire` 发 `evt.marked`）键不同，各自生效。
  - “目标 / 面过滤”按端口分两种合并方式：
    - `grm.mod.bounce`：面过滤（单位 / 非单位面）是键的一部分，各面分别取剩余反弹次数的大者。例：[跳弹, 壁撞] 两种反弹都生效——撞单位按跳弹改向下一目标，撞障碍 / 残骸 / 固态斑块按壁撞反弹（兑现 FG19A D-09“三者不再共用一个字段”）。
    - `grm.mod.homing`、`grm.mod.chain`：过滤是目标偏好，不进键；幅度（转向量 / 跳数）取大，偏好按固定顺序合并。homing 沿用 FG19A 0.3 #8：已标记 > 热信号 > 最近；chain：只跳已标记 > 导电优先 > 最近。例：[电弧, 标记跳转] 跳 2 次，先找已标记目标、再找导电目标，同时每跳仍注入电荷（`en.elec` 键与 chain 无关）。
      - 编译产物（EMG1-PRG-01）：合并后只留 1 行，偏好写在该行 `EmgInstr.Flags` 的 `PreferMarked` / `PreferHeat` / `PreferConductive` 位（由写同键各条指令的读端推出、按位并），内核按上述固定顺序挑目标；chain 只有“已标记”一种偏好时只跳已标记目标（FG19A 第 1 节第 20 行）。内核执行归 EMG1-GRM-01。
  - 不同端口从不互相作废：[回波, 装甲击穿] 各自的 `en.kinetic` 若生效事件不同即各自结算；[电容蓄力, 电弧] 的 `en.elec` 同理。
- 唯一能让同一键多次结算的结构是元程序“复制 / 循环”，它们付热量（FGR-EMG-042）。
- 取代 `FG02:206` 的“同参数加法叠加受上限”。

**FGR-EMG-018 端口 × 载体实现表 `fg.TbPortCarrier`**
- 由现有 `fg.TbCarrierReading`（字段 × 载体 → 内核动词，140 行，`tools/fgdata_reading.py`）扩展：加 `port` 列，把“字段”换成“端口”。旧字段行保留到双轨期结束（FGR-EMG-019）。

**FGR-EMG-019 双轨迁移**
- `stageGate` 未到（高于运行时总开关 `emg.stage`，ADR-EMG-001 ⑮）的声明不生效，该 owner 继续走旧 `readFields` → `CarrierReadings` 路径（`CarrierReadings.cs:231-346`）。同一 owner 同一阶段只能走一条轨，不得两轨同时结算（自检比对）。

- 阶段 4 结束时旧 `readFields` 列只保留作存档对账，不再被战斗读取；`GeneCatalog` 旧基因编译（`BlueprintCircuitCompiler.cs:279-310`）只保留给 `TotalNormalizedDamage` 预览，ADR-EMG-001 决定是否一并退役。

### 3.2 推荐方案：槽位顺序即程序顺序的线性程序

**FGR-EMG-030 程序来源与顺序**
- 每把武器的程序 = 一条有序指令序列，顺序与现有编译链顺序一致：
  1. 接入时、且接入口在至少一条源→汇路径上：接入固件 `U1…Uq`（按 FGR-SIG-023 实际插入的那几条，信号核槽序）；
  2. 机器固件槽 `S1`、`S2`（空槽跳过）。
  - 即 `程序 = [U1…Uq, S1, S2]`；AI 驾驶、没有接入口或接入口不在路径上时 `程序 = [S1, S2]`。
  - 现有预览字段 `FirmwareIds` 的顺序与此相反（机器在前，ADR-EMG-001 事实 1.18）：编译器显式从 `UplinkFirmwareIds` 与 `FirmwareSlots` 组装，不读 `FirmwareIds`（ADR ②、第 7 节第 11 条；阶段 1 卡片“规格”点名本条）。
- 载体本身（8 号格主组件的输出）是程序的隐含末尾，所以全部指令都在根载荷“上游”。
- 路径不产生多份程序：多路径只继续影响芯片被动与 `TotalNormalizedDamage` 预览（`BlueprintCircuitCompiler.cs:268-271`），“是否经过接入口”只决定接入固件进不进程序。路径上限 4 不受影响。
- 不改蓝图存档结构：程序完全由现有 `OrderedFirmwareIds` 与信号核槽序推出（`GL/Campaign/CampaignRecords.cs:205-262`），只需升 `ContentVersionAtCompile` 让旧蓝图提示重编译（代码核实：原先没有比较点，EMG1-PRG-01 补上——`CampaignSaveService.CurrentContentVersion` 1 → 2，`BlueprintEditorService.IsCompiledOnOldContent` + 电路编辑器预览提示“基于已变化内容编译，请重新编译”；FG-GAP-170）。
- 玩法含义：接入的固件永远排在机器自己的固件前面。玩家把一条触发器放进信号核 1 号槽，接入后它会把机器自己的固件装进子弹药——接入改变的是整把武器的程序结构（P2）。

**FGR-EMG-031 程序树与节点分配（编译时，确定性）**
- 输入：指令序列 `I`（混合固件展开为两条，父 A 在前，FGR-EMG-044）。程序里有元程序“反转”时，编译器对正序、逆序两个序列各跑一遍下列步骤，得到两棵树（FGR-EMG-040）。
- 步骤：
  0. 单位级读端提升：读端是单位级事件（阵亡、被击、过热、冷却完成、接入、断开、拾取、夺控、归还；“归还”按 FG19A A3 补齐，EMG1-PRG-01 审查修复 2026-10-29）的指令先放进根节点，再处理其余指令；根满时被提升的指令记“溢出”（FG19A 申请 A3、A13）。
  1. `cur = 根节点`（0 代，容量 `C(0)`）。
  2. 依次取指令 `x`：
     - 若 `cur` 已满：沿父链回退到第一个未满的祖先；回到根仍满，则 `x` 记为“溢出”，不编译，继续下一条。
     - 把 `x` 放进 `cur`，`cur.used + 1`。
     - 若 `x` 是触发器：当 `cur.gen < 2` 时新建子节点（`gen + 1`，容量 `C(gen + 1)`，挂在 `x` 的触发事件上，份数 = `x` 的 `grm.trig.amount`），`cur = 子节点`；当 `cur.gen = 2` 时 `x` 照样占位，但不生成子节点，预览写“代际已满”。
  3. 全部放完后做继承（FGR-EMG-033）。
- 效果指令（物质、能量、相态、实体、事件写端）只挂在它所在的节点：该节点每次结算（命中、反弹、穿透、到期……按载体定义，FGR-EMG-035）执行一次，不传给子节点。
- 同一程序、同一内容版本必须得到相同的树与相同的编译签名（IC-REQ-010）。

**FGR-EMG-032 弹载容量逐代减半**
- `C0` = 机器固件槽数 + 接入口配额（现值 2 + 2 = 4）；`C(gen) = max(1, floor(C0 / 2^gen))`，现值即 4 → 2 → 1。
- 代际上限：子载荷最多到 2 代（0、1、2 共三层，对应事件链深度 3，FGR-EMG-064）。
- 继承来的指令同样占容量（FGR-EMG-033），这就是“少带几条程序换更多子弹药，还是少几枚但每枚都追踪穿透”的取舍。
- 配额或槽数将来变化时公式不变（FGR-EMG-039）。

**FGR-EMG-033 修饰的作用域与继承（程序刷写）**
- 修饰只作用于下游：位置 `i` 的修饰作用于它所在节点的载荷，并被**位置在 `i` 之后**的触发器放出的子节点（及其后代）继承。位置在子节点作用域之后的修饰不回溯影响该子节点。
- 子节点先放自己的下游指令；剩余容量再按“最近的祖先优先、同一祖先内按程序位置”补入继承的修饰；继承来的修饰对孙节点同样可再继承。装不下的继承修饰预览写“未刷写：<名>（子弹药容量已满）”。
- 默认只继承修饰。触发器与效果不继承，除非程序里有写 `grm.inherit` 的指令（集群协议类，FG19A 定）——这时触发器 / 效果也进入继承候选，仍受容量约束。
- 按写端判：被归为修饰的指令若另有效果写端（过载、电容蓄力、电弧、锁定缓存等），默认继承进子节点的只是它的 `grm.mod.*` 写端；效果写端只有在程序里有 `grm.inherit` 时才一并继承（FG19A 第 0.3 节口径 5、申请 A4）。
- 例（按本规则推导，仅示意，固件的正式声明以 FG19A 为准）：
  - `[寻的, 分裂, 分裂]`：根 = 寻的 + 分裂（命中放 3 份）；1 代 = 分裂（自己的）+ 寻的（继承），满；2 代 = 寻的（继承），满。结果：二级子母弹，每颗都转向寻的。
  - `[分裂, 漏油]`（AI 机器 2 槽即可）：根 = 分裂；1 代 = 漏油。结果：每颗子弹药落点各留一摊油。
  - `[延时引信, 贯穿, 漏油, 寻的]`：根 = 延时引信；1 代 = 贯穿 + 漏油，满；寻的回到根。结果：会寻的的母弹飞行中定时裂开，子弹药穿透并漏油；子弹药不寻的。

- 程序只在装配变化时编译（接入、离开、装配变更、冷却起止），不按帧（ADR-ARC-003 结论 2）。
- 弹体增加：代号、所在节点、剩余穿透、剩余反弹、沾染位、质量（FGR-EMG-111）。具体结构、`CombatConst.FormatVersion` 升级与旧快照默认值由 ADR-EMG-001 定。
- `CombatReading` 继续承担根节点的数值读法（双轨期，FGR-EMG-019）。

### 3.4 元程序（通道 2，阶段 3）

**FGR-EMG-040 六条元程序指令的精确语义**
- “下游段” = 同一节点内、元程序指令之后的全部指令（包括其中触发器放出的整棵子树）。

| 指令 | 何时生效 | 语义 | 对修饰 | 对触发器 / 效果 |
|---|---|---|---|---|
| `meta.repeat` 复制 | 运行时，每次结算 | 下游段再执行一次，间隔 `emg.meta.repeat_gap`（0.1 秒），同位置 | 不重复（幂等） | 触发器多放一组子载荷；效果多结算一次 |
| `meta.loop` 循环 | 运行时，宿主存续期间 | 每 `emg.meta.loop_period`（0.5 秒）执行一次下游段，直到宿主结束或达 `emg.meta.loop_max`（8 次） | 不重复 | 飞行中的弹体沿途周期执行（例：循环 + 漏油 = 沿途滴油；循环 + 触发器 = 飞行中布子弹药） |
| `meta.if` 条件 | 运行时，每次结算 | 本指令的读端（`role = condition`）为真才执行下游段，否则整段跳过 | 条件为假时下游修饰不生效 | 同左 |
| `meta.random` 随机 | 运行时，每次结算 | 从下游段中随机选 1 条执行，其余跳过；随机用内核无状态哈希（因果链、事件序号、地点种子，确定性，不进快照，ADR-EMG-001 ⑬） | 选中才生效 | 同左 |
| `meta.reverse` 反转 | 编译时出两棵树，运行时选用 | 编译期同时出正序、逆序两棵树（逆序树：下游段顺序反转，改变谁被哪个触发器装进子弹药；段内 `fld.pull`↔`fld.push`、`grm.mod.return` → 前冲，取反）；运行时按本指令的 `prop.heat` condition 读端（本机积热 ≥ 50%）用逆序树，否则用正序树；两棵树都计入编译签名（FG19A N07、申请 A7） | 位置改变 | 位置改变 |
| `meta.defer` 延后 | 运行时，每次结算 | 下游段推迟 `emg.meta.defer_seconds`（1 秒）执行：瞬时载荷在结算点执行，移动载荷在其当时位置执行 | 不受影响（修饰在发射时已写入） | 推迟执行 |
- 条件类可读的端口不限，常用：`evt.marked`（目标被标记）、`phs.*`（目标处于某相态）、`mat.*`（目标或自身站在某物质里）、`prop.integrity`（结构完整度低于幅度）、`prop.heat`（本机积热高于幅度）、`chs.*`（本机底盘状态）。

**FGR-EMG-041 优先级与嵌套**
- 编译期：先生成逆序序列（按程序位置从前往后做全部“反转”），再对正序、逆序两个序列各做节点分配与继承；没有“反转”时只有正序一棵树。
- 运行期，同一节点内多条元程序按程序位置从外到内嵌套：前面的元程序的下游段包含后面的元程序。求值顺序：条件 → 随机 → 复制 / 循环 → 延后。
- 例：`[若目标被标记(条件), 复制, 分裂]` = 命中已标记目标时，放两组子载荷。

**FGR-EMG-042 上限与代价**
- 每次结算的下游段执行次数（各层复制相乘）≤ `emg.meta.max_exec`（4）；循环次数 ≤ `emg.meta.loop_max`；一条链上累计延后 ≤ `emg.meta.defer_total_max`（3 秒）。超出部分不执行，预览写原因。
- 热量：复制段的热量 ×（执行次数 − 1）计入每发热量；循环段热量 × `emg.heat.loop_factor`（2）；随机段热量按段内指令热量平均值计；条件、反转、延后不加段热量，只计自身热量。
- 元程序本身占容量 1 条，也受准入（必须有感知类读端）。

**FGR-EMG-043 元程序在 5 载体上的读法**

| 指令 | 射弹 / 无人机 | 格斗 / 力场（瞬时） | 布区 |
|---|---|---|---|
| 复制 | 命中点 0.1 秒后再结算 | 出手点 0.1 秒后再结算 | 每个区域节拍再结算 |
| 循环 | 飞行中每 0.5 秒执行 | 在出手点留下“程序锚点”，`emg.meta.loop_anchor_seconds`（2 秒）内每 0.5 秒执行 | 区域存续期间每 0.5 秒执行（与区域节拍无关） |
| 条件 | 对命中目标 / 自身求值 | 对主目标 / 自身求值 | 对区域内首个单位 / 区域本身求值 |
| 随机 | 每发 | 每次出手 | 每个区域节拍 |
| 反转 | 编译期出两棵树、运行时按条件选用，全载体相同 | 同左 | 同左 |
| 延后 | 1 秒后在弹体当时位置；弹体已结束则在结束点 | 1 秒后在出手点 | 1 秒后在区域中心 |

### 4.2 结构、预算与顺延

**FGR-EMG-061 事件数据结构**
- 内核事件记录（只含值类型）：`Kind`、`Depth`（链深）、`Code`、`Code2`、`Unit`、`Other`、`Value`、`Value2`、`Pos`、`Node`、`Chain`（因果链 ID，FGR-EMG-180）、`Seq`（全站递增序号）。布局按 ADR-EMG-001 ④：每条 56 字节，`Code` / `Code2` 为 ushort（放得下规则下标与端口码）；实体一律用稳定 ID 而不是下标——弹体、斑块、无人机、残骸、场各加每地点单调发号的 `Id`，因为下标每步压实会变（ADR 第 7 节第 7 条）。
- 由事件引起的一切新事件、新斑块、新实体都继承 `Chain`。
- `Depth` 只在“事件触发的生成”上加 1：触发器放出的子载荷、事件驱动的规则产物（新斑块、新实体、相变效果）、破片。原地物质转化（油 → 明火、水 → 冰等同一块斑块的转化）、热交换、能量传导、斑块合并**不**增加 `Depth`，取来源 `Depth` 的最大值继承。物质蔓延的规模由每步规则结算上限、斑块容量与软上限约束（FGR-EMG-082、084），不靠链深截断——一排相连的油斑块可以整片烧完（FGR-EMG-092）。

**FGR-EMG-062 按需发事件**
- 内核按地点维护“监听掩码”：当前所有活跃程序与规则表里被读的事件码集合。没有人读的事件不入队（例如没有任何程序读 `evt.prox` 时不做近炸求值；没有读 `evt.hit` 区域节拍命中的程序时，区域节拍不发命中事件）。
- 掩码在程序表或规则表变化时重算（O(程序数 + 规则数)），不按帧。

**FGR-EMG-063 每步预算与顺延（不丢）**
- 内核每步（60 Hz 固定步）最多处理 `emg.bus.per_step`（初值 512）条事件；超出的按 `Seq` 先进先出留到下一步，进快照，**不丢弃**。
- 由此衍生的生成请求（子载荷、斑块、实体）在池满时同样排队顺延，生成时才开始计寿命；排队情况可在调试层与因果链里看到（“弹体池满，顺延 3 步”）。
- 队列容量 `emg.bus.capacity`（16384）。逼近容量视为设计缺陷：模糊测试器必须报告（FGR-EMG-221）；运行时最后保护是把同一步、同类、同源的事件合并为一条计数事件，仍不丢失计数。
- 同一步内的处理顺序只认 `Seq` 先进先出：一步内各段按内核固定步序、段内按下标入队，`Seq` 本身确定，不另做排序（ADR-EMG-001 ④、第 7 节第 14 条）；本步处理中新产生的事件追加到队尾，预算有剩就本步继续处理。总线 `Seq` 是自己的计数器，不与 `CombatEvent.Seq` 共用（FGR-EMG-213）。
- 不改变现有“玩法事件 64 / 步、超出顺延不丢；提示事件 24 / 步、超出丢弃”的口径（`tools/fgdata_combat.py:17`；`Sim/Combat/CombatKernel.cs:1280-1306`）。

**FGR-EMG-064 链深上限 = 代际 3**
- `Depth` 从 0（玩家 / AI 的一次出手、一次世界源排放）开始；处理 `Depth = 3` 的事件时不再生成新事件、新载荷、新斑块，计数 `EmgDepthCut` 并在因果链末端显示“链深已达上限”。原地物质转化、热交换、传导、合并不加链深，也不受此截断（FGR-EMG-061）。
- 子载荷代号（≤2）与链深（≤3）是两个独立上限：子弹药命中引起的物质反应仍可继续，直到链深 3。

**FGR-EMG-065 扇出与每宿主上限**
- 一条事件最多唤起 `emg.bus.max_fanout`（8）条监听指令 / 规则，按单位槽位序截断，被截断的计数。
- 每个载荷节点对同一事件码最多触发 `emg.trig.max_per_host`（3）次（穿透、反弹、近炸重复进入时）。

**FGR-EMG-066 热更层注入的事件**
- `evt.uplink`、`evt.unlink`、`evt.pickup`（热更拾取）、`evt.seize`、`evt.release`（夺控类）由热更层在两步之间经 `CombatSite` 调内核命令注入，O(1)，与现有即时调用同一做法（底稿 03 §4B）。
- 接入 / 断开已有广播：已核实（`SignalUplinkService.cs:1260`、`:1432`，ADR-EMG-001 第 7 节第 3 条），注入点挂在这两处广播上。

**FGR-EMG-067 与热更层的交接**
- 涌现结果交给热更层只用两种方式：
  1. 可靠计数：内核按规则 `StableKey`、端口、实体种类累加计数，并维护“本步有变化的规则下标”脏列表；热更层每步只读脏列表（与 FG2-FW-04 的“按可靠计数每步增量结算”同一做法，`FG02:196`）。
  2. 需要热更层改存档状态的少数结果（永久地面改变、劫持开始 / 结束、发现记录）走玩法事件，受 64 / 步预算、顺延不丢。
- 热更层每帧开销与敌人数、弹体数、斑块数无关。

**FGR-EMG-068 术语区分**

**FGR-EMG-082 合并、容量与降级**
- 同物质、同层、重叠面积比 ≥ `emg.patch.merge_overlap`（0.5）的两块合并：份量相加，面积守恒求新半径，温度 / 电荷按份量加权，Owner 与因果链取份量大者并在链里记“合并”。
- 每地点上限 `emg.patch.capacity`（单地点最大 1024，与现有读法区域、场地区域上限分开计；实际值由热更层在地点载入 / 卸载时按世界级总上限 `emg.patch.world_capacity` 分摊，FGR-EMG-202）。其中划出世界源保留额 `emg.patch.reserve_world`（96，FG19B §8.1、第 9 节第 9 条），世界源（液洼、首领灌注等）不被战斗斑块挤掉；酸沼是虚拟世界源、不占槽（FGR-EMG-081），保留额里危害带那部分可回收。满了时：新斑块先并入最近的同物质斑块；仍不行则最早生成的同层斑块提前到期。降级都计数、在调试层可见，不静默。
- 斑块节拍 `emg.patch.tick`（0.25 秒）：结算物质 × 物质、物质 × 能量规则，扩散，衰减。每块按自带的下次节拍时刻 `NextTick` 错相，每步最多结算 `emg.patch.per_step`（69 块，FG19B §10），其余顺延到下一步优先结算；不按斑块下标轮转分桶（斑块会压实、合并，下标分桶会漏拍或重拍；ADR ⑤、第 7 节第 15 条①）。

**FGR-EMG-083 物质中立与沾染**

**FGR-EMG-085 反应去倍率化**

- 避险只作用于教义自选的站位（追击、风筝、索敌走位）；玩家显式下达的移动 / 攻击移动路径不改写，只在路径会穿过危险斑块时给一次警告级提示（B08）。
- 实现落点（ADR-EMG-001 ⑯、第 7 节第 19 条）：在内核单位移动步里，把“有害斑块排斥力”叠加到教义自选站位的期望方向上，只查本单位周围空间哈希格里按有效抗性判为有害的斑块，不在热更层重新寻路；排斥动作写进因果链（B20）。玩家显式命令的路径不施加排斥力，按上一条只警告一次。
- 玩家接入的机器不受此教义约束。

### 5.2 能量传导

**FGR-EMG-090 四种能量**
- `en.heat` 热：抬高斑块温度与单位积热。`en.elec` 电：给斑块与实体加电荷并沿导体传播。`en.mag` 磁化：抬高实体磁化度，沿磁性接触传播。`en.kinetic` 动能：每次命中按载体与伤害产生，不传播，只被相变与规则读取。
- 注入方式：固件写端（`role = inject`）、规则产物、世界源（明火持续放热、带电斑块放电）。

**FGR-EMG-091 传导图**
- 每 `emg.conduct.tick`（0.25 秒）对带能量的斑块 / 实体做一次有界传播：节点 = 导电（或导热、磁性）强度 ≥ 0.3 的斑块、残骸、冷渣、金属碎屑，以及站在其中的单位；边 = 重叠或接触（圆心距 ≤ 半径和）。
- 每跳衰减 × `emg.conduct.falloff`（0.7），最多 `emg.conduct.max_hops`（6）跳，低于 `emg.conduct.q_min` 停止；每个传导节拍的节点访问 ≤ `emg.conduct.max_visits`（256，FG19B §10），超出时剩余能量顺延到下一节拍（ADR-EMG-001 ⑥、⑬，第 7 节第 15 条②）。传到的单位得到电荷 / 热 / 磁化累积量，并按 FG19B 吃少量附带伤害。
- 连锁类修饰（`grm.mod.chain`）选目标时优先站在导电斑块里的单位（兑现 `fw_arcchain` 描述“沿湿面优先”）。

**FGR-EMG-092 热：点燃、蒸发、过热停机**
- 可燃斑块温度 ≥ 点燃阈值 → 转为明火；水 / 冷却液温度 ≥ 沸点 → 部分转为蒸汽；熔融金属温度降到凝固点 → 冷渣。阈值在 `fg.TbPhaseRule` / `fg.TbChannelRule`。
- 对单位注入的热进入现有武器积热（单位 `Heat`）：敌人被持续加热会过热停火（`bhv.overheat_stop`），己方同样。另有结构积热累积量 `phs.overheat`（熔穿用，FGR-EMG-101），两者分开。
- 明火对相邻可燃斑块与站在其中的单位持续放热，形成“热传导引燃整片油区”。

**FGR-EMG-093 动能（关闭脆裂无源问题）**
- 每次命中产生动能 = 伤害 × 载体动能系数（`fg.TbSubPayload` / `fg.TbEntityProfile` 列；格斗、重炮高，光束为 0）；撞击（`evt.impact`）产生动能 = 质量 × 速度的平方 × 系数。
- 动能不传播，只被读：冻结 → 碎裂；冰、玻化层、固化胶块受动能 → 碎成碎屑或破片。从此不需要任何固件挂“动能”标签（FG-GAP-052 的根因）。

### 5.3 相变

**FGR-EMG-100 累积量与阈值语义（`fg.TbPhaseRule`）**
- 每个累积量（2.7 节 7 个）在单位与斑块上都是浮点数，字段：`enter`（进入阈值）、`exit`（退出阈值，小于 enter）、`decay`（每秒衰减）、`cap`（上限，默认 enter × 1.5）、`minDwell`（最短停留秒）、`guard`（退出后免疫秒，防止永久冻结；沿用云端 `ThawGuardT` 做法）、`resistCol`（读 `fg.TbEntityProfile` 哪一列抗性）。
- 进入：累积量 ≥ enter 且不在免疫期 → 进入相态，发 `evt.phase`，施加相态效果。退出：累积量 < exit 且已停留 ≥ minDwell → 退出，进入免疫期。
- 现有状态叠层（每位最多 3 层，`CombatTypes.cs:95`）对“累积型”状态改由累积量表达；其余状态位的叠层规则不变。

**FGR-EMG-101 单位相态清单**

| 相态 | 效果（主结果类） | 退出方式 |
|---|---|---|
| 冻结 `phs.frozen` | 不能移动、不能开火（B `bhv.freeze`）；受动能 ≥ 阈值 → 碎裂（P）并立即退出 | 衰减或受热 |
| 熔穿 `phs.meltdown` | 正面装甲失效；身下生成熔融金属斑块（S） | 衰减 |
| 麻痹 `phs.stun` | 1 秒不能行动并向周围导体放电（B + P `topo.arc`） | 定时 |
| 破甲 `phs.breach` | 装甲脱落成金属碎屑（S `mat.debris`）+ 质量下降、被推 / 牵引 / 撞击的位移变大；装甲清零只作附带（不设 `bhv.breach` 产物，FG19B §3.3 `phase_corrode`） | 衰减 |
| 磁化 `phs.magnetized` | 成为弱磁场源，吸附碎屑、破片与弹体（P `topo.redirect`） | 衰减 |
| 燃烧 `phs.burning` | 持续伤害（附带），向相邻可燃物放热 | 衰减、进水 / 冷却液 |
| 被劫持 `phs.hijacked` | 见 FGR-EMG-163 | 定时 |
- 现“冻结 = 易伤 +25%”（`tools/fgdata_reading.py` 的 `STATUS_EFFECTS`）改为上表定身语义，属于机制改动，待用户确认（第 14 节）。

**FGR-EMG-102 斑块相变（物质转化）**
- 斑块的相变就是物质转化，由 `fg.TbChannelRule` 的 S 类产物表达（水 → 冰、水 → 蒸汽、油 → 明火、熔融 → 冷渣、粉尘 + 明火 → 玻化层、聚合胶 + 酸 → 固化胶块）。完整清单在 FG19B。
- 固态斑块（冰、玻化层、固化胶块、冷渣）有耐久，受动能或高温破坏；破坏产物（碎屑、破片、水）由规则给出。
- 固态斑块 = 动态障碍圆（阶段 2，T 类产物 `ter.block` 的落点，ADR-EMG-001 ⑯、第 7 节第 19 条）：进空间哈希，单位移动与障碍圆同一套“推出 + 避让”逻辑；生成时把圈内单位按 `Id` 升序推到离圆心最近的边缘（确定性），之后不可进入，后续单位绕行；离地单位（`chs.airborne`）不受地面固态斑块阻挡。家园与有寻路镜像的地点只在固态斑块、熔坑、冻结桥生成或销毁时按覆盖格增量更新寻路镜像（内核到内核，不经热更层，改动进快照、读档后重放）；其余地点只做局部避让。熔坑、冻结桥属阶段 4（FGR-EMG-151、152）。

**FGR-EMG-103 抗性按属性，不按单位 ID**
- 精英、首领、阵营单位的抗性写在 `fg.TbEntityProfile` 的抗性列（寒、热、电、腐蚀、磁、入侵），作用于累积速度。云端澄净“免疫酸蚀位”（`ImmuneMask`，origin: `CombatLogic.Reading.cs:684`）改为“腐蚀抗性 = 1”的属性表达，内核实现可继续用免疫位（FGR-EMG-161）。

## 6. 实体统一（通道 6）

**FGR-EMG-110 实体种类**
- 内核里会受场、牵引、推力、能量影响的东西统一称实体，共 6 种：弹体（含子弹药，按代号区分）、无人机（含伴飞）、哨戒桩、单位（机器 / 敌人 / 炮塔 / 建筑，`CombatUnitKind`，`Sim/Combat/CombatTypes.cs:427`）、残骸（新增）、破片（新增）。
- 现状：单位已统一一套 SoA；弹体、无人机、区域、回波、护盾各自一套小结构，没有公共属性（底稿 03 §9）。本文不要求合并数据结构，只要求下条的公共属性块在每种实体上都有、语义一致。

**FGR-EMG-111 公共属性块（`fg.TbEntityProfile` 给默认值）**

| 属性 | 含义 | 被谁读 |
|---|---|---|
| 质量 | 受力后加速度 = 力 / 质量；撞击动能 | 场、击退、推铲、撞击 |
| 导电 | 是否进传导图（FGR-EMG-091） | 电 |
| 可燃 | 受热点燃的难易 | 热 |
| 磁性 | 磁场作用强度、磁化累积速度 | 磁场、磁化 |
| 热量 | 当前温度；单位另有武器积热（现有）与结构积热 | 寻的读热信号（`prop.heat`）、点燃、相变 |
| 电荷 | 当前电荷 | 麻痹、放电 |
| 结构完整度 | 剩余耐久比例（单位、残骸、固态斑块） | 处决、破坏 |
| 材质 | `material.steel` 钢 / `material.alloy` 合金 / `material.composite` 复合 / `material.ceramic` 陶瓷 / `material.glass` 玻璃 | 默认属性来源、击杀事件 `Code` |
| 抗性 | 寒、热、电、腐蚀、磁、入侵六列 | 相变累积速度（FGR-EMG-103） |
- 默认值（定性，数值在 FG19B）：

| 实体 | 质量 | 导电 | 可燃 | 磁性 | 备注 |
|---|---|---|---|---|---|
| 弹体 | 轻（重炮重） | 高（金属弹） | 低 | 高 | 子弹药质量 = 母弹 / 份数 |
| 无人机 | 轻 | 中 | 低 | 中 | 现状不吃伤害、不被选中，保持不变 |
| 哨戒桩 | 中 | 高 | 低 | 高 | 插地，不被场推动，可导电 |
| 单位 | 按底盘 / 敌人表 | 按材质 | 按材质 | 按材质 | 敌人行新增 `material` 列 |
| 残骸 | 原单位质量 | 按材质 | 按材质 | 按材质 | FGR-EMG-113 |
| 破片 | 极轻 | 高 | 无 | 高 | FGR-EMG-114 |

**FGR-EMG-112 场、牵引、推力对所有实体生效**
- 牵引、推斥、涡旋、磁场、击退、推铲对 6 种实体都生效，位移 = 力 / 质量（磁场再乘磁性）。推斥、牵引、涡旋场也推动气体层斑块，涡旋把粉尘聚浓（尘爆依赖它，FG19B 第 9 节第 4 条）。例：己方磁场把飞行中的弹体弯回来；推铲把残骸推成掩体或抛射物；牵引把敌人的弹吸进己方力场。
- 单位位移沿用现有可位移判定（`CanDisplace`，`CombatLogic.Reading.cs:651`）；固定底盘与哨戒桩不位移（FGR-EMG-140 锚定）。
- 被推动的实体以 ≥ `emg.impact.v_min` 撞上障碍、残骸或其他实体时发 `evt.impact` 并产生动能（FGR-EMG-093），兑现“壁撞”描述（底稿 01 D-03）。
- 场对弹体的查询走空间哈希；同时活跃的场 ≤ `emg.field.capacity`（64）。

**FGR-EMG-113 残骸实体（新增）**
- 生成：机器、敌人、炮塔在战斗内核里阵亡时生成残骸（现在只留墓碑槽位，`Tombstones`）。建筑由热更层管理，不生成内核残骸。
- 外部血量单位（己方机器与首领的血量在热更层，ADR-EMG-001 ⑦、第 7 节第 18 条）：
  1. 阵亡只有一个入口：内核直接击杀与热更层同步血量判死两条路径都走同一个阵亡入口，由它生成残骸、发 `evt.death` / `evt.kill`；同一单位只处理一次，不漏生成、不重复生成。
  2. 击杀归属：内核为外部血量单位记最后一次伤害请求的攻击者与因果链，阵亡时击杀者取它，不再是 0。
  3. “直接击毁”（碎裂、湮灭、处决等不留残骸的结果）打外部血量单位时，内核不自行判死，改发一条带“不留残骸”标志的致死伤害请求，由热更层判死后回到阵亡入口；下一次血量同步不得把它“复活”。
  4. 同一外部血量单位一步内受到的斑块接触、传导、持续伤害合并为一条伤害请求（命中类伤害照旧逐条），不挤占玩法事件 64 / 步。
- 属性：质量 = 原单位质量；半径 = 原半径 × 0.9；耐久 = 原最大耐久 × `emg.wreck.hp_ratio`（0.5）；材质与热量继承阵亡时状态。
- 作用：
  1. 掩体：挡弹（弹体线段与残骸圆相交即被吸收，发 `evt.absorb`，扣残骸耐久），残骸背后的单位获得掩护。
  2. 通行：单位穿过残骸减速 × `emg.wreck.slow`（0.5），**不改寻路网格**（避免动态重建开销；阶段 4 是否升级为寻路障碍待定）。
  3. 进传导图（导电材质）、可被点燃（可燃材质）、可被磁场吸动、可被推铲推动成抛射物。
- 存续：野外地点 `emg.wreck.seconds`（90 秒）后崩解为金属碎屑斑块；家园与前哨的残骸长期留存（FGR-EMG-150），直到被摧毁、被回收或被玩家工作单清除。
- 容量：每地点 `emg.wreck.capacity`（256）；满了时最早的残骸崩解为碎屑斑块（转化，不消失）。
- 与现有流程：远征战利品“残骸节点”、解析台“残骸”物品计数（`GL/Campaign/CampaignRecords.cs:877-880`）是另外的东西；己方机器阵亡后的现有回收流程与残骸实体的关系待核实，阶段 1 开工时对齐，不得出现“同一台机器的残骸被回收两次”。
- 进内核快照（FGR-EMG-211）。

**FGR-EMG-114 破片实体（新增）**
- 由碎裂、固态斑块破坏、残骸被重击、触发器的破片类子形态生成；本质是弹体池里的一种短寿命弹体，固定按 2 代处理（不再执行程序），命中仍发 `evt.hit`（链深 + 1），可被磁场吸动、可沾染。
- 残骸参与的 `matter_entity` 规则条件可以同时读“残骸在斑块里的停留秒数”和“残骸本次受到的单次动能”（FG19B W02），不新增残骸累计动能字段；残骸重击（单次动能 ≥ 40）生成破片不变。
- 份数、伤害、射程在 FG19B；共享弹体池 4096（`CombatTypes.cs:1099`），池满按 FGR-EMG-063 顺延。

**FGR-EMG-115 回收修复改为“击毁回收废料修复”（读残骸）**
- `fw_reclaim` 的新机制（第 11 节第 7 行；声明由 FG19A 定）：读 `evt.kill`（本机击毁目标），写 `ent.wreck`（就地拆解该残骸）→ 残骸消失，按残骸质量换算的维修量修复本机，上限 `emg.reclaim.max_ratio`（本机最大耐久的 15%），每秒最多一次。修复己方机器（外部血量单位）时发修复请求（新玩法事件，与伤害请求对称），由热更层改记录血量，下一次血量同步不冲掉修复量（ADR-EMG-001 ⑦、第 7 节第 18 条）。
- 与拆解钳（`comp_claw`，“击毁多回收废料”文案，落地与否未核实）合并为同一条“拆解残骸”规则：拆解钳击毁时额外得到废料物品。
- 取舍：残骸留着是掩体，拆了是维修量。取代现“按伤害 20% 回血”（`Blood` 标签 leech，`CarrierReadings.cs:323、418-419`）。

## 7. 其余通道（7、8、10、11、12、13）

### 7.1 场与载体互作（通道 7，阶段 2）

**FGR-EMG-120 穿过场 / 斑块的载荷被改写**
- 弹体、无人机子弹、破片穿过场或斑块时，按 `fg.TbFieldCarrierRule` 获得沾染或参数改变，命中时带给目标。规则方向（完整表在 FG19B）：
  - 穿过己方电晕场 → 带电，命中注入 `en.elec`；
  - 穿过冷却液 / 液氮雾 → 弹体降温：去掉带火沾染，已在出手时计过的热量不返还（FG19B §5、第 9 节第 10 条②），带寒，命中注入 `phs.chill`；
  - 穿过明火 → 带火，命中注入 `en.heat`；本身沾油的弹体会沿途拖出明火（`topo.trail`）；
  - 穿过烟 / 蒸汽 → 失锁，寻的修饰失效：烟 `emg.smoke.lockloss_seconds`（0.5 秒），蒸汽 0.3 秒（FG19B §5 `fieldrule_steam_payload`）；
  - 穿过磁场 → 弹道偏转（`topo.redirect`）；
  - 撞上玻化层 / 冰面等反射斑块 → 反弹（`topo.reflect`，发 `evt.bounce`）；
  - 穿过敌方偏折场 → 反射为对方弹体（沿用现有，`CombatLogic.cs:1591`）。
- 每发弹体每种沾染只记一次（幂等），沾染位进弹体结构（弹体沾染共 8 种，FG19B §3.2、第 9 节第 8 条；位宽由 ADR-EMG-001 ③ 定）。

**FGR-EMG-121 场改单位**
- 单位处于场内：电晕场持续加电荷；牵引 / 推斥 / 涡旋位移（按质量）；磁场按磁性吸引；冷雾持续加寒。规则同样在 `fg.TbFieldCarrierRule`（`target = 单位`，字段见 FGR-EMG-122，与 FG19B §5 一致）。

**FGR-EMG-122 表 `fg.TbFieldCarrierRule`**
- 字段：`id`（`fieldrule_<名>`）、`source`（场端口或物质端口）、`target`（载荷种类：弹体 / 无人机子弹 / 破片 / 单位）、`effect`（沾染位 / 参数 / 产物码）、`amount`、`once`（是否每载荷一次）、`faction`（`any` / `own` / `hostile`，指场的阵营与载荷阵营的关系）。由 FG19B 填。

### 7.2 跨机协同（通道 8，阶段 3）

**FGR-EMG-130 一台车的输出就是另一台车的输入**
- 斑块、残骸、能量、相态都是世界状态，任何机器的载荷都能读到别的机器留下的东西：A 车铺油、B 车点火、C 车用磁场把燃烧碎屑吸成火团。
- 归属：斑块与实体记 Owner 与因果链；跨机结果在因果链里同时显示各台机器（FGR-EMG-180），伤害归因按链平分（FGR-EMG-182）。

**FGR-EMG-131 信号离开后的留存**
- 信号离开机器后，该机器在信号期间留下的物质、热量、残骸、相态都留在世界里，按各自规则继续演化；已发射载荷按发射时程序走完（FGR-EMG-037）。热量留在机体沿用 FGR-SIG-033。

**FGR-EMG-132 信号中继转发（事件转发）**
- 装有信号中继（`struct_relay`）的机器，其程序里所有 `role = trigger` 且端口属于白名单（`evt.hit`、`evt.kill`、`evt.marked`、`evt.hurt`、`evt.bounce`、`evt.pierce`）的读端，自动获得 `sqd.relay` 作用域：中继范围 `emg.relay.range`（12 米）内友机的这些事件也算本机事件来触发。固件不需要、也不能自行声明 `sqd.relay`；它只由 `struct_relay` 的 scope 声明提供（FG19A §2.2 同此口径）。程序树预览在这些指令上标“可被中继转发”。例：装中继的 B 车带“命中时放电”，A 车每次命中，B 车也放电。
- 只转发事件，不转发程序：每台机器只运行自己装配的程序，“只有一道信号”不变（FG01 §3.1）。
- 限流：每台中继机器每秒最多转发触发 `emg.relay.per_second`（4）次；转发触发的热量记在执行方。
- 这是玩家显式装配的程序行为，界面显示“由中继转发：A 车命中”（FGR-BASE-020）。

**FGR-EMG-133 信号脉冲 `evt.ping`**
- 写 `evt.ping` 的固件在指定事件时广播一个频道（0～3）的脉冲；中继范围内读该频道的友机程序被触发。用于编排“一台标记、三台齐射”这类跨机连招，全部由玩家装配决定。

- 底盘特性只做两件事：设置 `chs.*` 状态端口；在其 `appliesTo` 范围内改物质层 / 载体的结算。固件想“随底盘变化”只能读 `chs.*` 状态端口（例：“离地时……”），读不到底盘 ID——因此悬浮与飞行共享“离地”读法，新底盘不需要改任何固件。

**FGR-EMG-142 预留底盘的接口**
- 越野多足、飞行、船体落地时只需新增 `fg.TbChassisTrait` 一行与 `fg.TbEntityProfile` 默认值，不改规则表、不改固件声明；零死对与模糊测试器自动把新底盘纳入用例（FGR-EMG-220）。

### 7.4 地形与永久改变（通道 11）

现实：地形不可破坏；战斗内核看不到地形，只有障碍圆、寻路镜像与铸造炉渣区（`Sim/Combat/CombatData.cs:88,168-171`）；唯一改地形的现有写法是废墟拆完变空地（`GL/Campaign/Economy/ProductionService.cs:3078` 调 `HomeGridMap.SetTerrain`，`HomeGridMap.cs:444`）；家园格网有差异存档（底稿 03 §8）。因此分两段做。

**FGR-EMG-150 阶段 2：场地物长期留存与残骸掩体**
- 固态斑块（冰、玻化层、固化胶块、冷渣）与残骸在野外按各自寿命存在；在家园与前哨长期留存、进存档，直到被摧毁、融化、回收或被玩家工作单清除。
- 突袭打过的家园防线前沿会留下残骸墙、冷渣堆、固化胶块，下一次突袭仍在（“家园防线也吃这一套”）。它们挡弹、减速、可导电、可点燃，按第 5、6 节规则参与；物质对炮塔在内核结算、对建筑经聚合脏列表结算（FGR-EMG-083），不复用跳过炮塔 / 建筑的中立区域分支（ADR-EMG-001 第 7 节第 17 条）。
- 存档方式（ADR-EMG-001 ⑦、第 7 节第 9 条）：优先随该地点的内核快照进存档，不另开战役存档域；前提是家园 / 前哨地点内核全程常驻、不被销毁重建，阶段 2 开工时核实（ADR T1）；若会重建，改走 FGR-EMG-212 的战役存档新增字段（缺省为空、不升 schema）。
- 数量上限：每个家园 / 前哨地点长期留存的固态斑块 ≤ `emg.persist.patch_max`（128），残骸 ≤ `emg.wreck.capacity`；满了时最早的崩解为碎屑（可见、计数）。

**FGR-EMG-151 阶段 4：冻结桥**
- 冰斑块覆盖在“水面”（`ter.water`）上时，地面单位可以通行；内核寻路镜像把冰覆盖区标为可通行，融化后恢复。同时最多 `emg.terrain.bridge_max`（8）座。
- 冰融化时桥上的单位：被推到最近的陆地，不阵亡（防软锁，B11）；飞行与悬浮不受影响。
- 依赖水面地形（FG18 海与空、DEBT-FG10BOSS01-02 湖面地形）；水面未落地前本条不开工，**随水面 Story（FG18-SEA-01）交付**：EMG4-TER-01 届时只交付熔坑，冻结桥登记 DEBT-EMG4TER01-01（条件性）承接到 FG18-SEA-01，FGJ-EMG-4 的冻结桥一步同时移出。

**FGR-EMG-152 阶段 4：熔坑**
- 熔融金属或酸液在“可熔地面”（生成规则标记的工业铁板、混凝土楼板，`ter.ground`）上累积到阈值 → 熔坑：一块不可通行的小区域，寻路镜像更新，家园上不能建造。每地点 ≤ `emg.terrain.pit_max`（8）个。
- 熔坑可以被工作单填平（耗材料，B03 可取消）。

**FGR-EMG-153 阶段 4：战痕写入家园格网**
- 家园与前哨（`HomeGridMap` 覆盖的表面）上，长时间燃烧、玻化、冻结、熔坑等结果按格写入地面材质（焦土 / 玻化地面 / 冻土 / 熔坑），走现有差异存档；下一场战斗载入该地点时，这些地面材质转为长期斑块或寻路标记。
- 写入只在战斗内核发出的“地面标记”玩法事件上进行（受 64 / 步预算，顺延不丢），热更层 O(本次标记数)，不按帧扫描。每地点 ≤ `emg.terrain.marks_max`（64）处，超出时合并相邻标记。
- 远征区域是否同样由 `HomeGridMap` 承载：待核实；不承载的区域只做阶段 2 的长期留存。
- 新地面材质字节值必须登记进地形层的取值表，旧档读到未登记值按“原生成值”处理并记 Error（防坏档）。

**FGR-EMG-154 清除与保底**
- 玩家可以对家园 / 前哨的残骸、固态斑块、熔坑、战痕下达清除工作单（沿用工作单与优先级，FG04）；清除前可取消，取消全额返还预留材料（B03）。
- 软锁保底：任何永久改变若堵死家园与核心、仓库、出入口之间唯一通路，系统发警告通知并在地图上标出位置与清除办法（B06、B11）。

### 7.5 敌方与劫持（通道 12）

**FGR-EMG-160 敌人用同一套程序**

**FGR-EMG-161 免疫与弱点按属性 / 读端表达**
- “免疫酸”“只怕一类固件”这类设计一律写成抗性列（FGR-EMG-103）或“对某端口无读取”。FG13-END-05（FG11 FGR-END-022 阶段二）四类护盾节点是封闭枚举，弱点按端口表达如下（名称沿用旧固件家族列 `em` / `fluid` / `fuse` / `limiter`，只作命名来源，判定不看固件 ID 或家族）：
  | 护盾节点 | 只被这些端口破坏 | 玩家怎么做 |
  |---|---|---|
  | 电磁 | `en.elec`、`en.mag`、`fld.*` | 电荷注入、磁化或让场作用于节点 |
  | 流体 | `mat.*`（物质斑块覆盖节点或沾染节点） | 把物质排放到节点上 |
  | 引信 | `grm.trig` 放出的子载荷（1 代及以上）命中 | 用触发器把子弹药打到节点上 |
  | 限制器 | `en.heat`、`phs.overheat` | 持续加热到节点积热满 |
  - 节点对其余端口无读取（受伤不扣节点护盾）。第 4 步 FG11 FGR-END-022 与 FG13-END-05 卡片直接引用本表，不再“开工时定”。

**FGR-EMG-162 回收敌方固件**

**FGR-EMG-163 信号劫持（取代“感染”）**
- 写 `hij.hack` 的固件命中时给目标加入侵度（`phs.hack`）。目标在入侵度 ≥ 阈值期间阵亡 → 不留残骸，原地以 `emg.hijack.hp_ratio`（30%）耐久重启为己方，持续 `emg.hijack.seconds`（30 秒），带着它的原生程序为玩家作战，期满自毁并留下残骸。

- 题材口径：玩家是信号，劫持 = 在敌机控制器里写入一段重启程序，与“玩家是信号”的设定一致；代码内部状态位 `Infected`（`Sim/SimTypes.cs:315-316`）不改名、不复用。

**FGR-EMG-164 镜像复制按继承规则（FG11-FAC-01）**
- 镜像体复制玩家在其附近最近一次发动的核心固件，得到“本地版本”（`FG09:246`）。按本文：复制品是 1 代程序，容量 `C(1)`，占镜像体自身的刷写带宽；复制品不能再被复制（代际），复制触发器时其子载荷按容量截断。

**FGR-EMG-165 夺控、槽位封锁、劫持共用事件与术语**

### 7.6 时间节拍（通道 13，阶段 3）

**FGR-EMG-170 全局节拍**
- 内核时钟每 `emg.tempo.beat`（0.5 秒）发一次 `evt.beat`，按内核时间计，与帧率、倍速、是否被观察无关（内核固定 60 Hz 步，`CombatLogic.cs:11-19`）。

**FGR-EMG-171 周期指令与相位**
- 读 `tmp.beat` 的指令声明周期（拍数 `amount`）与相位（`param2`）；在“拍序号 % 周期 = 相位”的拍上执行。现有时钟脉冲（`fw_clock`，`RhythmModule`）改用此读法（FG19A 定）。
- 相位默认 = 指令在程序里的序号 % 周期，玩家调槽位顺序即可调相位。

**FGR-EMG-172 相位对齐（齐射）**
- 同一台机器、或同一中继组内，同一拍有 ≥ 2 条节拍指令执行时，本拍对这些机器置 `tmp.sync`；读 `tmp.sync` 的指令在本拍执行（例：对齐时把本拍各机器的触发器子载荷同时放出 = 齐射）。
- 每台机器每拍 `tmp.sync` 最多触发一次。

## 8. 可读性

**FGR-EMG-180 因果链记录（对接 FGR-BASE-020）**
- 每次出手、每次世界源排放分配一个因果链 ID；其后代事件、载荷、斑块、实体、规则结算都继承它（FGR-EMG-061）。合并的斑块记“合并自链 X、Y”。
- 内核每地点保留最近 `emg.chain.ring`（256）条链记录（环形缓冲，只含值类型）：链 ID、父链、节点种类（出手 / 触发 / 规则 / 相变 / 转发）、端口或规则 `StableKey`、源单位、位置、时刻、链深。
- 热更层只在玩家打开面板或悬停时读取（O(环长)），不按帧读。链记录不进存档（与“反应日志不存档”一致，`FG02:258`）；可靠计数照常进存档（FGR-EMG-067）。

## 10. 护栏

### 10.1 性能

**FGR-EMG-200 帧率口径（120 帧，待用户确认）**
- 用户口径：开发标准最低 120 帧（8.33 毫秒 / 帧）。FG15 FGR-SYS-042（`FG15:106-110`）仍写“推荐配置 60 帧：热更层 ≤ 4 毫秒、内核（物流 + 战斗）≤ 6 毫秒”。两者冲突，**待用户确认是否把 FG15 改为 120 帧**；本文一律按 120 帧做预算。
- 口径：**全部已载入地点之和**。每个世界步推进全部已载入地点的内核（家园、裂城、铸造前哨、各室内场地各跑一次 `SimStep`，与镜头无关，ADR-EMG-001 事实 1.20），家园长期留存的斑块与残骸会和远征地点的满载战斗同帧运行；下列“内核”一律指一个世界步里所有地点内核耗时之和，上限不得按“是否被观察”区分（FGR-BASE-021）。逐地点分摊与世界级总上限（`emg.patch.world_capacity`、`emg.bus.world_per_step`，FGR-EMG-202、第 18 节）见 ADR-EMG-001 ⑬。
- 本文预算（建议值，ADR-EMG-001 用性能场景实测后定稿）：
  - 涌现新增的内核开销（程序树、事件总线、斑块、传导、相变、残骸、场对实体）在“涌现满载场景”（FGR-EMG-203）下 ≤ 1.0 毫秒 / 世界步（p99，全部地点之和）；
  - 战斗内核（全部地点之和）：1x（最坏 1 步 / 帧）≤ 3.0 毫秒 / 帧；3x（最坏 2 步 / 帧）每世界步 ≤ 1.5 毫秒，即 ≤ 3.0 毫秒 / 帧（p99，ADR-EMG-001 第 7 节第 5 条），保证内核步落在的那一帧仍在 8.33 毫秒内；3x 是否同守 120 帧待用户确认（按推荐默认执行（2026-10-28），待用户确认：3x 也守 120 帧、每世界步 ≤ 1.5 毫秒，热更层整体预算 2.0 毫秒 / 帧（其中涌现相关仍 ≤ 0.1 毫秒，见下）；EMG1-BUS-01 的 `FgEmgBusSelfCheck` J 段按此判单步耗时）；
  - 内核合计（物流 + 战斗）≤ 4.3 毫秒 / 帧（战斗 3.0 + 物流 1.3，ADR-EMG-001 ⑬）；
  - 热更层涌现相关开销 ≤ 0.1 毫秒 / 帧，且与敌人、弹体、斑块数量无关；
  - 每帧托管堆分配接近 0（沿用 FGR-SYS-042）。
- 内核现为单线程 Burst `IJob`（`Sim/Combat/CombatKernel.cs:1186-1187`）；斑块节拍与传导是否拆成并行作业由 ADR-EMG-001 决定，前提是结果与线程数无关。

**FGR-EMG-201 复杂度红线**
- 逐单位、逐弹体、逐斑块、逐残骸的 O(N) 逻辑只能在 `Sim/`（Burst）。
- 热更层只做：装配变化时编译程序（O(程序长度)）；每步读脏列表（O(本步变化的规则数)）；按需读因果链环（玩家操作时）；打开数据包时算 N（FGR-EMG-191）；处理地面标记与劫持等玩法事件（受 64 / 步）。

## 15. 负向与边界矩阵

| 场景 | 期望行为 |
|---|---|
| 程序 5 条以上（混合固件展开后超过容量） | 超出的指令标“溢出”，不编译、不计热量，预览说明 |
| 触发器在 2 代节点里 | 占位但不生成子节点，预览“代际已满” |
| 程序只有触发器，没有下游指令 | 子载荷为该载体的基础子形态，继承上游修饰 |
| 同一节点两条重复判定键完全相同的修饰 / 排放 | 第二条无效，预览“重复无效”；键不同（生效事件、面过滤、延迟不同）的各自结算（FGR-EMG-017） |
| 同一台机器装第二件同名部件 | 蓝图校验拒绝，原因“同名部件每台机器限装 1 件”（FGR-EMG-193） |
| 接入口不在任何源→汇路径上 | 接入固件整体不进程序（沿用 `BlueprintCircuitCompiler.cs:152-155`） |
| 接入中途信号离开 | 已发射载荷按原程序走完；无人机剥离核心指令；武器表重编译 |
| 无人机飞出刷写范围 | 末尾指令暂停，回到范围内恢复；悬停可见 |
| 一步内事件超过预算 | 顺延到下一步，不丢；存档时队列一起保存 |
| 链深到 3 | 不再生成后代，因果链末端写“链深已达上限” |
| 弹体池满时触发器放子载荷 | 生成请求顺延，池有空位再生成 |
| 斑块容量满 | 先合并，再最早同层提前到期；计数可见 |
| 两条规则同时满足 | 只结算优先级最小的一条，其余下一节拍 |
| 己方站进己方导电水洼 | 照样被电（中立），AI 教义默认避开，玩家接入的机器不避；发友伤通知 |

| 被劫持敌机劫持期满 / 劫持者阵亡 | 定时自毁留残骸；劫持者阵亡时同样立即自毁 |

| 残骸堆满家园出入口 | 警告并标位置；清除工作单可解；残骸不改寻路网格，单位可减速穿过 |

1. 第一次看到子弹药带着机器自己的固件炸开时，玩家能不能说出“是我插进去的引信把它的程序装进了子弹药”？
2. 一条连锁结束后，玩家能不能不看说明、只看因果链说清“为什么会这样”？——要的是“意外，但看得懂为什么”。
3. 拿到一条新固件或新部件时，玩家是不是马上想去试它能和手上的东西碰出什么？三选一的“N 种新交互”有没有让选择更有意思，而不是变成“选 N 最大的那个”？
4. 换一台底盘，同一套固件的玩法是不是真的变了？
5. 友伤是“有趣的代价”还是“烦人的惩罚”？AI 避险教义够不够？
6. 默认缩放下，能不能一眼分清油、水、酸、冰、明火、烟这些斑块？
