## 1. 玩家目的

- 故事**不打断游戏**：靠日志、截获、环境和核心自己的备忘来讲。
- 前两幕埋下的伏笔，在信标点亮那一刻**全部接上**。
- 终战是对之前所有系统的**总考**：家园自动化、跨阵营构筑、信号接入。
- 结局让玩家记住**自己的机器**。

## 3. 叙事投放

**FGR-NAR-001 投放方式**

| 方式 | 说明 |
|---|---|
| 核心备忘 | 归还核心在剧情节点自动写下的日志，是玩家自己的"声音" |
| 数据终端 | 阵营领地和遗迹里的文字日志 |
| 监听截获 | 监听站破译的通讯，以"无线电杂音 + 文字"呈现 |
| 遗迹纪念物 | 人类遗产的描述文字 |
| 环境叙事 | 关卡里的场景细节（炮口朝天的阵地、贴满天空扫描记录的墙） |
| 结局演出 | 游戏内镜头 + 文字 |

- 不做对话树（沿用 GDD 的非目标）。v1 不需要配音，配音是可选项（P2）。

**FGR-NAR-002 不打断游戏**
- 日志、截获、备忘都以通知形式出现，玩家有空时再读。
- 只有揭示和结局这两段演出会接管画面。两段都可以跳过（首次观看时，跳过需要确认），之后可以在资料库里重看。

**FGR-NAR-003 资料库**
- 图鉴里的"资料库"页收录所有已获得的文本，可以按幕和来源筛选，未读的有标记。
- "剧情回顾"按时间顺序列出已经发生的剧情节点。

**FGR-NAR-004 文风**
- 克制、冷静，带人情味的机器视角。
- 揭示之前，舰队的消息**温暖而鼓舞人心**；越接近揭示，越显得程式化。前后反差就是最大的情绪冲击。

### 3.1 剧情节点

**FGR-NAR-010 节点表**

| 节点 | 触发 | 方式 | 内容 |
|---|---|---|---|
| 苏醒 | 新游戏 | 演出（简短） | 核心启动；舰队简报："归还核心，欢迎回家。恢复电力，点亮信标。" |

| 巨构蓝图 | 第三幕开始 | 舰队消息 | 舰队发来巨构蓝图，语气热情 |

- 核心备忘还会在归还面积达到各个里程碑时各写一条（FGR-ENV-042）。
- 核心的疑虑**不会强迫玩家做选择**，剧情照常推进。

> 实现注记（FG11-E2E-01，2026-11-18，DEBT-FG5RND05-04）：第二幕起监听站按顺序各截获一次三条舰队信号片段（`fg.TbIntelFragment`，文本键 `intel.fragment.act2.*`，收进资料库“监听截获”）：问候（“……这里是舰队。向全体地表单元致以问候……你们做得很好……”）→ 返航窗口（“……归还序列第七批次，信标状态良好……返航前须完成清点……”）→ 清点（“……地表自治单元清点进度百分之六十四……清点完成之前，请保持信标静默……”）。语气由温暖转向程式化（FGR-NAR-004），不提前写出“净化协议”——那句留给击败余烬主机的破译片段。

> 实现注记（FG13-END-02 修复轮，2026-11-19）：第二幕两条“净化”伏笔落地为资料库剧情节点——“净化即救赎”（`node.purify_salvation`，监听截获，触发 = 第一次进入沉淀湖（澄净领地），与图鉴“进入领地”同一时机）、“净化的意义”（`node.purify_meaning`，核心备忘，触发 = 击败洗礼塔）。揭示演出（第 5 章）按本表逐行回应揭示之前的全部节点：苏醒、天上的眼睛、朝天的炮口、第一个片段、它在等什么、净化即救赎、信号幽灵（第一次夺控用的是人类根权限，呼应第 7 章阶段三）、净化的意义、破译、巨构蓝图与阶段消息（回信越来越短），另加监听截获的“清点”片段；生成前校验与 FgRevealSelfCheck 都按“资料库每个剧情节点都有回应”核。

## 4. 返航工程

**FGR-END-001 巨构阶段**
- 五个阶段：地基锚定 → 能源矩阵 → 信号天线阵 → 轨道校准 → 信标点火。
- 每个阶段是一片大型工地（**初值：12×12 格**），带输入端口，要用传送带和管线持续送入指定物资，并且持续供电一段时间。例如一个阶段需要：巨构构件 400、冷却液 2,000、持续供电 500 达 2 个游戏小时（**初值**）。
- 工地面板显示每种物资的进度，以及按当前供给速度预计的完成时间。

**FGR-END-002 防守工地**
- 每完成一个阶段，触发一次更高等级的突袭（FGR-DEF-020）。
- 工地受损时暂停推进，**已完成的进度不会倒退**。

## 5. 揭示

**FGR-END-010 揭示**
- 触发：玩家在信标点火后确认启动（沿用现有的二次确认面板）。
- 演出：镜头转向天空，舰队信号接入，文字："归还核心任务完成。净化协议启动。"之前所有伏笔在这里接上。
- 舰队第一次报出完整的名字：方舟舰队；执行清洗的无人舰群"白潮"；先遣旗舰"归乡号"（命名表见设计案 17.1）。
- 状态变化：HUD 出现"轨道威胁"指示；任务更新；音乐切换。
- 演出前后各自动存档一次。

> 实现注记（FG13-END-02，2026-11-19）：按推荐默认执行，待用户确认——“确认启动”= 五个巨构阶段完工（信标点火）后，玩家选中返航工地点“点亮信标…”，在信标确认面板（Demo 信标二次确认面板同一份界面，“点亮信标”模式）点“确认点亮”；不自动播放、没有倒计时，只有主线任务“返航工程”提示。演出走叙事框架（资料库条目 `node.reveal`，镜头 sky：镜头抬起转向天空），开始前自动存档（存档里记着待播：演出中退出，读档后重新播放），演出结束（看完或跳过）时状态落定：事件账本 `endgame_revealed`、顶栏“轨道威胁”指示、主线任务“返航工程”完成 → “守住家园”出现、音乐切到轨道威胁层，然后再自动存档一次。伏笔接上：苏醒的简报、天上的眼睛、朝天的炮口、第一个片段、它在等什么、第二幕截获的“清点”、破译各有一行字幕回应（`fgdata_narrative.REVEAL_CALLBACKS`）。

## 6. 三段终战

**FGR-END-020 第一段：清洗波次（家园）**
- 2 个游戏日内来 3 波。无人舰群分批登陆；轨道打击周期性清空一片区域，落点提前 30 秒标出。
- 目标：守住家园。这一段是家园自动化的总考。
- 每一波开始前自动存档。

> 实现注记（FG13-END-03，2026-11-19）：按推荐默认执行，待用户确认——揭示状态落定后清洗开始（PurgeWaveService）：第 1 / 2 / 3 波最早在开始后 0.05 / 0.6 / 1.15 个游戏日、并且上一波打完（全歼或撤退）至少 120 游戏秒才交给突袭导演（触发 purge，白潮，2 / 3 / 4 级，不受最短间隔、建造者难度照样来）；之后走正式突袭流程：筹备 0.25 日 → 预警（预警时自动存档 = “每一波开始前自动存档”，与突袭前读档点同一钩子）→ 从核心外 56 格的轨道登陆点行进 → 攻城。每波编成里至少一个登陆舱，攻城队伍里的舱落地后投放同一队伍的清洗无人机（“无人舰群分批登陆”）。上一波拖着没打完，下一波顺延（不叠波）。轨道打击：开始后 90 游戏秒起每 240 秒一次，落点是离归还核心至少 14 米的一座家园建筑（没有就落在核心外 14 米），落点提前 30 秒在地图与地面画圈和倒计时，敌我单位都受伤、建筑受最大耐久 40%；撑过第 3 波后停止。撑过 3 波 = 事件账本 endgame_purge_cleared（主线“守住家园”完成）。核心被毁时失败页写明“读取最近自动存档后从第 n/3 波重试”，读回后已撑过的波次不再来、奖励只一次。游戏中途改成建造者难度也不取消清洗计划；计划被导演取消（派不出队伍等）或没建出时，这一波不算打完，隔 120 游戏秒重新发动。轨道打击落点只选已开工的建筑（规划虚影不算）；撑过第 3 波时还在倒计时的那一次一并撤掉。数值是初值（FG15-BAL-01 统一调参）。

**FGR-END-021 第二段：登陆场（远征）**
- 白潮滩头出现在区域规划层预留的地方（FGR-GEN-041），和家园在同一张地图上，可以一路开过去，也可以投送（前提是先打掉护卫无人机的防空）。锚点和旗舰降落区是手工锚点。目标：摧毁 3 个轨道锚点和登陆信标，切断持续投送。
- 屏蔽塔会限制接入，要先拔掉。
- 这一段期间，家园只会遭受 1 级骚扰（由自动化防守），避免双线同时失败。

> 实现注记（FG13-END-04，2026-11-19）：按推荐默认执行，待用户确认——撑过清洗波次（endgame_purge_cleared）后的下一步，舰队在预留区的着陆点（规划层锚点 white_tide_landing）着陆：手工模板 white_tide_beachhead（fg.TbAnchorTemplatePoint）的旗舰降落区、3 个轨道锚点、登陆信标、2 座屏蔽塔、4 台护卫无人机、1 台净化步行机按锚点原点与朝向落到星球上（落在悬崖 / 水面的就近挪到可走格），登陆信标周围是灭活焦土；着陆后自动存档一次（BeachheadLanded），主线“切断投送”出现，地图标出滩头、旗舰降落区与还立着的目标。“持续投送”= 还有目标立着时每 45 秒 × 4 ÷ 存活目标数落一个登陆舱（落在信标旁，信标没了落在剩下的锚点旁），滩头投送来的单位活着满 12 台时这一次跳过；4 个目标全毁 = 切断投送（事件账本 endgame_beachhead_cleared，FG13-END-05 首领战从这里开始）。“护卫无人机的防空”= 滩头存活的护卫无人机实时中点 60 格内投送舱不能落。“1 级骚扰”= 着陆到切断投送之间突袭导演每个计划的等级不超过 1（着陆时还没预警的计划一并降级重编；已经预警的照原样来）。登陆场中核心被毁按失败规则：读最近自动存档接着打，存档时已摧毁的目标保留。数值是初值（FG15-BAL-01 统一调参）。

**FGR-END-022 第三段：最终 Boss·先遣旗舰"归乡号"**
- **阶段一·轨道轰炸**：旗舰悬在高空，无法攻击。它标记区域进行延时轰炸。场上有 4 座校准信标引导轰炸，每摧毁一座，轰炸就更不准；全部摧毁后，旗舰降下。
- **阶段二·登陆要塞**：旗舰降下地面要塞，有多个炮位和护盾节点。**每个护盾节点只怕一族端口**（按 FG19 FGR-EMG-161 的四行表：电磁 = `en.elec`、`en.mag`、`fld.*`；流体 = `mat.*`；引信 = `grm.trig` 放出的子载荷命中；限制器 = `en.heat`、`phs.overheat`；其余端口无效）。这一阶段检验的是你跨阵营构筑的广度，是跨阵营编译（P3）的最终兑现。
- **阶段三·根权限压制**：旗舰动用人类根权限，每 20 秒夺取一台最靠近"压制中继"的你的机器（场上共 3 座中继）。被夺取的机器转而攻击你。夺取走与信号幽灵同一套夺控状态机与事件（FG19 FGR-EMG-165）。
  - 你可以对被夺取的机器**反向接入**夺回来。这和信号幽灵（FG10）是同一个机制，玩家之前学会的技巧在这里得到回报。
  - 被夺取的机器被击倒后进入**瘫痪**，不会阵亡，阶段结束后恢复。
  - **永远不会夺取玩家当前所在的那台机器。**
  - 摧毁全部 3 座中继后，旗舰核心暴露，进入最后的爆发窗口。
- 这是**脚本化的首领机制**，只在这场战斗中出现，不属于常态 AI 行为。
- 每个阶段开始时自动存档；失败后从该阶段开始重试。
- **FG13-END-05 已落地（2026-11-19）**：`Campaign/Endgame/FlagshipService.cs`（唯一写入口，进度在 `CampaignProgressState.Flagship`）。切断投送后下一步开战；编成 = fg.TbEnemyEncounter 区域 `white_tide_flagship`（base 4 座校准信标 / boss 要塞 + 2 炮位 + 四类护盾节点 / boss_wave 3 座压制中继），点位在滩头模板 `white_tide_beachhead`。阶段一每 `flagship.bomb_interval_seconds` 用内核轨道打击轰炸竞技场里离降落区最近的机器，落点散布 = base + 已毁信标数 × per_beacon；阶段二节点 = 内核端口闸门（FG19 FGR-EMG-161，敌人表列 `flGate` / `flGateHp`，快照格式 26），要塞在节点 / 中继还在时不可伤；阶段三每 20 秒经 `SignalSeizeService.Seize`（来源 = 根权限，直到阶段结束）夺取离存活中继最近的机器，不夺取玩家接入 / 接入过渡中的那台，**也不夺取家园里最后一台可用的机器**（按推荐默认执行（2026-11-19），待用户确认：否则只有 1 台机器时夺取直接变成全灭重试的死循环）；中继全毁 → 夺取的机器归还、核心暴露，摧毁核心写事件账本 `endgame_flagship_defeated`。每阶段开始自动存档（`SaveReason.FlagshipPhase`）；竞技场（`flagship.arena_radius` 米）里出现过可用机器后一台都没了（阵亡、被夺取或离开）= 全灭，从本阶段开始重试（按推荐默认执行（2026-11-19），待用户确认：离开竞技场也算）。自检 `FgFlagshipSelfCheck`。

## 7. 结局

**FGR-END-030 结局演出**
- 先遣旗舰撤退，先遣舰队被击退。镜头转向天空：主舰队仍停在轨道上。
- 核心写下最后一条备忘：人类仍在沉睡，净化协议没有撤销，它选择继续守着这片土地，好让人类将来醒来时，还有东西可以归还。

**FGR-END-031 结算与纪念**
- 沿用并扩展 Demo 的机器故事：
  - 幸存机器列表：名字、编号、经历。
  - 纪念墙：所有阵亡机器（数据来自黑匣子陈列馆，FG05）。
  - 统计：归还面积、游戏天数、发现的反应、熔合配方数、击退的突袭次数。
- 结语根据统计略有变化（只是文字差异，不是分支结局）。例如：归还面积达到最高里程碑有专属的一句；提到最老的那台机器；提到被接入最多的那台机器。

**FGR-END-032 之后**
- 结算后让玩家选择：继续（进入后日谈沙盒，FG12）或返回主菜单。
- 解锁对应成就（FG15）。
- **FG13-END-06 已落地（2026-11-19）**：`Campaign/Endgame/EndingService.cs`（唯一写入口）+ 结算面板 `UI/Kit/EndingSettlementPanelUIToolkit.cs`（`EndingSettlement.uxml`）。先遣旗舰被击退（`FlagshipService.DefeatedEvent`）→ 投放资料库条目 `node.ending`（演出，镜头 sky；叙事框架播放：开始前自动存档、可跳过（首次确认）、资料库与结算里可重看）→ 收进资料库那一步写事件账本 `endgame_ending` 并**先自动存档**（`SaveReason.EndingComplete`）→ 打开结算（世界暂停；结算期间任何存档——自动档、暂停菜单“保存并返回主菜单”——一律被拒，`SaveOutcome.SettlementOpen`）。统计只聚合既有数据源：归还面积 = `PurificationService.ReturnedArea`；游戏天数 = 统一时钟游戏日；发现的反应 = 组合图鉴已解锁具名交互数（FG19 口径，跨存档 D-17）；熔合配方 = 本档配方书已发现数；击退的突袭 = 结束原因为被全歼 / 抵达后撤退的突袭累计（`RaidDirectorState.RepelledCount`，旧档按突袭历史补下限）。幸存机器按编号；纪念墙 = 黑匣子陈列馆同一份名单；结语依次为面积与天数、归还十万格专属一句（`PurificationService.EndingLineKey`）、最老的那台（幸存机器里编号最小的；全部阵亡换句）、被接入最多的那台（信号进入次数最多，阵亡换句）、纪念墙人数。继续 → `IsPostgame` = true（存档卡显示后日谈，后日谈玩法由 FG14-SBX-01 接上）、恢复暂停状态、自动存档（`SaveReason.PostgameStart`）；返回主菜单 → 不存档，下次读这份档回到结算重新选择。成就以事件账本 `endgame_ending` 为准，由 FG15-SYS-04 解锁。自检 `FgEndingSelfCheck`。

## 8. 正常游戏补全清单

- 演出可以跳过，也可以在资料库重看。
- 文本显示速度、字幕大小可以设置。
- 阅读日志时游戏不会自动暂停，但可以手动暂停。
- 资料库有未读标记；新文本进来时发通知。
- 如果玩家迟迟不建信标，游戏**没有时间压力**，只用任务提示引导，不设倒计时。
- 终战各段都有独立的失败界面，写明失败原因和重试点。

## 9. 负向与边界矩阵

| 场景 | 期望行为 |
|---|---|
| 揭示演出中退出游戏 | 读档后回到演出前的自动存档 |
| 清洗波次中核心被毁 | 从这一波开始前的自动存档重试 |
| 登陆场期间家园遭袭 | 只有 1 级骚扰，由自动化防守 |
| 根权限阶段玩家只有 1 台机器 | 不会夺取玩家所在的机器；中继照常可以摧毁 |
| 被夺取的机器被玩家击倒 | 瘫痪，阶段结束后恢复，不阵亡 |
| 巨构工地被摧毁 | 进度暂停，不倒退；重建后继续 |
| 玩家不建信标 | 游戏继续，没有倒计时 |
