# 《ProjectA》AI 实施里程碑

> 对应产品权威：`ProjectA_GDD.md`  
> 用途：供 AI 工作者逐项领取、实施、测试和交接  
> 原则：里程碑只规定顺序；`detailed/` 规定完整行为；一项任务交付一个玩家可验证的完整结果
> 逐项门禁：历史 M0～M10 覆盖矩阵已删除；本归档只记录当时的过程，不能据此开工或标 Done。

## 0. AI 执行契约

### 0.1 每次开始前必须读取

1. 仓库根目录 `AGENTS.md`；
2. `production/session-state/DIGEST.md`；
3. `production/PROGRESS.md` 的当前焦点；
4. `DesignDocs/README.md`；
5. 本文对应里程碑；
6. `ProjectA_GDD.md` 中对应系统章节；
7. 本文任务卡点名的 `detailed/` 文档、章节与需求 ID；
8. 所有任务都读 `detailed/00_Implementation_Completeness_Contract.md`；
9. 涉及代谢/ComposeEngine 时，再读 `最新改动需求/AUTHORITY_AND_CONFLICTS.md`。

不得把 `production/design` 中旧 Epic 的产品假设自动带入当前任务。

### 0.2 单任务输出格式

每个 AI 任务结束时必须留下：

- 改了什么；
- 哪些文件是规则真相；
- 如何验证，结果是什么；
- 未完成、被阻塞或主动未做的部分；
- 对后续任务新增的约束；
- 若更改玩法含义，同步更新权威文档。
- 需求—生产入口—代码—自动测试—玩家反馈覆盖矩阵；
- 所有降级项的 `DEBT-ID`、承接故事和最迟门禁。

### 0.3 通用完成定义

一项任务只有同时满足以下条件才可标记完成：

- 编译通过，无新增错误；
- 对应 EditMode/PlayMode/模拟测试通过；
- 点名需求 ID 100% 映射到生产入口、代码和逐语义自动断言；
- 没有复制第二份领域真相；
- 关键状态可在调试界面或日志中观察；
- 存档/读档影响已处理或明确证明无影响；
- 性能敏感逻辑没有在 HotFix 每帧 O(N) 扫描；
- 正式输入/命令/AI/场景入口至少有一条 E2E；深层直调只能补充，不能代替；
- 成功、失败、中断、恢复、暂停、死亡/卸载与资源不足已覆盖，或逐项证明不适用；
- 没有顺手加入无关扩展；“非目标”不得删除一个正常玩家流程必需的输入、反馈、空间、资源和恢复行为；
- 占位、假实现和只读字段不冒充完整功能；确需延后时有 DEBT-ID 和阻塞门禁；
- 文档与代码术语一致。

### 0.4 工作粒度和串行规则

- 一次只领取一个编号任务；
- 同一时刻只有一个任务处于 `in_progress`；
- 后置任务不得以“以后补”为由跳过前置验收；
- 已完成旧故事在新详细规格发布后仍需走 M4-R00 覆盖审计；历史 Done 不等于产品完整；
- 涉及同一核心文件的任务必须串行；
- 每完成一个里程碑，先做固定种子回归，再进入下一里程碑；
- 不默认提交 Git，不默认创建分支。

### 0.5 任务卡模板

后续新增任务必须包含：

- **目标**：一句可判断真假的结果；
- **依赖**：必须已经完成的编号；
- **主要范围**：预计涉及的模块/文件；
- **实施**：按顺序列出的动作；
- **交付物**：代码、资产、文档或测试；
- **验收**：可重复的具体检查；
- **非目标**：本任务禁止顺手做的无关事情；任何延后项必须写 DEBT-ID、承接故事和门禁；
- **需求 ID**：精确到详细规格的封闭集合；
- **正常旅程**：从正式入口到玩家结果；
- **负向矩阵**：失败、中断、死亡、暂停、断网、目标丢失、资源与存读档；
- **覆盖矩阵**：完成时逐 ID 映射代码、测试和反馈。

## M1：可转移控制权基座

**里程碑目标：** 模拟不再把索引 0 永久等同玩家；任意合法友军可在 AI 与玩家意图间安全切换。

**详细规格：** `detailed/02_Combat_Projection_And_Primitives.md` 的 `CP-REQ-002/004/090～092`；历史实现按 `detailed/05_M1_M4_Backfill_And_Acceptance.md` 的 `M1-R01～R03` 复验。M1 的 Done 只保留为历史状态，新规格缺口必须进入 M4-R00 队列。

### M1-01 玩家索引依赖审计

- **目标：** 得到所有“index 0 / PlayerIndex / player entity”假设的完整分类表。
- **依赖：** M0 完成。
- **主要范围：**
  - `Assets/GameScripts/Main/Sim/SimWorld.cs`
  - `Assets/GameScripts/Main/Sim/SimTypes.cs`
  - `Assets/GameScripts/Main/Sim/SimSnapshot.cs`
  - `Assets/GameScripts/Main/Sim/Jobs/`
  - `Assets/GameScripts/Main/Sim/SimRenderer.cs`
  - HotFix 的状态、UI、效果执行与战斗桥接代码
- **实施：**
  1. 搜索所有玩家索引常量与注释；
  2. 分类为模拟规则、输入、镜头、UI、渲染、存档、测试；
  3. 标出必须改为稳定实体 ID 的位置；
  4. 标出只为兼容旧逻辑可暂留的适配点。
- **交付物：** `DesignDocs/migration/Controlled_Unit_Audit.md`。
- **验收：** 审计表每项包含文件、符号、风险和迁移任务编号。
- **非目标：** 不在审计任务中修改运行逻辑。

### M1-02 控制身份数据模型

- **目标：** 建立唯一的 `ControlledUnitId` 与 `IntentSource` 规则真相。
- **依赖：** M1-01。
- **实施：**
  1. 定义稳定实体 ID，不依赖数组槽位；
  2. 定义 `AI`、`Player`、`Scripted` 意图来源；
  3. 在世界状态中保存当前控制实体；
  4. 提供只读查询和受控切换命令；
  5. 定义目标死亡、移除和世界重置行为。
- **验收：** 测试中把控制权从实体 A 切到实体 B 后，数组重排不改变目标。
- **非目标：** 不做镜头、UI 或视觉转场。

### M1-03 模拟作业去玩家特判

- **目标：** 转向、伤害、查询和生命周期作业使用实体状态/意图，而非索引 0。
- **依赖：** M1-02。
- **主要范围：** `JobSteering.cs`、`JobDamage.cs`、`JobQuery.cs` 及相关作业。
- **实施：**
  1. 将玩家输入编译为标准意图缓冲；
  2. AI 输入也写入同一形状的意图；
  3. 作业只读取最终意图，不识别“主角”；
  4. 保留必要的阵营和权限检查；
  5. 增加多友军并存回归测试。
- **验收：** 任一友军接收玩家意图时行为一致；未受控单位继续执行 AI；敌军不可被错误控制。
- **非目标：** 不优化寻路，不增加新攻击。

### M1-04 HotFix/模拟桥接 API

- **目标：** HotFix 只能通过单一桥接层查询和切换控制实体。
- **依赖：** M1-03。
- **主要范围：** `Battle/SimBridge.cs` 及控制服务。
- **实施：**
  1. 添加请求切换、查询当前控制、查询候选的 API；
  2. 验证阵营、存活、信号范围与冷却；
  3. 返回明确失败原因；
  4. 通过事件发布切换结果；
  5. 禁止其他 HotFix 文件直接访问模拟数组。
- **验收：** 非法目标不改变现状且有稳定错误码；合法切换只产生一次事件。
- **非目标：** 不实现信号网络，只使用可配置临时判定。

### M1-05 表现与 UI 查找迁移

- **目标：** 相机、HUD、血条和特效跟随当前受控实体。
- **依赖：** M1-04。
- **实施：**
  1. 移除 `SimRenderer` 的索引 0 跟随；
  2. HUD 从快照中的控制 ID 取数据；
  3. 切换时清理旧目标的玩家专属提示；
  4. 无控制实体时回退到战略锚点视角；
  5. 增加目标生成晚于 UI 的容错。
- **验收：** 连续切换 20 次，无血条串体、相机丢失、特效残留或空引用。
- **非目标：** 不制作最终意识转场美术。

### M1-06 死亡、断线与存档回归

- **目标：** 控制目标死亡、卸载或读档时控制状态确定且可恢复。
- **依赖：** M1-05。
- **实施：**
  1. 定义目标死亡后的意识回弹；
  2. 定义场景卸载与实体暂不可用；
  3. 保存稳定 ID 与回退锚点；
  4. 对旧存档提供安全默认值；
  5. 建立固定种子自动回归。
- **验收：** 死亡、暂停、存档、读档、重进场景后均只有一个控制实体或明确为无。
- **非目标：** 不加入正式死亡惩罚数值。

**M1 出口标准：** 在固定房间内，玩家能在三个真实友军间切换；离开的单位可靠恢复 AI；任何系统不再依赖索引 0 定义玩家。

## M2：同世界战略视角与意识传递竖切

**里程碑目标：** RTS 选择、暂停下令、近第三人称直控在同一场景和同一实体上闭环。

**详细规格：** 战斗、角度、发射点、基元阶段与 AI/玩家一致性执行 `detailed/02_Combat_Projection_And_Primitives.md` 全文；历史降级按 `detailed/05_M1_M4_Backfill_And_Acceptance.md` 的 `M2-R01～R06` 返工。特别禁止继续用常数伤害、假召唤、空交互、固定世界方向或调试直调冒充产品完成。

### M2-01 战略相机状态机

- **目标：** 建立战略、过渡、直控三个明确镜头状态。
- **依赖：** M1。
- **实施：**
  1. 定义每个状态的输入所有权；
  2. 实现平移、缩放、边界与目标聚焦；
  3. 过渡期间冻结冲突输入；
  4. 允许暂停时选择目标；
  5. 无效目标回退战略视角。
- **验收：** 镜头切换不传送实体、不重载场景、不产生双重输入。
- **非目标：** 不做电影级轨迹。

### M2-02 RTS 选择与基础命令

- **目标：** 能框选、追加选择、编组，并发出移动、攻击、守护和撤退命令。
- **依赖：** M2-01。
- **实施：**
  1. 选择只操作友方可指挥实体；
  2. 命令转换为模拟意图；
  3. 暂停状态允许排队；
  4. 显示路径与目标反馈；
  5. 直控时仍可看见已有编队命令。
- **验收：** 两组单位可执行不同命令，暂停下令后恢复顺序稳定。
- **非目标：** 不做复杂阵型和共享寻路。

### M2-03 直控移动与器官输入适配

- **目标：** 当前真实器官映射为直控动作，没有额外英雄技能表。
- **依赖：** M2-02。
- **实施：**
  1. 从个体装配读取可用动作；
  2. 建立移动、主器官、功能器官和交互输入；
  3. 失能器官禁用对应动作；
  4. 显示代谢、过载债和冷却；
  5. 退出时恢复 AI 教义。
- **验收：** 两个不同装配单位被接管时动作集不同且与实体一致。
- **非目标：** 不新增大量器官。

### M2-04 AI 接管可靠性

- **目标：** 玩家退出后的单位能延续合理意图，而不是站桩或自杀。
- **依赖：** M2-03。
- **实施：**
  1. 保存退出前所属编队和命令；
  2. 定义接管缓冲和安全位置；
  3. AI 禁止高风险过载；
  4. 处理玩家把单位留在不可达处；
  5. 调试显示当前教义与目标。
- **验收：** 在交战、搬运、撤退三种状态退出，单位均能继续合理行动。
- **非目标：** 不让 AI 自动决定战略路线。

### M2-05 手术窗口原型

- **目标：** 证明直控能在同数值下提供独特高价值，而非只提高 DPS。
- **依赖：** M2-04。
- **实施：**
  1. 给一个测试敌人设置身体和两个器官接点；
  2. RTS 可指定器官类别；
  3. 直控可瞄准具体接点；
  4. 低伤精准切离保留完整器官；
  5. 粗暴击杀只给生物质。
- **验收：** 外部测试者能描述“为什么这次值得接管”。
- **非目标：** 不做完整器官掉落池。

### M2-06 意识传递试玩门

- **目标：** 用一个 8–12 分钟固定场景验证双层操作。
- **依赖：** M2-05。
- **交付物：** 固定场景、测试脚本、观察表。
- **验收：** 至少 5 名测试者中，4 人能完成 RTS 下令、接管、手术和退出；若多数人只玩一层，停止进入 M3，先修交互。
- **非目标：** 不做正式美术。
- **当前状态（2026-09-14）：** 固定场景、测试脚本、观察表与 AI 自跑四步端到端已完成；外部 5 人测试未执行，
  但产品负责人已明确接受该替代证据并开放 M3。此决定只解除当时门禁，不免除 M4-GATE 的自动正式入口与最终体验复验。

### M2-07 战斗真相源统一

- **目标：** 同一具身体，玩家直控和 AI 驱动打出来的是**同一种东西**——同一件器官、同一套弹道参数、同一本冷却与过载债。
- **依赖：** M2-03。与 M2-06 的人测门禁并行，不受它阻塞（门禁只挡 M3-02+）。
- **背景：** M2-06 试玩反馈 #5「AI 与直控打法完全不同」。根因不是数值，是同一具身体挂着两套战斗真相源：
  玩家开它走器官（`OrganKernelActionTable` → 真弹体），松手后走 `BehaviorArchetype.AttackDamage` 的瞬时扣血。
  "接管一具身体"因此没有可比较的基准。
- **实施：**
  1. 职责切分：内核答"什么时候、朝谁开"（它才有空间哈希与阵营），热更层答"打出什么"（那是器官的事）；
  2. 内核逐帧抛 `MinionFireOpportunity`，**不带任何伤害/速度/半径数值**——带了分叉就会原地长回来；
  3. 两条路调用同一个释放函数 `OrganReleaseRunner.Release`，弹体仍由内核生成；
  4. 冷却/代谢/过载债共用一本账（`UnitVitalsRegistry`），不因为"换了谁在开"而重置；
  5. AI 守过载安全线（`AiStrainCeilingRatio`），玩家可以按到爆表换爆发——同数值下的真实差别。
- **验收：** 自检 [25] 逐字段比对"玩家打出来的"与"AI 打出来的"；只比"都能造成伤害"不算（旧路径也成立）。
- **非目标：** 不把器官下沉进内核（那是 M3-04）；AI 只用主武器槽，不替它决定何时用功能器官；自爆型不走器官路。
- **刻意保留的降级：** 没登记装配的身体（召唤物等）仍走行为原型数值。让它们跟着走器官路会彻底哑火，比原问题更严重。
- **当前状态（2026-09-14）：** 已实现并自检通过（511 断言全绿）。顺带修掉一个被它照出来的内核既有缺陷：
  弹体命中判定原先只判位移终点，贴脸射击与高速弹打小目标会整帧跳过判定窗口（隧穿），现改为对整条位移线段判定。

## M3：蓝图库、谱系与表型模板

### M3-01 现有 Carrier/基因系统映射

- **交付物：** `DesignDocs/migration/Lineage_Loadout_Mapping.md`。
- **验收：** 每个旧概念对应“保留、包装、迁移、废弃”之一。
- **非目标：** 不直接批量改代码。

### M3-02 蓝图库领域模型

### M3-03 谱系与表型模板模型

- **目标：** 一个谱系能保存多个有版本的表型模板。
- **依赖：** M3-02。
- **实施：**
  1. 定义谱系、模板、槽位、基因顺序和教义；
  2. 每次提交生成不可变模板版本；
  3. 校验蓝图所有权、槽位和兼容性；
  4. 计算生物质与代谢成本；
  5. 生成稳定装配签名。
- **验收：** 修改模板不会回写旧版本；相同配方生成相同签名。
- **非目标：** 不生成地图单位。

### M3-04 装配签名编译与缓存

- **目标：** 同模板个体复用 ComposeEngine 编译结果，同时保留个体状态。
- **依赖：** M3-03。
- **实施：**
  1. 以模板版本和临时移植生成签名；
  2. 通过适配层调用现有编译器；
  3. 缓存静态输出；
  4. 个体生命、伤势、过载债保持独立；
  5. 模板失效时安全淘汰缓存。
- **验收：** 100 个同模板单位只编译一次静态组合；改变一个个体的伤势不污染其他单位。
- **非目标：** 不重写 ComposeEngine。

### M3-05 萌生腔与新生传播

- **目标：** 模板提交只影响之后新生的对应表型。
- **依赖：** M3-04。
- **实施：**
  1. 建立萌生队列；
  2. 扣除真实资源；
  3. 绑定谱系、表型和模板版本；
  4. 生成实体并写入装配签名；
  5. 处理中途取消和萌生腔被毁。
- **验收：** 旧单位保持 V1，新单位表达 V2；其他表型不受影响。
- **非目标：** 不做最终孕育动画。

### M3-06 回巢改造

- **目标：** 旧单位只有返回联网萌生腔并支付成本后才更新模板。
- **依赖：** M3-05。
- **实施：**
  1. 校验位置、交战、携带物和网络；
  2. 锁定目标模板版本与成本；
  3. 暂时移出战斗；
  4. 完成后替换装配签名并保留允许保留的状态；
  5. 定义腔体中断和版本再次更新行为。
- **验收：** 断网、交战或资源不足时不能改造；中断不复制资源或器官。
- **非目标：** 不自动召回整支队。

### M3-07 野生器官与单体临时移植

- **目标：** 一件未归档器官能被搬运、拆解、解析或只装到一个身体。
- **依赖：** M3-06。
- **实施：**
  1. 建立物理战利品实体；
  2. 实现携带容量；
  3. 实现一个体细胞临时槽；
  4. 处理污染、死亡掉落和冲突；
  5. 返回萌生腔后提供三种处理。
- **验收：** 临时移植不会修改模板或其他单位；同一实物不能同时被解析和装备。
- **非目标：** 不做多临时槽和复杂手术动画。

### M3-08 模板编辑与传播 UI

- **目标：** 玩家明确知道改了什么、影响谁、花多少、谁仍是旧版。
- **依赖：** M3-07。
- **实施：**
  1. 展示器官/基因来源与用途；
  2. 展示模板预览和冲突；
  3. 展示新生数量、可改造数量与总成本；
  4. 在个体面板显示谱系、表型和版本；
  5. 允许筛选旧版个体并下达回巢命令。
- **验收：** 新玩家不会误以为一次提交瞬间改变整队。
- **非目标：** 不做复杂拖拽动画。

**M3 出口标准：** 玩家可从敌人切下器官，选择单体救急或带回解析；建立模板后只有新生/回巢单位获得能力；直控读取真实装配。

## M4：编队、教义与多线指挥

### M4-01 编队领域模型

- **目标：** 保存编队成员、命令、教义和临时脱队状态。

### M4-03 六种教义

## M8：固定地图完整竖切片

**里程碑目标：** 在不依赖 PCG 和大量内容的情况下，交付 20–30 分钟可反复试玩的完整游戏。

**历史集成规格：** M8 当时接通过 `00`～`03` 的玩家旅程；区域 Alpha 旧文档与覆盖矩阵均已删除。本段不构成当前产品的 PCG、内容或系统需求。

### M8-01 固定战役地图

- **目标：** 1 个玩家基础底盘、6 器官、8 基因、2 友方谱系、3 敌方谱系简版、6 适应模块，以及 1 个“Alpha 核心 + 8 名真实护群成员”的基线猎群。
- **依赖：** M8-01。
- **实施：** 每个器官/能力声明准确发射点、瞄准规则、弹道/场地形态、基元阶段、资源事务、敌我 AI 用法、反馈、保存与取消；每条谱系声明食源、繁殖/补员、职责和最终策略；Alpha 四套战术骨架只通过共享基元配方复杂化。
- **验收：** 至少两种本质不同的通关构筑；每项内容符合 GDD 17.3 和 `IC-REQ-001～014`；禁用任一必需依赖时给出明确降级/阻塞，不得静默改成常数、假召唤或空动作。

- **目标：** 按 GDD 14.3 在真实循环中教授直控、AI 接管、搬运、解析、模板和免疫回声。

- **验收：** 固定旅程机器人能完整走过教程并覆盖跳过、误操作、目标死亡、断网和读档；不读文档的测试者可独立进入第二幕，且能解释至少一次“我的命令为什么成功或失败”。

### M8-04 胜负、存档与恢复

- **目标：** 全部整局失败、软失败和胜利条件正确结算。
- **依赖：** M8-03。
- **实施：** 保存并恢复资源预留/携带/库存、编队命令与教义、直控快照、飞行物/持续场处理策略、敌方需要与巢状态、Alpha 配方/护群/食源、锚点和决策指纹；中断事务必须守恒。
- **验收：** 每个锚点、模板提交、跨腔、战斗中退出和 Alpha 多状态均可恢复；死亡、目标易主、重复读档、取消能力和版本迁移不复制资源、奖励或单位；不能刷随机结果。

### M8-05 性能基线

- **目标：** 在目标硬件、目标单位数和双镜头模式下达到帧时与内存预算。
- **依赖：** M8-04。
- **实施：** 测量模拟、渲染、UI、路径、编译缓存和存档峰值；先修架构热点。

- **非目标：** 不通过减少玩法正确性掩盖问题。

### M8-06 外部可玩性门禁

- **目标：** 验证核心不是“开发者自己才能理解”。
- **依赖：** M8-05。

  1. 至少 10 名目标玩家盲测；

## M9：受控 PCG 与重玩结构

**进入条件：** M8-06 达到门槛。未达到不得开始。

**历史规格：** M9 旧 PCG 文档已删除；本段只记录当时的范围，不构成当前 PCG 需求。

### M9-01 图章规范与标注工具

- **目标：** 手工腔室可声明入口、导航宽度、视线、环境、体型和首领兼容标签。
- **需求 ID：** `PCG-REQ-001～006`。
- **实施：** 用带版本的 RoomStamp 保存入口/出口、窄道、镜头、掩体、食源、巢、音响区、可访问性和阵营标签；导出前阻断几何、体型、资源和标签错误。
- **验收：** 现有固定地图腔室全部通过标注校验。
- **玩家结果：** 新种子中的门、掩体、资源、巢和镜头像同一套规则生成，而不是房间拼贴。

### M9-02 腔室图生成器

- **目标：** 生成 9–13 腔室，保证三锚、环路、捷径和双路线。
- **依赖：** M9-01。
- **需求 ID：** `PCG-REQ-010～016`。
- **实施：** 先生成逻辑图，再按入口、体型、生态、镜头和主线标签选图章；放置锚点、巢、食源、替代来源、教学点和返回边后执行全量旅程验证。
- **验收：** 10,000 个离线种子无不可达主线。
- **玩家结果：** 路线功能有真实差异；随机化改变机会，不改变必须学习的命令和投射规则。

### M9-03 空间拼装与导航烘焙

- **目标：** 标签兼容的图章确定性拼接，生成合法 RTS/直控导航。
- **依赖：** M9-02。
- **需求 ID：** `PCG-REQ-020～026`。
- **实施：** 同时校验接缝几何、碰撞、可走面、信号、镜头和音响；窄道压缩/恢复编队；动态封路触发重规划、替代目标和失败反馈。
- **验收：** 无重叠、断门、镜头越界和大体型卡死。
- **玩家结果：** 编队不会穿墙、传送或静默站桩；阻塞时看得到原因和替代方案。

### M9-04 生态投放器

- **目标：** 三谱系、资源、巢和迁徙路线按生态约束投放。
- **依赖：** M9-03。
- **需求 ID：** `PCG-REQ-030～036`。
- **实施：** 使用共享食源、库存、运输、巢、样本、信号和护群；每个主巢有主食源、运输线和替代来源；投放密度随空间/人口预算变化。
- **验收：** 基础通关工具有替代来源；没有单一随机掉落软锁。
- **玩家结果：** 断粮、伏击、诱离和绕行都是可理解、可反制的选择，不靠隐藏加血调难度。

### M9-05 种子验证与重生成

- **目标：** 自动执行 GDD 12.3 的全部检查，失败种子重生成并记录原因。
- **依赖：** M9-04。
- **需求 ID：** `PCG-REQ-040～045`。
- **实施：** 按版本、图结构、几何、导航、资源、生态、旅程、负向、性能和存档顺序验证；记录 RuleId、节点、图章、候选和重试次数。
- **验收：** 错误不会暴露给玩家；日志能定位失败图章或规则。
- **玩家结果：** 不可玩的随机结果不会进入会话；后备种子可用且不会无限重生成。

### M9-06 决策指纹与复现

- **目标：** 结算显示地图种子、主力模板、最大债务、债兽和胜利方式。
- **依赖：** M9-05。
- **需求 ID：** `PCG-REQ-040～045`。
- **实施：** 保存种子/版本、模板、器官、Alpha 配方、债务、食源、债兽部件顺序、命令和辅助设置；复制指纹提供离线复盘入口。
- **验收：** 输入同一种子可复现地图与初始投放，玩家决策仍能导向不同进化。
- **玩家结果：** 玩家能看懂“这局为什么不同”，并能安全复盘而不泄露调试字段。

## M10：美术、声音、可访问性与商店演示

**历史规格：** M10 旧 PCG/表现文档已删除；“不以预渲染、占位音画或宣传素材代替可玩功能”仅作为过程记录，当前门禁以《地球归还》验收矩阵为准。

### M10-01 模块化美术规范

- **目标：** 定义底盘比例、器官接口、材质、功能色、受损和敌方适应表现。
- **依赖：** M8 玩法稳定。
- **需求 ID：** `VIS-REQ-001～008`。
- **实施：** 为底盘/器官/接口建立稳定挂点、远近景、发射/命中/受损/切离/禁用/读档状态和低动态替代；美术不得决定伤害、方向或资源规则。
- **验收：** 新器官无需为每个底盘重新制作完整角色。
- **玩家结果：** 轮廓、状态和功能色在远景、近景、灰度和高密度战斗中都可读。

### M10-02 玩家与三敌方谱系正式视觉

- **目标：** 战略远景和直控近景均可读，轮廓不靠文字区分。
- **依赖：** M10-01。
- **需求 ID：** `VIS-REQ-001～008`。
- **实施：** 用轮廓、运动节奏、器官位置、资源行为和声音组合区分玩家、友军、三谱系、护群、Alpha 和债兽部件；不得只靠颜色。
- **验收：** 灰度、色盲模式和高密度战斗截图均能辨认。
- **玩家结果：** 玩家不看名称也能判断当前受控体、危险、护群和可交互资源。

### M10-03 器官、弹道与命中反馈

- **目标：** 12 个器官按功能拥有一致且有冲击力的发射、命中、受损和切离反馈。
- **依赖：** M10-02。
- **需求 ID：** `VIS-REQ-003～004`、`CP-REQ-090～092`。
- **实施：** 炮口、方向预览、弹体、命中、场地、持续伤害、后坐力、声音和 UI 读取同一 EmissionContext 与阶段事件。
- **验收：** 关闭伤害数字仍能大致判断命中类型和器官状态。
- **玩家结果：** 玩家能判断发射方向、是否命中、命中类型、持续区域和器官是否被挡/禁用。

### M10-04 意识传递与网络表现

- **目标：** 镜头沿信号脉冲进入同一身体，网络健康可由视觉和声音读出。
- **依赖：** M10-02。
- **需求 ID：** `VIS-REQ-005～006`、`UX-REQ-007`。
- **实施：** 过渡读取真实控制实体、信号范围、断线/恢复和暂停规则；无目标、目标死亡和低动态设置有替代表现。
- **验收：** 转换不遮挡危险超过可接受时长；低动态模式可关闭强效果。
- **玩家结果：** 玩家知道自己切入了谁、网络是否可用、为什么失败以及何时恢复。

### M10-05 Alpha、债兽与发射高潮

- **目标：** 债务器官来源远景可读，终局吸收与发射达到宣传片级记忆点。
- **依赖：** M10-01、M7。
- **需求 ID：** `VIS-REQ-007～008`、`AL-REQ-030～035`。
- **实施：** 表达 Alpha 核心/护群职责、食源依赖、运输暴露、诱饵识破、配方学习和器官弱点；债兽吸收按实际部件顺序并可读档恢复。
- **验收：** 不看 UI 的观众也能识别首领部件被逐个拆除和最终变成文明身体。
- **玩家结果：** 玩家能把敌方适应、自己的对策和终局身体变化联系起来。

### M10-06 完整声音语言

- **目标：** 三谱系、网络、样本搬运、归档、适应和意识传递有可学习声音。
- **依赖：** M10-02。
- **需求 ID：** `AUD-REQ-001～006`。
- **实施：** 为发射/命中、危险、食源争夺、搬运在途、样本被抢、断流、学习、切换、暂停和存档设计短、可区分、可重复声音，并限制叠加。
- **验收：** 玩家不看屏幕中心也能听出样本即将被搬走和网络断流。
- **玩家结果：** 声音能作为第二规则通道，而不是只在战斗高潮播放音乐。

### M10-07 可访问性实现

- **目标：** 完成暂停、慢速、瞄准辅助、轮廓、色彩、闪烁、摇晃和字幕设置。
- **依赖：** M10-03、M10-04。
- **需求 ID：** `UX-REQ-001～010`。
- **实施：** 覆盖重绑定、保持/单键、鼠标、瞄准辅助、色彩/轮廓、字体/字幕、闪烁/摇晃/动态模糊、低动态、游戏速度、暂停和分轨；重启/读档/演示版保持设置。
- **验收：** 设置保存；所有终局步骤均有非高精度输入替代。
- **玩家结果：** 色盲、低动态、字幕和辅助设置不会抹掉关键因果，也不会改变资源、伤害和生态账本。

### M10-08 Steam 演示版门禁

- **目标：** 交付稳定演示版和能在数秒内表达独特性的商店素材。
- **依赖：** M9、M10-07。
- **需求 ID：** `DEMO-REQ-001～006`。
- **实施：**
  1. 开场 10 分钟内出现一次意识传递和一次器官获取；
  2. 演示版至少让玩家看到一次敌人因果进化；
  3. 商店动图依次展示 RTS 下令、切入直控、器官手术、敌人长出反制、债兽轮廓；
  4. 完成崩溃、存档、输入设备和性能回归；
  5. 再做一轮陌生玩家测试。
- **验收：** 玩家仅看短预告也能复述“培育军团，也培育天敌”。
- **玩家结果：** 新玩家在首 10 分钟真实完成一次意识传递、器官获取、RTS 命令、直控释放、敌方适应和资源选择，并能暂停、存档、失败和重试。

若每次由一个 AI 工作者串行执行，按编号顺序领取。若未来允许多个彼此独立的工作者，也只有以下内容适合在核心接口冻结后并行：
