## 1. 这一段在修什么

GDD §7.3 的产品语义是：

> AI 不是故意愚蠢，而是**风险保守、精度有限、不会发明临场组合**。
> 玩家接管带来峰值价值，但离开后单位仍能可靠完成明确命令。

拆开来看，交还这件事其实有三条独立的路径，而在 M2-04a 之前只有前两条是通的：

| 单位在被接管前的状态 | 交还之后发生什么（M2-04a 之前） | 结论 |
|---|---|---|
| 属于某个编队 | 编队归属**完全不受影响** | 本来就对 |
| 带着一条 RTS 命令 | 命令**自动复活**，继续执行 | 本来就对 |
| 什么都没有（裸 AI） | 落回 `JobAIIntent` **从零决策**，不记得刚才在打谁、正朝哪走 | 这才是缺口 |

所以本段的工作量分布很不均匀：前两条是**核实 + 补真断言**，第三条才是真的写代码。
下面逐条写明哪些是本来就成立的。

## 2. 编队与命令为什么本来就不会丢（核实结论，非新增实现）

### 编队归属

编队存在 `SquadCommandSystem._groups`（热更层 `Dictionary<int, List<SimEntityId>>`），
**内核根本不认识"编队"这个概念**——它只认识每个单位身上那一条 `UnitCommand`。
接管与交还全程在内核里改 `IntentSource`，碰不到那个字典。
键是稳定 `SimEntityId`，槽位复用也不会让它指向别人。

唯一的可见差异：**直控期间该单位不会出现在选择集里**。
`SquadCommandSystem.IsSelectable` 过滤掉 `IntentSource == Player`，
`SimWorld.QueryUnitsInRect(commandableOnly: true)` 同判据。
这是 M2-02 立的规矩（"两套输入不抢同一个单位"），不是编队丢了——
退出直控后 `RecallGroup` 立刻能把它唤回来。自检 `[18]-A` 守这条。

### RTS 命令

直控期间命令**原样留在内核的 `_unitCommands` 里**：`SwitchControlledUnitInternal`
一行都没碰它，只把 `IntentSource` 改成 `Player`。而 `JobCommandIntent.Execute`
只处理 `IntentSource == Commanded` 的槽位，于是命令在直控期间处于"冻结"而不是"被清掉"。

交还时 `SwitchControlledUnitInternal` 第 377 行把旧受控者的 `IntentSource` 恢复成
`_intentSourceBeforePlayer[previousIndex]`——**它可能是 `AI`，也可能是 `Commanded`**，
不是恒定 AI。是 `Commanded` 时下一帧 `JobCommandIntent` 就把命令重新编译成意图，命令自动复活。

**`AiHandoffSystem` 在这条路上一行都不插手**（`LastContinuation == ResumeCommand` 直接返回）。
插手就等于在交还那一刻把玩家的明确命令盖掉，那正好是 GDD §7.3 的反面。

## 3. 接管缓冲：为什么是一条短时守备命令

裸 AI 单位交还后的真实问题不是"站桩"也不是"自杀"，而是**忘掉上下文重新决策**：
`JobAIIntent` 按 `BehaviorArchetype.Kind` 走 switch，没有任何"刚才在干什么"的输入。
于是"玩家把它开到敌人脸上然后松手"和"它自己漂到那儿"在下一帧完全等价。

### 机制

交还那一刻（订阅 M1-06 的单一出口 `ControlledUnitChangedSignal`），对**会落回裸 AI** 的单位
下一条 `UnitCommandKind.Guard`，钉在一个按退出瞬间状态算出来的延续点上；
缓冲窗口到期后由 `AiHandoffSystem` 撤销，单位落回 AI。

**为什么用守备而不是新造一套 AI 记忆：**

1. 守备的语义天然就是"待在这别乱跑、不主动追远处目标"——正好等于任务要求的
   "保守、不主动开新战线"。缓冲命令**绝不是 `Attack`**，自检 `[18]-B` 专门守这条。
2. 它走的是 M2-02 已经验收过的 `JobCommandIntent` 路径，热更层只在下令那一刻付一次代价，
   逐帧的事全归 AOT 作业。造一套"AI 记忆"意味着给内核每个单位加状态字段 + 一条新的逐帧分支。
3. 命令**只产出移动意图，不接管战斗**（M2-02 契约）。所以"原地守住"不等于"不还手"——
   攻击结算仍走既有的距离判定路径。这是"交战中退出仍能继续交战"成立的前提。

### 三种延续判定

判据只用两个量：退出瞬间的**速度**，和威胁半径内**最近的敌对单位**。

| 判定 | 条件 | 延续点 |
|---|---|---|
| `HoldGround` | 有威胁 + 退出时基本静止 | 交还点原地 |
| `Disengage` | 有威胁 + 速度方向背离威胁（点积 > 0.35） | 交还点 + `normalize(朝向 + 背离方向)` × 6 |
| `Advance` | 无威胁 + 退出时在移动 | 交还点 + 朝向 × 6 |
| `HoldGround` | 无威胁 + 退出时静止 | 交还点原地 |

`Disengage` 用「朝向 + 背离方向」的合成而不是纯背离方向：玩家绕着敌人跑开的那一下
会被纯背离拉直成"正对背面直线撤"，看起来像换了个人在操作。

### 常量与理由

| 常量 | 值 | 为什么是这个值 |
|---|---|---|
| `HandoffBufferSeconds` | 1.5s | 必须 **长于一次控制权切换冷却**（`SimBridge.DefaultControlSwitchCooldown` = 0.75s，这里取 2 倍），否则"切过去看一眼再切回来"会让缓冲每次都在半路被打断，等于不存在；又必须短到玩家不会误读成"这个单位不听 AI 了"——俯视战斗里超过两秒的静默期看起来就是卡住。同时够单位按常规移速走完 `ContinuationDistance`。 |
| `ContinuationDistance` | 6 | 常规移速 4~6/s × 缓冲窗口，正好一口气走完，不会出现"命令还没到就过期"的半截观感。 |
| `EngageThreatRange` | 12 | 与内核撤退命令的 `RetreatThreatRange` 同量级。**刻意不复用那一个**：它是内核撤退行为的参数，改它会顺带改掉所有撤退命令的手感。 |
| `BufferArriveRadius` | 1.5 | 比单位半径宽，避免在守备点上反复微调位置。 |
| `MaxPendingHandoffs` | 8 | 同时在缓冲期的记录上限，也是每帧代价的上界。 |

### 两条不变量（都有断言）

- **缓冲不吞玩家的新命令。** 到期时只撤"内容与自己下的那条完全一致"的守备命令。
  缓冲期间玩家完全可能给它下新的编队命令，一起清掉就是"RTS 命令莫名被吞"，
  而且只在接管刚结束的那 1.5 秒里复现——最难查的一类 bug。
- **缓冲不在玩家手里跑完。** 缓冲期内玩家又把它接管回去时，倒计时**冻结**
  （`ExpireBuffers` 见 `ControlledUnitId == record.Unit` 就把 `ExpireAt` 往后推），
  等它下次被放开时重新武装一个完整窗口。
  不冻结的话，"切过去看一眼再切回来"会让缓冲形同虚设；
  而在玩家手里 `ClearCommand` 也会被内核拒绝（那条拒绝正是"绝不夺走玩家直控实体"的保护）。

### 守备必须由本系统撤销

`Guard` 在内核里是**持久命令，不会自己完成**（M2-02 有意如此）。
所以缓冲的结束时机是热更层的产品决策，**不能藏进内核的完成判据里**。
代价是：漏掉撤销 = 把那个单位永久钉在地上。`MaxPendingHandoffs` 溢出时最旧的一条
也走同一条收尾路径，不留悬挂命令。

## 4. 每帧代价：与场上单位数无关

仓规架构红线第 4 条要求热更层每帧与敌人数无关。本系统稳态每帧只做：

- `_clock += dt`（一次 float 加法）；
- 每条缓冲记录一次 `_clock < ExpireAt` 比较（记录数 ≤ 8，与场上单位数无关）；
- 对**当前受控的那一个**单位做一次位置有效性校验，O(障碍数 ≤ `SimConst.MaxObstacles` = 32）。

"解析实体"这类 O(单位数) 的活（`TryResolveUnitIndex` / `QueryUnitsInRect` / `ClearCommand`）
只发生在**交还那一刻**和**每条记录到期的那一次**，每条记录一生只付一次，
且逐单位扫描整段发生在 AOT 内核里——与 M2-02 `QueryUnitsInRect`、M1-06 `GetControlCandidates`
同一条约定。

## 5. 安全位置：没有寻路，所以"不可达"不是"卡在墙后"

**全仓没有寻路**（`Pathfind` / `NavMesh` / `Reachable` 零命中），移动是纯直线：
期望方向 = 目标向量归一化，交给 `JobIntegrate` / `JobSeparation` 积分与分离。
本段**不新建寻路系统**（M2-04 非目标，且 Built-in RP 无 NavMesh 依赖）。

因此"玩家把单位留在不可达处"的真实形态是**位置本身无效**，只有三种：

1. 坐标变成 NaN / Inf（留在内核里会顺着空间哈希污染整局）；
2. 落在场地外（`|x| > ArenaHalfExtent`）；
3. 落在障碍体内部——`JobIntegrate` 的推出循环是"逐个障碍依次推"，
   两个互相重叠的障碍会把单位从 A 推进 B、再从 B 推回 A，最终停在某个障碍内部反复推挤。

### 为什么守在"接管期间每帧"而不是"交还那一刻"

玩家只能把**自己正在直控的那一个**单位精确开进坏位置；被命令 / 被 AI 驱动的单位
每帧由 `JobIntegrate` 推出障碍、夹进场地，玩家碰不到它们的落点。
守住受控单位这一个槽位，"交还时单位处在有效位置"就是**构造上成立**的，
而不是靠交还那一刻补救。顺带还修掉了同源的另一半问题：玩家自己被卡住、动不了。

这也是本段**内核零改动**的前提：受控单位有现成的内核入口 `SimBridge.SetControlledPosition`；
换成"交还之后再搬运"就必须给内核新开一个"按实体 id 挪动任意单位"的公共入口
（今天只有 `SetPlayerPosition`（只认受控者）与 `Knockback`（区域、不精确）两个位移原语）。

### 抢救算法

先"夹进场地 + 逐个推出障碍"迭代 4 轮（与 `JobIntegrate` 同一套几何，只是多跑几遍以处理
互相重叠的障碍）；仍然不行才退到一圈一圈向外采样（8 方向 × 6 圈）。
采样兜底只在抢救路径上跑，不在每帧路径上。NaN 进来时一切几何都没有意义，从场地中心重新起算。

### 不得误伤

`SafeEpsilon = 0.01` 的容差是必需的：`JobIntegrate` 把贴边单位**精确**放在
`ArenaHalf` / `障碍半径 + 单位半径` 上，不留余量就会把"正常贴墙"判成"卡在墙里"，
于是每帧都在瞬移。自检 `[18]-G` 的第一条断言就是"正常行进 60 帧不得触发任何抢救"。

## 6. 调试显示：这里显示的**不是**教义

里程碑实施第 5 条写的是「显示当前教义与目标」，但**代码里不存在"教义"（Doctrine）这个概念**
——全仓零命中。GDD §8.3 的六种编队教义（先锋 / 猎手 / 护送 / 潜行 / 回收 / 坚守）是
**编队级**概念，属 M3 的 `PhenotypeTemplate` 层，今天既没有数据也没有代码。

所以本段显示的是**单位级行为原型**，两者不是一回事，将来接上教义时这块要并存而不是替换：

| 显示项 | 来源 |
|---|---|
| 行为原型 `BehaviorKind` | `BehaviorArchetype[snapshot.ArchetypeId[i]].Kind`（11 种） |
| 意图来源 `IntentSource` | `snapshot.IntentSource[i]`（AI / Player / Scripted / Commanded） |
| 当前命令 `UnitCommandKind` | `SimBridge.TryGetCommand` |
| 当前目标 | 攻击命令 → 目标实体 id；其余 → 目标坐标；缓冲期内无命令目标时 → 退出瞬间记下的威胁 |
| 是否在接管缓冲期 | 剩余秒数 + 这一次的延续判定 |
| 所属编组 | 槽位位掩码（bit1..bit9） |

入口是 `AiHandoffSystem.Describe(SimEntityId)`，**随查随算，不缓存**——
自检直接对它写断言（下一条命令立刻能读到），不必去比像素。

画法沿用 `WhiteboxSquadOverlay`：`GL` 直接画线 + IMGUI 写字，**不新建任何 UI 资源**。
走资源模块就要配对加载 / 释放，给白模调试多一条能泄漏的路径不值得。
组件挂在同一个 `__SquadOverlay` GameObject 上，`CellStageFlow.Exit` 整个销毁它，
不多一条要单独清理的路径。默认关闭，**F9** 开关
（F10 = `CellDebugHud`，F11 = 压力测试，F12 = 相机验证态，都已被占）。

## 7. 生命周期

| 时机 | 动作 | 在哪 |
|---|---|---|
| `SetupCameraDirector`（`SetupSim` 之后） | `new AiHandoffSystem()` + `Bind(sim, squad, archetypes)` | `CellStageFlow` |
| 每帧 | `Tick(dt, paused)`，排在暂停早退**之前** | `CellStageFlow.Update` |
| 控制权变更 | 订阅处理 | `ControlledUnitChangedSignal` |
| `Exit` | `Unbind()`，**排在 `_squadCommands.Unbind()` 之前** | `CellStageFlow` |

`Unbind` 必须先行：它订阅着控制权变更信号，留着会在下一局用上一局的编队字典记录归属。

与 `CameraDirector` / `SquadCommandSystem` / `DirectControlActions` 同理**不进 `_hub`**：
控制权在暂停下也可能变（死亡回弹、读档恢复），而 `_hub` 会被暂停早退整个冻住。
`Tick` 内部自己判暂停：暂停时单位不动，位置也不会变坏，没必要在冻结帧里反复校验。

## 8. 内核零改动

`Assets/GameScripts/Main/Sim/` 本段**一行未改**。
用到的全是既有入口：`SimBridge.IssueCommand` / `ClearCommand` / `TryGetCommand` /
`QueryUnitsInRect` / `SetControlledPosition` / `Obstacles` / `ArenaHalfExtent`。
热更层碰内核仍然只有 `SimBridge.cs` 这一个口子，且 `SimBridge` 本段也没有新增成员。

热更层唯一的新增公开面是 `SquadCommandSystem.GroupMembers(slot)`（只读，返回内部列表本身）
——交还那一刻要读编队归属，而编队归属只存在那里。

## 9. 验收覆盖程度（如实说明）

自检 `[18]` 段 66 条全绿，全部是行为断言而不是字段比对：真起 `SimBridge`、真切控制权、
真推进帧，然后去看单位到底往哪走了。

**里程碑验收原文写的是「交战、搬运、撤退」三态，但代码里不存在"搬运"**
（全仓 `Carry` / `Haul` 零命中，它属于后续里程碑的回收 / 搬运玩法）。
本段用「**移动中退出**」替代第二态，并在这里如实写明——没有假装做了搬运。

三态各自的行为断言：

| 状态 | 断言的是什么 |
|---|---|
| 交战中退出 | 缓冲期内守在交还点（漂移 0.01），而**同原型、同参数、从没被接管过的对照单位已经漂了 5.84**——否则"没乱跑"只是因为这个原型本来就不动，什么都没证明 |
| 移动中退出 | 位移 4.50、方向一致度 1.00，真的沿原方向继续前进而不是原地发呆一拍 |
| 撤退中退出 | 与敌人距离 7.32 → 11.82，真的继续拉开而不是掉头回去 |

另外：到期之后单位**真的重新按行为原型活动**（证明确实回到了 AI，不是永久卡在守备点）；
缓冲期内玩家下的新命令到期后仍在；反复接管 / 交还之后 M1-06 的
"`IntentSource == Player` 数量 ≤ 1"不变量仍成立。

### 没覆盖到的部分

- **F9 调试叠加层的"画出来长什么样"没测。** Edit 模式不跑 `OnRenderObject` / `OnGUI`，
  测的是它读的那份数据（`Describe`）——每一项都有真断言，包括"下一条命令立刻能读到"。
  GL 画线与 IMGUI 排版本身只有人眼能验。
- **F9 按键路径没测。** 与 M2-03b 同样的原因：Edit 模式敲不出真实按键。
  开关本身是 `AiHandoffSystem.DebugOverlayEnabled` 一个 bool，自检直接读写它。
- **"最近威胁"的判据在极密集虫群里可能漏判。** `QueryUnitsInRect` 的返回条目被
  `SimConst.MaxSelectionSize`（64）截断，理论上可能漏掉真正最近的那一个。
  后果只是把 `Disengage` 判成 `HoldGround`，不会产生错误命令，所以没为它做缓解。
- **互相重叠障碍的抢救没有构造用例。** `[18]-G` 测的是单个障碍 / 场地外 / NaN 三种，
  多重叠障碍走的是同一段采样兜底代码，但没有针对它的断言。
- **缓冲窗口长度是产品手感值，没有玩家侧验证。** 1.5s 的论证见 §3，但"玩家会不会觉得别扭"
  要等 M2-06 的试玩门。
- **没有跨局回归断言**（不像 M2-03b 那样测 `Unbind` 之后信号不再生效）。
  `Unbind` 走的是与 `DirectControlActions` 完全相同的 `SignalScope.Dispose()` 模式。

## 10. 非目标（M2-04a 明确不做）

- **不做「AI 禁止高风险过载」**（里程碑实施第 3 条）——见下面 §12 起的 M2-04b。
- **不建寻路 / NavMesh / 可达性图**（M2-04 非目标）。
- 不做搬运 / 回收玩法（"搬运"态的替代说明见 §9）。
- 不让 AI 自动决定战略路线（M2-04 非目标）——缓冲只延续玩家留下的那一拍，不新增决策。
- 不改内核；不新增器官、基因、敌人、美术、可交互物；不新建 UI 资源 / UXML。
- 不重建 M1-06 的控制生命周期链路、M2-02 的命令链路（本段只复用并回归验证）。

## 11. 已知缺口（交给后续里程碑）

- **编队教义（GDD §8.3）整体缺席**，见 §6。调试显示今天显示的是单位级行为原型。
- **缓冲期结束就真的什么都不记得了**：没有"上一个目标"之类的持久 AI 记忆。
  这是刻意的最小实现边界——造一套 AI 记忆系统要给内核每个单位加状态字段和逐帧分支。
- **缓冲对「被命令中的单位」不生效**：带命令交还直接复活命令、不进缓冲（§2）。
  如果将来发现"玩家接管带命令单位后松手，命令的旧目标已经不合理了"，
  那是命令本身的时效问题，属于 RTS 层，不该在缓冲里补。
- **安全位置只守受控单位**（§5）。若将来出现"AI 单位也会被卡死"的新来源
  （例如动态生成的障碍直接盖在单位身上），需要一个内核侧的位置有效性作业，而不是把这段搬去逐帧扫。

# M2-04b：AI 禁止高风险过载

## 12. 在修一个真实漏洞，不是在加功能

M2-03c 立的规矩是「过载债**按身体**归属」：能按出什么、按得多勤，都由这具身体决定
（理由见 `Control/UnitVitals.cs` 的 `UnitVitalsRegistry` 类注释）。
但那本账只挡得住**一条路**：

| 谁在开这具身体 | 攻击走哪条路 | M2-04b 之前受不受过载债约束 |
|---|---|---|
| 玩家直控 | `DirectControlActions.TryRelease` → `UnitVitalsRegistry.Evaluate` | ✅ 受 |
| AI / 被命令 | 内核 `SimWorld.ResolveMinionCombat`，限制只有原型的 `AttackCooldown` | ❌ **完全不受** |

于是存在一条可利用的漏洞：**把一具身体打到过载 → 退出直控换一具接着打**。
那具身体交给 AI 后照常全速攻击，过载的惩罚被完全规避——
「按身体归属」这条立论在行为上只兑现了一半。

GDD §7.3 那张能力表里，「蓄力/过载」这一行 AI 侧写的是「**只在安全阈值内使用**」。
一具**已经过载**的身体，无论谁在开，都不在安全阈值内。拆成两条可验的产品含义：

1. **AI 继承过载后果** —— 本段真正写的代码。
2. **AI 自己不会主动过载** —— **构造上已经成立，本段没有为它写任何代码**，理由见 §15。

## 13. 实现路线：内核只做"被通知的位"，判定一行不下沉

架构红线：判定不得下沉 `Main/Sim/`，内核不认识"器官"，更不认识由器官推导出来的过载债。
但「这具身体现在瘫痪了」是**身体状态**，内核本来就认识——
`SimStatus.Stunned`（无法移动）/ `SimStatus.Feared`（转 Flee）都是既有且已验收的
「内核状态位改变 AI 行为」模式。所以复用它，不发明新机制：

| 谁 | 负责什么 |
|---|---|
| `UnitVitalsRegistry`（热更） | **唯一真相**：债怎么涨、怎么衰减、何时进过载、何时滞回解除。数值口径一行未改 |
| `OverloadSuppressionMirror`（热更，新增） | 过载态**翻转那一刻**推一次给内核。不含任何判定、不含任何计时 |
| `SimWorld.ResolveMinionCombat`（内核） | 一条 `if 位` 的分支。**没有自己的过期逻辑** |

### 防漂移：内核侧不许有第二套过期

`SimStatus` 确实另有一套限时机制（热更层 `StatusSystem` 的 `_entries`，到期取消）。
**本位刻意不登记任何限时条目**：解除的唯一来源是账本自己衰减到清除线 60。
两套过期并存必然漂移——一边按 `Strain` 滞回解除、一边按秒数到点取消，
只要 `StrainDecayPerSecond` 改一次，两边就再也对不上。
`SimTypes.cs` 里 `SimStatus.Overloaded` 的注释已把这条写进枚举本身。

（该位在 M2-04b 之前是**声明了但全仓零使用**的——原注释写的"反应矩阵殉爆"从未实现。
本段接管了它并写明唯一写者，不是与既有用法抢同一个位。）

### 巡守表：惰性结算在这里必须开一个口子

`UnitVitalsRegistry` 是惰性结算的（读/写那一刻才按时间差补齐），前提是
"没人读 = 结果无所谓"。镜像进内核之后这条前提破了：一具交给 AI 的身体**没有任何读者**，
`Sync` 永远不跑，过载位就会永久挂着——**单位被无声地永久钉死，这是本段最危险的失败模式**。

所以额外维护一张只装"当前处于过载态的实体"的巡守表 `_overloadWatch`，在 `Advance` 里逐条补齐：

- 长度与场上单位数**无关**：过载债只可能由玩家的释放（`Commit`）产生，玩家一次只操一具身体；
  稳态是 0（没人过载时整段是空循环），硬上限 `MaxOverloadWatch = 16`。
- 清除判据仍然只有 `Sync` 里那一套，**没有第二个公式**。
- 溢出兜底是"最早进入过载的先解除"：宁可让一具身体提前脱离过载，
  也绝不能让它的内核压制位悬空。

### 每帧代价

热更层每帧新增：巡守表逐条一次 `Sync`（长度 ≤ 16，稳态 0）。
`TryResolveUnitIndex`（内核内 O(单位数)）每次过载只付两回（进 + 出），
与 M2-02 `QueryUnitsInRect`、M2-04a 交还处理同一条约定。
内核每帧新增：`ResolveMinionCombat` 既有循环里一次位与——而且它排在索敌之前，
被压制的单位**省掉**了一次空间哈希查询，净开销为负。

## 14. 内核改了什么（逐条说明为什么非改不可）

**两处，其中只有一处是可执行代码。**

1. `Main/Sim/SimWorld.cs` · `ResolveMinionCombat`：在攻击冷却递减之后加一条
   `if ((_status[i] & (uint)SimStatus.Overloaded) != 0u) continue;`。

   **为什么非改不可**：这是 AI 单位攻击结算的**唯一**落点，而它整段在内核里。
   热更层没有任何入口能拦住它——`SimBridge` 上不存在"让某个单位停火"的原语
   （既有位移原语只有 `SetPlayerPosition` 与 `Knockback`，攻击侧一个都没有）。
   不改这里，就只剩两条更坏的路：把 AI 攻击整个搬去热更层（每帧 O(单位数)，撞红线），
   或者给热更层新开一条"每帧扫描并压制"的路径（同样 O(单位数)）。

   **位置在冷却递减之后**：被压制的身体不该顺带把攻击冷却也攒成一笔债，
   解除那一刻应当是"就绪"而不是"再等一个 CD"。

2. `Main/Sim/SimTypes.cs` · `SimStatus.Overloaded` 的文档注释：写明唯一写者与
   "不许加第二套过期"。**纯注释，零行为**。写它的理由是防止下一个人给这个位接上
   `StatusSystem` 限时条目——那正是 §13 说的漂移，而且是运行时才暴露的那一类。

其余内核文件一行未改。`SimBridge` **没有新增任何成员**：镜像用的
`TryResolveUnitIndex` / `ApplyStatusUnit` 都是既有入口。

## 15. 「AI 自己不会主动过载」：构造上成立，本段没为它写代码

核实结论：AI 的攻击（`ResolveMinionCombat`）**根本不经过 `UnitVitalsRegistry.Commit`**，
一分过载债都不产生；`Commit` 全仓唯一调用点是 `DirectControlActions.TryRelease`
（外加验收自己调的那次）。所以"AI 保守、不去冒这个险"在今天是**构造上成立**的，
不需要任何机制。

**刻意不为它造一本账**：给 AI 记过载债意味着要为每个 AI 单位登记条目、逐帧衰减
（O(单位数) 的每帧循环，撞红线），而换来的行为差异是零——AI 的输出本来就被
原型的 `AttackCooldown` 卡死，它没有"连点到过载"这个动作可以做。

自检 `[19]-B` 与 `[19]-F` 把这条做成了真断言而不是一句话：两名 AI 召唤物在整段里
持续攻击（真掉血），跑完之后在账本里**连条目都没有**（`IsTracked == false`）。

**将来要小心的地方**：哪天给 AI 加上"会用器官的 AI"（走 `OrganKernelAction` 那条路），
这条构造保证当场失效，必须同时决定"AI 要不要记债"。别以为本段已经替它挡住了。

## 16. 验收覆盖程度（如实说明）

自检 `[19]` 段 29 条全绿，全部是行为断言：真起 `SimBridge`、让 AI 召唤物真打真敌人、
真比掉血量。每一条"打不出东西"都配一个同原型、同参数、从没被接管过的**对照单位**
在同一批帧里照常掉血——否则"没打出来"完全可能只是因为整副内核被测停了。

关键几条：

| 断言 | 实测 |
|---|---|
| 基线：AI 召唤物本来就在打人 | 60 帧各打掉 25.0 |
| 玩家的释放真的记债 | 一次释放 → 过载债 10.9 |
| **过载的身体交给 AI 之后同样打不出东西** | 52 帧掉血 **0.000**；同期对照单位打掉 30.0 |
| 过载**不是麻痹** | 压制窗口内它仍朝目标移动 2.45 |
| 债衰减到清除线后 AI 恢复攻击 | 60 帧打掉 40.0（没人读它，靠巡守表补齐） |
| `Unbind` 不留悬挂压制 | 拆台后那具身体立刻恢复输出（打掉 40.0） |
| AI 全程零过载债 | 跑完整段仍 `IsTracked == false` |

M2-03c 的 `[17]` 段 52 条、M2-04a 的 `[18]` 段 66 条全部零退化
（按断言集合比对，不比总数）。

### 没覆盖到的部分

- **只覆盖了 `ResolveMinionCombat` 这一条 AI 输出路径。** 今天可直控的身体
  （`IsFriendlyFaction` = `Player` / `PlayerMinion`）在 AI 手里的输出手段只有这一条，
  所以当前是完备的；但 `ResolveHostileRangedCombat` / `ResolveHostileAbilities` /
  `JobContactDamage` **都没有**这个分支。哪天玩家能直控敌方阵营的身体，那三条要一起补。
- **`MinionSeekExplode` 的自毁没有单独断言。** 它与 `MinionSeekAttack` 共用同一条被改的
  `continue`，所以行为上必然一起被压制，但没有针对它的用例。
- **没有多具身体同时过载的用例。** `MaxOverloadWatch = 16` 的溢出兜底路径
  （"最早进入过载的先解除"）没有构造断言——它在实际玩法里到不了
  （玩家一次只操一具身体，一具身体 1.6 秒就衰减出过载态）。
- **没有视觉断言。** 内核不给 `Overloaded` 染色（`SimRenderer` 的染色名单里没有它），
  可见后果只有 HUD 状态条上多一枚"过载"标记（`BattleHudToolkit` 按中性标记默认样式画），
  与三个量面板上的过载提示说的是同一件事。这一条只有人眼能验。
- **数值手感没验。** 阈值 100 / 清除线 60 / 衰减 25/s 一个都没改（M2-03c 已验收），
  但"AI 被压住 1.6 秒，玩家看着觉不觉得别扭"要等 M2-06 的试玩门。
- **没有跨局（换关）回归断言**，只测了 `Unbind` 收尾。`Bind` 侧的先解绑再重绑
  走的是同一段代码。

### 非目标（M2-04b 明确不做）

- 不改过载债的任何数值口径与代价推导公式（M2-03c 已验收）。
- 不给 AI 记过载债（§15）。
- 不碰 `AiHandoffSystem`（M2-04a）——本段一行未改它。
- 不给内核加"器官"概念、不加第二套状态过期、不加新的内核公共入口。
