# 《ProjectA》AI 实施里程碑

> 对应产品权威：`ProjectA_GDD.md`  
> 用途：供 AI 工作者逐项领取、实施、测试和交接  
> 原则：先证明闭环，再扩内容；一项任务只解决一个可验收问题

---

## 0. AI 执行契约

### 0.1 每次开始前必须读取

1. 仓库根目录 `AGENTS.md`；
2. `production/session-state/DIGEST.md`；
3. `production/PROGRESS.md` 的当前焦点；
4. `DesignDocs/README.md`；
5. 本文对应里程碑；
6. `ProjectA_GDD.md` 中对应系统章节；
7. 涉及代谢/ComposeEngine 时，再读 `最新改动需求/AUTHORITY_AND_CONFLICTS.md`。

不得把 `production/design` 中旧 Epic 的产品假设自动带入当前任务。

### 0.2 单任务输出格式

每个 AI 任务结束时必须留下：

- 改了什么；
- 哪些文件是规则真相；
- 如何验证，结果是什么；
- 未完成、被阻塞或主动未做的部分；
- 对后续任务新增的约束；
- 若更改玩法含义，同步更新权威文档。

### 0.3 通用完成定义

一项任务只有同时满足以下条件才可标记完成：

- 编译通过，无新增错误；
- 对应 EditMode/PlayMode/模拟测试通过；
- 没有复制第二份领域真相；
- 关键状态可在调试界面或日志中观察；
- 存档/读档影响已处理或明确证明无影响；
- 性能敏感逻辑没有在 HotFix 每帧 O(N) 扫描；
- 没有顺手加入本任务“非目标”的扩展；
- 文档与代码术语一致。

### 0.4 工作粒度和串行规则

- 一次只领取一个编号任务；
- 同一时刻只有一个任务处于 `in_progress`；
- 后置任务不得以“以后补”为由跳过前置验收；
- 涉及同一核心文件的任务必须串行；
- 每完成一个里程碑，先做固定种子回归，再进入下一里程碑；
- 不默认提交 Git，不默认创建分支。

### 0.5 任务卡模板

后续新增任务必须包含：

- **目标**：一句可判断真假的结果；
- **依赖**：必须已经完成的编号；
- **主要范围**：预计涉及的模块/文件；
- **实施**：按顺序列出的动作；
- **交付物**：代码、资产、文档或测试；
- **验收**：可重复的具体检查；
- **非目标**：本任务禁止顺手做的事情。

## M0：权威切换与基线冻结

**里程碑目标：** 所有 AI 能找到同一套产品权威，旧设计无法再无提示覆盖新规则。

### M0-01 建立新产品权威

- **目标：** 完整 GDD 与本里程碑文档进入 `DesignDocs` 权威目录。
- **依赖：** 无。
- **实施：**
  1. 建立完整 GDD；
  2. 建立 AI 里程碑；
  3. 建立 `DesignDocs/README.md` 权威索引；
  4. 明确旧规格的保留与失效范围。
- **交付物：** 三份文档。
- **验收：** 从仓库根入口能在两次链接跳转内到达产品权威和当前实施任务。
- **非目标：** 不修改玩法代码。

### M0-02 标记旧产品案

- **目标：** 旧六阶段计时案和旧上层玩法案打开即能看到“已被取代”。
- **依赖：** M0-01。
- **实施：**
  1. 给 `Cell_Stage_Spec.md` 增加醒目失效说明；
  2. 给旧上层玩法临时案改为迁移桥接页；
  3. 给框架文档标注“技术部分保留、产品流程部分失效”；
  4. 给化学权威说明增加产品权威边界。
- **验收：** 搜索“六阶段”“60 分钟”“PhaseTimeline”时，相关权威文档均能指向替代规则。
- **非目标：** 不删除历史文档。

### M0-03 更新生产入口

- **目标：** 根指令、进度页和会话摘要不再让 AI 先读旧案。
- **依赖：** M0-01。
- **主要范围：** 根 `AGENTS.md`、`CLAUDE.md`、`production/PROGRESS.md`、`production/session-state/DIGEST.md`。
- **验收：** 新会话按入口阅读时，第一产品规格为新 GDD；历史 Epic 只被描述为实现事实。
- **非目标：** 不重写历史完成记录。

## M1：可转移控制权基座

**里程碑目标：** 模拟不再把索引 0 永久等同玩家；任意合法友军可在 AI 与玩家意图间安全切换。

### M1-01 玩家索引依赖审计

- **目标：** 得到所有“index 0 / PlayerIndex / player entity”假设的完整分类表。
- **依赖：** M0 完成。
- **主要范围：**
  - `Assets/GameScripts/Main/Sim/SimWorld.cs`
  - `Assets/GameScripts/Main/Sim/SimTypes.cs`
  - `Assets/GameScripts/Main/Sim/SimSnapshot.cs`
  - `Assets/GameScripts/Main/Sim/Jobs/`
  - `Assets/GameScripts/Main/Sim/SimRenderer.cs`
  - HotFix 的状态、UI、效果执行与战斗桥接代码
- **实施：**
  1. 搜索所有玩家索引常量与注释；
  2. 分类为模拟规则、输入、镜头、UI、渲染、存档、测试；
  3. 标出必须改为稳定实体 ID 的位置；
  4. 标出只为兼容旧逻辑可暂留的适配点。
- **交付物：** `DesignDocs/migration/Controlled_Unit_Audit.md`。
- **验收：** 审计表每项包含文件、符号、风险和迁移任务编号。
- **非目标：** 不在审计任务中修改运行逻辑。

### M1-02 控制身份数据模型

- **目标：** 建立唯一的 `ControlledUnitId` 与 `IntentSource` 规则真相。
- **依赖：** M1-01。
- **实施：**
  1. 定义稳定实体 ID，不依赖数组槽位；
  2. 定义 `AI`、`Player`、`Scripted` 意图来源；
  3. 在世界状态中保存当前控制实体；
  4. 提供只读查询和受控切换命令；
  5. 定义目标死亡、移除和世界重置行为。
- **验收：** 测试中把控制权从实体 A 切到实体 B 后，数组重排不改变目标。
- **非目标：** 不做镜头、UI 或视觉转场。

### M1-03 模拟作业去玩家特判

- **目标：** 转向、伤害、查询和生命周期作业使用实体状态/意图，而非索引 0。
- **依赖：** M1-02。
- **主要范围：** `JobSteering.cs`、`JobDamage.cs`、`JobQuery.cs` 及相关作业。
- **实施：**
  1. 将玩家输入编译为标准意图缓冲；
  2. AI 输入也写入同一形状的意图；
  3. 作业只读取最终意图，不识别“主角”；
  4. 保留必要的阵营和权限检查；
  5. 增加多友军并存回归测试。
- **验收：** 任一友军接收玩家意图时行为一致；未受控单位继续执行 AI；敌军不可被错误控制。
- **非目标：** 不优化寻路，不增加新攻击。

### M1-04 HotFix/模拟桥接 API

- **目标：** HotFix 只能通过单一桥接层查询和切换控制实体。
- **依赖：** M1-03。
- **主要范围：** `Battle/SimBridge.cs` 及控制服务。
- **实施：**
  1. 添加请求切换、查询当前控制、查询候选的 API；
  2. 验证阵营、存活、信号范围与冷却；
  3. 返回明确失败原因；
  4. 通过事件发布切换结果；
  5. 禁止其他 HotFix 文件直接访问模拟数组。
- **验收：** 非法目标不改变现状且有稳定错误码；合法切换只产生一次事件。
- **非目标：** 不实现信号网络，只使用可配置临时判定。

### M1-05 表现与 UI 查找迁移

- **目标：** 相机、HUD、血条和特效跟随当前受控实体。
- **依赖：** M1-04。
- **实施：**
  1. 移除 `SimRenderer` 的索引 0 跟随；
  2. HUD 从快照中的控制 ID 取数据；
  3. 切换时清理旧目标的玩家专属提示；
  4. 无控制实体时回退到战略锚点视角；
  5. 增加目标生成晚于 UI 的容错。
- **验收：** 连续切换 20 次，无血条串体、相机丢失、特效残留或空引用。
- **非目标：** 不制作最终意识转场美术。

### M1-06 死亡、断线与存档回归

- **目标：** 控制目标死亡、卸载或读档时控制状态确定且可恢复。
- **依赖：** M1-05。
- **实施：**
  1. 定义目标死亡后的意识回弹；
  2. 定义场景卸载与实体暂不可用；
  3. 保存稳定 ID 与回退锚点；
  4. 对旧存档提供安全默认值；
  5. 建立固定种子自动回归。
- **验收：** 死亡、暂停、存档、读档、重进场景后均只有一个控制实体或明确为无。
- **非目标：** 不加入正式死亡惩罚数值。

**M1 出口标准：** 在固定房间内，玩家能在三个真实友军间切换；离开的单位可靠恢复 AI；任何系统不再依赖索引 0 定义玩家。

## M2：同世界战略视角与意识传递竖切

**里程碑目标：** RTS 选择、暂停下令、近第三人称直控在同一场景和同一实体上闭环。

### M2-01 战略相机状态机

- **目标：** 建立战略、过渡、直控三个明确镜头状态。
- **依赖：** M1。
- **实施：**
  1. 定义每个状态的输入所有权；
  2. 实现平移、缩放、边界与目标聚焦；
  3. 过渡期间冻结冲突输入；
  4. 允许暂停时选择目标；
  5. 无效目标回退战略视角。
- **验收：** 镜头切换不传送实体、不重载场景、不产生双重输入。
- **非目标：** 不做电影级轨迹。

### M2-02 RTS 选择与基础命令

- **目标：** 能框选、追加选择、编组，并发出移动、攻击、守护和撤退命令。
- **依赖：** M2-01。
- **实施：**
  1. 选择只操作友方可指挥实体；
  2. 命令转换为模拟意图；
  3. 暂停状态允许排队；
  4. 显示路径与目标反馈；
  5. 直控时仍可看见已有编队命令。
- **验收：** 两组单位可执行不同命令，暂停下令后恢复顺序稳定。
- **非目标：** 不做复杂阵型和共享寻路。

### M2-03 直控移动与器官输入适配

- **目标：** 当前真实器官映射为直控动作，没有额外英雄技能表。
- **依赖：** M2-02。
- **实施：**
  1. 从个体装配读取可用动作；
  2. 建立移动、主器官、功能器官和交互输入；
  3. 失能器官禁用对应动作；
  4. 显示代谢、热债和冷却；
  5. 退出时恢复 AI 教义。
- **验收：** 两个不同装配单位被接管时动作集不同且与实体一致。
- **非目标：** 不新增大量器官。

### M2-04 AI 接管可靠性

- **目标：** 玩家退出后的单位能延续合理意图，而不是站桩或自杀。
- **依赖：** M2-03。
- **实施：**
  1. 保存退出前所属编队和命令；
  2. 定义接管缓冲和安全位置；
  3. AI 禁止高风险过载；
  4. 处理玩家把单位留在不可达处；
  5. 调试显示当前教义与目标。
- **验收：** 在交战、搬运、撤退三种状态退出，单位均能继续合理行动。
- **非目标：** 不让 AI 自动决定战略路线。

### M2-05 手术窗口原型

- **目标：** 证明直控能在同数值下提供独特高价值，而非只提高 DPS。
- **依赖：** M2-04。
- **实施：**
  1. 给一个测试敌人设置身体和两个器官接点；
  2. RTS 可指定器官类别；
  3. 直控可瞄准具体接点；
  4. 低伤精准切离保留完整器官；
  5. 粗暴击杀只给生物质。
- **验收：** 外部测试者能描述“为什么这次值得接管”。
- **非目标：** 不做完整器官掉落池。

### M2-06 意识传递试玩门

- **目标：** 用一个 8–12 分钟固定场景验证双层操作。
- **依赖：** M2-05。
- **交付物：** 固定场景、测试脚本、观察表。
- **验收：** 至少 5 名测试者中，4 人能完成 RTS 下令、接管、手术和退出；若多数人只玩一层，停止进入 M3，先修交互。
- **非目标：** 不做正式美术。

## M3：蓝图库、谱系与表型模板

**里程碑目标：** 器官/基因从战利品到蓝图，再到模板、新生和回巢改造形成真实闭环。

### M3-01 现有 Carrier/基因系统映射

- **目标：** 明确现有 `CarrierInstance`、`CarrierRegistry`、`CarrierGeneService`、`CarrierCompiler` 与新对象模型的复用边界。
- **依赖：** M2。
- **实施：**
  1. 记录现有 Carrier 是器官实例还是个体；
  2. 记录活动 Carrier 单例假设；
  3. 记录基因实例唯一占用规则；
  4. 记录 ComposeEngine 编译入口；
  5. 设计不破坏现有化学规则的适配方案。
- **交付物：** `DesignDocs/migration/Lineage_Loadout_Mapping.md`。
- **验收：** 每个旧概念对应“保留、包装、迁移、废弃”之一。
- **非目标：** 不直接批量改代码。

### M3-02 蓝图库领域模型

- **目标：** 区分野生实物、已解析蓝图和个体已表达器官。
- **依赖：** M3-01。
- **实施：**
  1. 定义器官/基因蓝图 ID；
  2. 保存来源、完整度、污染和重复解析进度；
  3. 提供查询与序列化；
  4. 从现有 Catalog 引用静态定义，不复制定义；
  5. 建立旧存档默认蓝图迁移。
- **验收：** 拾到器官不会自动解锁蓝图；解析后能稳定复制；拆解后不能复制。
- **非目标：** 不做 UI。

### M3-03 谱系与表型模板模型

- **目标：** 一个谱系能保存多个有版本的表型模板。
- **依赖：** M3-02。
- **实施：**
  1. 定义谱系、模板、槽位、基因顺序和教义；
  2. 每次提交生成不可变模板版本；
  3. 校验蓝图所有权、槽位和兼容性；
  4. 计算生物质与代谢成本；
  5. 生成稳定装配签名。
- **验收：** 修改模板不会回写旧版本；相同配方生成相同签名。
- **非目标：** 不生成地图单位。

### M3-04 装配签名编译与缓存

- **目标：** 同模板个体复用 ComposeEngine 编译结果，同时保留个体状态。
- **依赖：** M3-03。
- **实施：**
  1. 以模板版本和临时移植生成签名；
  2. 通过适配层调用现有编译器；
  3. 缓存静态输出；
  4. 个体生命、伤势、热债保持独立；
  5. 模板失效时安全淘汰缓存。
- **验收：** 100 个同模板单位只编译一次静态组合；改变一个个体的伤势不污染其他单位。
- **非目标：** 不重写 ComposeEngine。

### M3-05 萌生腔与新生传播

- **目标：** 模板提交只影响之后新生的对应表型。
- **依赖：** M3-04。
- **实施：**
  1. 建立萌生队列；
  2. 扣除真实资源；
  3. 绑定谱系、表型和模板版本；
  4. 生成实体并写入装配签名；
  5. 处理中途取消和萌生腔被毁。
- **验收：** 旧单位保持 V1，新单位表达 V2；其他表型不受影响。
- **非目标：** 不做最终孕育动画。

### M3-06 回巢改造

- **目标：** 旧单位只有返回联网萌生腔并支付成本后才更新模板。
- **依赖：** M3-05。
- **实施：**
  1. 校验位置、交战、携带物和网络；
  2. 锁定目标模板版本与成本；
  3. 暂时移出战斗；
  4. 完成后替换装配签名并保留允许保留的状态；
  5. 定义腔体中断和版本再次更新行为。
- **验收：** 断网、交战或资源不足时不能改造；中断不复制资源或器官。
- **非目标：** 不自动召回整支队。

### M3-07 野生器官与单体临时移植

- **目标：** 一件未归档器官能被搬运、拆解、解析或只装到一个身体。
- **依赖：** M3-06。
- **实施：**
  1. 建立物理战利品实体；
  2. 实现携带容量；
  3. 实现一个体细胞临时槽；
  4. 处理污染、死亡掉落和冲突；
  5. 返回萌生腔后提供三种处理。
- **验收：** 临时移植不会修改模板或其他单位；同一实物不能同时被解析和装备。
- **非目标：** 不做多临时槽和复杂手术动画。

### M3-08 模板编辑与传播 UI

- **目标：** 玩家明确知道改了什么、影响谁、花多少、谁仍是旧版。
- **依赖：** M3-07。
- **实施：**
  1. 展示器官/基因来源与用途；
  2. 展示模板预览和冲突；
  3. 展示新生数量、可改造数量与总成本；
  4. 在个体面板显示谱系、表型和版本；
  5. 允许筛选旧版个体并下达回巢命令。
- **验收：** 新玩家不会误以为一次提交瞬间改变整队。
- **非目标：** 不做复杂拖拽动画。

**M3 出口标准：** 玩家可从敌人切下器官，选择单体救急或带回解析；建立模板后只有新生/回巢单位获得能力；直控读取真实装配。

## M4：编队、教义与多线指挥

**里程碑目标：** 两到四支职责不同的编队可被可靠指挥，直控不会破坏编队状态。

### M4-01 编队领域模型

- **目标：** 保存编队成员、命令、教义和临时脱队状态。
- **依赖：** M3。
- **验收：** 混编单位可加入同一队；模板变化不改变编队身份；死亡成员被安全移除。
- **非目标：** 不做阵型寻路。

### M4-02 命令队列与优先级

- **目标：** 支持移动、攻击、器官类别、守护、搬运、占据、伏击和撤退。
- **依赖：** M4-01。
- **实施：** 定义排队、覆盖、中断、完成和失败原因；暂停中只编辑，不推进模拟。
- **验收：** 每种命令均有视觉反馈和确定结束条件。
- **非目标：** 不为每个器官增加单独 RTS 命令。

### M4-03 六种教义

- **目标：** 先锋、猎手、护送、潜行、回收、坚守产生可观察差异。
- **依赖：** M4-02。
- **验收：** 相同编队切换教义后目标选择、距离和撤退阈值按定义变化。
- **非目标：** 不做可视化行为树编辑器。

### M4-04 共享路径与局部分离

- **目标：** 编队使用共享路径走廊，个体只做局部避障和阵位调整。
- **依赖：** M4-02。
- **实施：** 建立可复用路径、跟随槽、卡死检测和重规划边界。
- **验收：** 目标规模单位通过狭窄通道无持续拥堵；CPU 满足预算。
- **非目标：** 不实现自由三维飞行导航。

### M4-05 直控脱队与回归

- **目标：** 接管编队成员时临时接收玩家意图，退出后回到合理队形和任务。
- **依赖：** M4-03、M4-04。
- **验收：** 玩家不会通过切换复制单位、清空命令或破坏搬运所有权。
- **非目标：** 不允许同时直控多个单位。

### M4-06 多线固定遭遇

- **目标：** 一个遭遇要求一队守护搬运线、一队处理敌巢，玩家可择机接管。
- **依赖：** M4-05。
- **验收：** 至少两种可行方案；单一万能队可尝试但明显低效；无倒计时。
- **非目标：** 不加入随机地图。

## M5：真实空间、导管网络与资源经济

**里程碑目标：** 空间、补给、信号和改造形成同一可读网络，替代无坐标环境标签。

### M5-01 空间模型迁移设计

- **目标：** 从 `WorldEnvironment` 的字符串 CellId 迁移到真实腔室/连接/世界坐标模型。
- **依赖：** M4。
- **交付物：** 数据模型、迁移步骤、性能预算和兼容层说明。
- **验收：** 能回答 RTS 导航、直控碰撞、网络覆盖和 PCG 分别读取什么。
- **非目标：** 不在设计任务中生成地图。

### M5-02 固定腔室图

- **目标：** 建立 6 个手工腔室与连接，支持同世界 RTS/直控。
- **依赖：** M5-01。
- **验收：** 所有目标体型可达；相机边界、门和跨腔状态稳定。
- **非目标：** 不做 PCG。

### M5-03 导管图与覆盖

- **目标：** 玩家可铺设主干/末梢，计算联网、信号覆盖和断点。
- **依赖：** M5-02。
- **验收：** 切断一条非冗余导管会使前线失联；环路可保持连接；结果可视化。
- **非目标：** 不模拟连续流体力学。

### M5-04 生物质与代谢流

- **目标：** 孕育、修复、改造和铺管使用守恒资源账。
- **依赖：** M5-03。
- **实施：** 统一交易接口、传输损耗、预留、取消和失败退款。
- **验收：** 无孕育拆解套利；网络断开不复制在途资源。
- **非目标：** 不增加多种稀有货币。

### M5-05 信号带宽

- **目标：** 活跃编队、远程命令和意识传递消耗可读带宽。
- **依赖：** M5-03。
- **验收：** 超载时按明确优先级降级，不随机丢命令；暂停界面可预览。
- **非目标：** 不做硬性 APM 限制。

### M5-06 萌生腔与锚点实体

- **目标：** 模板改造、生产、网络扩展和战役承诺绑定到真实地点。
- **依赖：** M5-04、M5-05。
- **验收：** 失联萌生腔不能远程改造；锚点未激活不提供覆盖；夺回后恢复一致。
- **非目标：** 不触发正式进化。

### M5-07 时间控制

- **目标：** 0× 暂停、0.5×、1×、2× 对模拟、输入、UI 和特效行为一致。
- **依赖：** M5-06。
- **验收：** 暂停时资源、敌人、冷却和进化均不推进；命令可编辑；恢复确定。
- **非目标：** 不加入时间型压力预算。

## M6：敌方采样、谱系适应与因果回执

**里程碑目标：** 玩家能看见敌人如何从证据变成反制，并能在每一步介入。

### M6-01 进化账本

- **目标：** 记录行为痕迹、公共表型、完整器官和清醒签名四类证据。
- **依赖：** M5。
- **实施：** 事件化写入；按伤害、频率、场景公开度聚合；保存来源实体和地点。
- **验收：** 相同固定种子和输入产生相同债务排序。
- **非目标：** 不直接改变敌人数值。

### M6-02 样本实体与搬运

- **目标：** 强证据在世界中成为可抢夺的样本，由指定敌人搬回巢。
- **依赖：** M6-01。
- **验收：** 玩家可夺回、摧毁或跟踪样本；搬运者死亡不会让样本瞬间归档。
- **非目标：** 不实现全部敌人变体。

### M6-03 敌方巢与育化进度

- **目标：** 巢接收样本后产生可侦察、可打断的归档与育化状态。
- **依赖：** M6-02。
- **验收：** 摧毁巢或夺走样本按规则降低进度；读档不重复结算。
- **非目标：** 不按现实时间无条件升级。

### M6-04 三条基础敌方谱系

- **目标：** 甲壳工蚁、浮囊鳐、菌毯拾荒者开场即有不同轮廓和行为。
- **依赖：** M6-03。
- **验收：** 盲测玩家只看行为/轮廓也能区分三类威胁。
- **非目标：** 每条只做竖切片所需 1–2 个基础单位。

### M6-05 适应槽、代价与兼容表

- **目标：** 每条谱系最多两个后天槽，每项反制都有代价和两种对策。
- **依赖：** M6-04。
- **实施：** 数据驱动模块；兼容性校验；视觉挂点；AI 行为钩子；对策元数据。
- **验收：** 不会组合出无动画、无弱点、完全封死玩家或违反谱系身份的变体。
- **非目标：** 不做任意程序化身体。

### M6-06 锚点免疫回声

- **目标：** 即使玩家不丢任何器官，第一锚产生教学回声，第二锚保证一次正式适应。
- **依赖：** M5-06、M6-05。
- **验收：** 零战利品丢失测试局仍能完整触发核心进化循环，且无倒计时。
- **非目标：** 不替玩家选择公开模板。

### M6-07 因果回执 UI

- **目标：** 每次永久进化显示原因、变化、代价和至少两种对策。
- **依赖：** M6-05、M6-06。
- **验收：** 回执内容来自进化账本真实事件；可在生态谱系树中回看。
- **非目标：** 不用模糊的“适应值 +1”。

### M6-08 可操纵进化测试

- **目标：** 玩家可以故意喂出一种反制，再利用其代价获胜。
- **依赖：** M6-07。
- **交付物：** 固定测试种子与剧本。
- **验收：** 至少两条不同的诱导—反制路线成立；系统不是纯惩罚。
- **非目标：** 不追求全组合平衡。

**M6 出口标准：** 测试者能从地图上指出证据如何被搬回、敌人学到了什么、为什么学到、自己下一步如何利用其代价。

## M7：三幕导演、中期 Alpha 与终局债兽

**里程碑目标：** 一局出现明确起伏，并以玩家亲手塑造的史诗狩猎和文明发射结束。

### M7-01 战役导演替代时间轴

- **目标：** 以锚点和玩家承诺驱动扎根、反进化、偿债远征三幕。
- **依赖：** M6。
- **主要范围：** 迁移/替代 `Stage/PhaseTimeline.cs`、`Stage/CellStage/CellStageFlow.cs` 及 `Spawning/SpawnDirector.cs` 的时间压力职责。
- **实施：**
  1. 定义幕状态和进入条件；
  2. 把危机挂在可预览的玩家承诺上；
  3. 移除随累计时间增长的最低难度；
  4. 保留需要的生成接口，不保留旧节奏假设；
  5. 提供调试跳幕和固定种子。
- **验收：** 玩家静止思考不会推进幕或增强敌人；主动锚定才推进。
- **非目标：** 不删除仍被其他模式使用的通用计时器，先隔离。

### M7-02 区域 Alpha 组装数据

- **目标：** 用基础谱系底盘 + 首次公共表型反制 + 环境模块 + 明确弱点组成 Alpha。
- **依赖：** M7-01。
- **验收：** 组合完全可追溯且通过兼容表；不是随机加属性。
- **非目标：** 竖切片只做一个底盘。

### M7-03 Alpha 战略猎杀

- **目标：** 实现断粮、诱离或正面围猎三类路径。
- **依赖：** M7-02。
- **实施：** 食源、迁徙、巢区增益、环境战场与器官暴露状态。
- **验收：** 不直控也能低质量通关；直控手术可获得完整外部应答记录。
- **非目标：** 不做第二个中期首领。

### M7-04 生态债务排序与预览

- **目标：** 三锚完成后显示将被债兽继承的 2–3 项债务。
- **依赖：** M7-01、M6-07。
- **验收：** 排序来自真实账本；玩家在广播前可回巢准备；确认后组合锁定。
- **非目标：** 不隐藏终局克制信息。

### M7-05 债兽模块化底盘

- **目标：** 一个手工底盘可装三个受控债务模块和一个环境模块。
- **依赖：** M7-04。
- **实施：** 模块接口、视觉挂点、攻击阶段、受损状态、弱点元数据、存档。
- **验收：** 所有竖切片组合有动画、提示、代价和可行对策。
- **非目标：** 不做无限部件组合。

### M7-06 追踪与多线遏制

- **目标：** 债兽在战略图移动，玩家可切断食源，并需压制两个供养点。
- **依赖：** M7-05。
- **验收：** 单队可打但恢复压力显著；两队分工有明确收益；无计时失败。
- **非目标：** 不做全地图实时破坏。

### M7-07 债务器官破坏顺序

- **目标：** 三个部件可按任意顺序拆除，战斗阶段随结果改变。
- **依赖：** M7-06。
- **验收：** 每种顺序至少可完成；粗暴摧毁与精确切离奖励不同；阶段不会软锁。
- **非目标：** 不为所有排列制作独立剧情。

### M7-08 核心意识手术

- **目标：** 玩家接管一个真实单位安装外部应答记录；失败可重新创造窗口。
- **依赖：** M7-07。
- **验收：** RTS 编队在外部仍持续战斗；手术不是一次性 QTE；存在纯战略低奖励替代。
- **非目标：** 不切换到独立关卡。

### M7-09 文明吸收与发射结算

- **目标：** 吸收债兽、点亮三锚、生成文明形态、破壳发射并结算决策指纹。
- **依赖：** M7-08。
- **验收：** 玩家能看见自己的主力模板和债务如何改变最终外形；胜利状态正确保存。
- **非目标：** 不制作下一文明阶段。

**M7 出口标准：** 完成固定地图全局时，情绪曲线至少包含第一次回声、区域 Alpha、创世广播、债兽围猎和发射五个清晰峰值。

## M8：固定地图完整竖切片

**里程碑目标：** 在不依赖 PCG 和大量内容的情况下，交付 20–30 分钟可反复试玩的完整游戏。

### M8-01 固定战役地图

- **目标：** 6–9 个手工腔室包含三锚、三敌方领地、Alpha 与终局场。
- **依赖：** M7。
- **验收：** 两条通往第二锚的路线；至少一条环路；所有胜负路径可达。

### M8-02 竖切片内容包

- **目标：** 1 底盘、6 器官、8 基因、2 友方谱系、3 敌方谱系简版、6 适应模块。
- **依赖：** M8-01。
- **验收：** 至少两种本质不同的通关构筑；每个内容符合 GDD 17.3 完成规则。

### M8-03 首局教学

- **目标：** 按 GDD 14.3 在真实循环中教授直控、AI 接管、搬运、解析、模板和免疫回声。
- **依赖：** M8-02。
- **验收：** 不读文档的测试者可独立进入第二幕。

### M8-04 胜负、存档与恢复

- **目标：** 全部整局失败、软失败和胜利条件正确结算。
- **依赖：** M8-03。
- **验收：** 每个锚点、模板提交、跨腔和退出位置均可恢复；不能刷随机结果。

### M8-05 性能基线

- **目标：** 在目标硬件、目标单位数和双镜头模式下达到帧时与内存预算。
- **依赖：** M8-04。
- **实施：** 测量模拟、渲染、UI、路径、编译缓存和存档峰值；先修架构热点。
- **验收：** 预算写入技术文档并由自动性能场景守护。
- **非目标：** 不通过减少玩法正确性掩盖问题。

### M8-06 外部可玩性门禁

- **目标：** 验证核心不是“开发者自己才能理解”。
- **依赖：** M8-05。
- **实施：**
  1. 至少 10 名目标玩家盲测；
  2. 记录首次困惑、主动切换次数、构筑变化、因果理解和再玩意愿；
  3. 访谈只问事实和原因，不向玩家推销设计；
  4. 按 GDD 2.3 统计；
  5. 未达门槛时只修核心，不加新内容。
- **验收：** 形成一份含录像索引、数据和前三问题的试玩报告。

## M10：美术、声音、可访问性与商店演示

- **验收：** 关闭伤害数字仍能大致判断命中类型和器官状态。

### M10-04 意识传递与网络表现

- **目标：** 镜头沿信号脉冲进入同一身体，网络健康可由视觉和声音读出。
- **依赖：** M10-02。
- **验收：** 转换不遮挡危险超过可接受时长；低动态模式可关闭强效果。

### M10-05 Alpha、债兽与发射高潮

- **目标：** 债务器官来源远景可读，终局吸收与发射达到宣传片级记忆点。
- **依赖：** M10-01、M7。
- **验收：** 不看 UI 的观众也能识别首领部件被逐个拆除和最终变成文明身体。

### M10-06 完整声音语言

- **目标：** 三谱系、网络、样本搬运、归档、适应和意识传递有可学习声音。
- **依赖：** M10-02。
- **验收：** 玩家不看屏幕中心也能听出样本即将被搬走和网络断流。

### M10-07 可访问性实现

- **目标：** 完成暂停、慢速、瞄准辅助、轮廓、色彩、闪烁、摇晃和字幕设置。
- **依赖：** M10-03、M10-04。
- **验收：** 设置保存；所有终局步骤均有非高精度输入替代。

### M10-08 Steam 演示版门禁

- **目标：** 交付稳定演示版和能在数秒内表达独特性的商店素材。
- **依赖：** M9、M10-07。
- **实施：**
  1. 开场 10 分钟内出现一次意识传递和一次器官获取；
  2. 演示版至少让玩家看到一次敌人因果进化；
  3. 商店动图依次展示 RTS 下令、切入直控、器官手术、敌人长出反制、债兽轮廓；
  4. 完成崩溃、存档、输入设备和性能回归；
  5. 再做一轮陌生玩家测试。
- **验收：** 玩家仅看短预告也能复述“培育军团，也培育天敌”。

## 建议派工顺序

若每次由一个 AI 工作者串行执行，按编号顺序领取。若未来允许多个彼此独立的工作者，也只有以下内容适合在核心接口冻结后并行：

- 正式概念美术与已冻结器官的数据实现；
- 声音素材制作与非声音代码；
- PCG 图章美术与生成验证器；
- 文案/本地化与模拟优化。

以下任务永不并行修改：控制身份、个体装配签名、网络图、进化账本、战役导演和存档模式。它们都是单一规则真相。
