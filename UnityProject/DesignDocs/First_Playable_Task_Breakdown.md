# 文明织造 First Playable 开发任务拆解

## 1. 当前工程状态

当前 Unity 项目已有：
- `Assets/Scenes/main.unity`
- `Assets/GameScripts/HotFix/GameLogic/GameApp.cs`
- TEngine 热更代码目录与基础 UI 框架
- `GDD_Starter_Pack.md`
- `First_Playable_Spec.md`

当前未发现：
- First Playable 专用流程管理器
- 细胞 / 生物阶段场景
- 构筑选择 UI
- 阶段 HUD
- 玩法数据模型
- 敌人、资源、阶段目标等 gameplay 脚本

因此第一批开发目标是先建立最小可运行闭环，而不是直接做完整内容。

---

## 2. 开发总目标

First Playable 要跑通：

`主入口 -> 细胞阶段 -> 器官/组织构筑阶段 -> 生物阶段 -> 结算 -> 返回或重开`

验收重点：
- 前一阶段选择会影响后一阶段。
- 三条路线有可感知差异。
- 三阶段能连续完成，不依赖手动切场景。
- 范围不进入文明、大明、废土、星海、宇宙终局。

建议新增目录：

- `Assets/GameScripts/HotFix/GameLogic/FirstPlayable/Stage/`

- `FirstPlayableState.cs`
- `FirstPlayableRunData.cs`
- `StageControllerBase.cs`
- `CellStageController.cs`
- `BuildStageController.cs`
- `CreatureStageController.cs`

任务：
- 建立 `FirstPlayableState` 枚举：`None`、`Cell`、`Build`、`Creature`、`Summary`。
- 建立 `FirstPlayableRunData` 保存本局数据：生命值、生物质、进化点、细胞微选择、已选模块（上限 2）、路线倾向计分。
- 建立 `FirstPlayableGameMode` 管理阶段切换，并持有 `RunData` 静态单例。
- 从 `GameApp.StartGameLogic()` 进入 First Playable 流程（替换当前的 `ShowUIAsync<BattleMainUI>()`）。
- 暂时允许所有阶段在 `main.unity` 内运行，避免早期被场景加载阻塞。

编码红线（项目 CLAUDE.md，逐条适用于本文档全部任务）：
- 异步一律 `UniTask`，禁止 Coroutine 与同步加载。
- UI 一律走 `GameModule.UI.ShowUIAsync<T>()`，不直接 Instantiate。
- 资源 `LoadGameObjectAsync` 必须与 `UnloadAsset` 配对释放。
- 阶段切换事件走 `GameEvent`，新增接口后需跑 `TEngine/Tools/GameEventSourceGenerator`。

验收：
- 运行项目后能进入 First Playable。
- 能按调试按钮或代码流程依次切到 `Cell -> Build -> Creature -> Summary`。
- 阶段切换不会丢失 `FirstPlayableRunData`。

## 4. 阶段 1：数据模型

目标：让构筑、资源、敌人和玩家形态有统一数据来源。

建议新增脚本：
- `EvolutionRoute.cs`
- `EvolutionModuleData.cs`
- `PlayerStats.cs`
- `EnemyStats.cs`
- `StageGoalData.cs`

核心枚举：
- `EvolutionRoute.None`
- `EvolutionRoute.Devour`
- `EvolutionRoute.Specialize`
- `EvolutionRoute.Technology`

首版 6 个构筑模块（`Cost` 单位为生物质，效果数值见 Spec §7.3）：
- `吞噬口器`：吞噬扩张型，Cost 120，近战伤害 +60%、击杀回血 8。
- `厚壁细胞层`：吞噬扩张型，Cost 140，最大生命值 +50、移速 -8%。
- `感知纤毛`：功能特化型，Cost 150，移速 +28%、敌人察觉范围 -35%。
- `协同神经束`：功能特化型，Cost 160，冲刺无敌帧 +0.15 秒、体力消耗 -30%。
- `原始放电囊`：科技统治型，Cost 190，解锁远程放电（伤害 25 / 射程 3.5 米 / 冷却 1.2 秒）。
- `能量导流组织`：科技统治型，Cost 170，体力上限 +40、体力回复 +50%。

细胞阶段微选择（3 选 1，各记 1 点路线倾向）：
- `贪食囊`：吞噬获得生物质 +25%，吞噬扩张型。
- `趋光纤毛`：移速 +20%，功能特化型。
- `代谢泡`：每次吞噬回复 3 生命值，科技统治型。

任务：
- 先用代码内静态数据定义 6 个模块与 3 个微选择项。
- 每个模块至少包含：`Id`、`Name`、`Route`、`Cost`、`Description`、`StatModifiers`。
- `FirstPlayableRunData` 能记录 1 个微选择 + 最多 2 个模块。
- 实现路线判定：微选择 +1 点、每模块 +1 点，平票时器官模块优先，三路各 1 点判为混合型（Spec §5.3）。
- 生物阶段属性**只由 2 个器官模块计算**；微选择效果仅作用于细胞阶段，不带入生物阶段（Spec §4.1）。

验收：
- 构筑模块与微选择项能被读取。
- 选择后数据能进入 `RunData`，且阶段切换不丢失。
- 生物阶段能看到两级选择带来的属性差异。
- 主导路线判定结果正确，含混合型情形。

## 5. 阶段 2：细胞阶段

目标：实现最小移动、吞噬、受伤、资源获取。

建议新增脚本：
- `CellPlayerController.cs`
- `CellEntity.cs`
- `CellFood.cs`
- `CellThreat.cs`
- `CellStageGoal.cs`

最小玩法：
- 玩家控制一个细胞在 3D 平面移动（WASD，带惯性）。
- 场景中存在两类可吞噬食物（A 型 / B 型）。
- 场景中存在威胁目标与危险区域。
- 吞噬同时获得生物质和进化点。
- 接触威胁造成伤害。
- 4:30 触发一次 3 选 1 微选择。
- 进化点达 100 后出现「进化」按钮，**由玩家自行决定何时进入构筑阶段**。

建议新增脚本追加：
- `CellMicroChoiceUI.cs`

任务：
- 实现 3D 平面惯性移动（加速度 12 / 阻力 4）。
- 创建玩家细胞、A/B 型食物、威胁细胞白模（基础几何体，颜色区分）。
- 实现体积对比吞噬判定，阈值 1.15（Spec §5.1）。
- 实现吞噬后体积增长与移速衰减，体积上限 3.0（Spec §5.2）。
- 实现触碰检测与同一敌人 0.8 秒伤害间隔。
- 实现生命值、生物质、进化点变化（产出比约 1:2.6）。
- 实现波次刷新：每 4:30 一波，共 3 波，威胁数量倍率 1×/2×/4×。
- 实现 4:30 的 3 选 1 微选择（暂停玩法，不选不继续）。
- 实现「进化」按钮：进化点 ≥ 100 时出现，不强制跳转。
- 实现 13:30 强制进入构筑阶段（进化点 < 100 则本局失败）。
- 实现失败即重开整局并清空 `RunData`（Spec §9）。

验收：
- 玩家能移动，手感有惯性。
- 玩家能吞噬小于自己的目标并增长资源与体积。
- 体积增大后移速可感知下降。
- 玩家会因威胁与危险区域受伤。
- 生命值归零会失败并可重开整局。
- 4:30 微选择正常触发并写入 `RunData`。
- 进化点达 100 后「进化」按钮出现，玩家可选择继续留场攒生物质。
- 13:30 强制跳转生效。

## 6. 阶段 3：器官/组织构筑阶段

目标：实现 6 选最多 2 的构筑选择，并传入生物阶段。

## 7. 阶段 4：生物阶段

目标：验证前三阶段选择的实战差异。

建议新增脚本：
- `CreaturePlayerController.cs`
- `CreatureEnemy.cs`
- `CreatureEliteEnemy.cs`
- `CreatureAbilityController.cs`
- `CreatureStageGoal.cs`

最小玩法（10 到 12 分钟）：
- 玩家控制小型生物移动与冲刺，管理体力。
- 场景中有 2 种普通敌人（草食虫巡逻 / 掠食虫追踪）。
- 场景中有 1 个精英敌人「顶级掠食者」。
- 玩家属性由细胞微选择 + 构筑模块共同决定。
- 三条路线在体感上有可测的差异。

时间结构：
- 0:00-4:00 生态区探索，击杀普通敌人，熟悉新形态。
- 4:00-8:00 敌人持续刷新，压力递增。
- 8:00 起 精英战。**进入精英战前生命值全满**，排除前段耗血的随机性。

路线体现（数值见 Spec §7.2 / §7.3）：
- 吞噬扩张型：最大生命值 190、近战伤害 24、击杀回血；移速最低 4.6。
- 功能特化型：移速 6.4、察觉范围 -35%、无敌帧 0.45 秒；生命值为基础 140，容错最低。
- 科技统治型：3.5 米放电攻击、体力上限 140；近身容错低。

任务：
- 实现生物玩家单位（基础生命 140 / 移速 5.0 / 近战 15、间隔 0.6 秒、距离 1.5 米）。
- 实现体力系统：上限 100、冲刺消耗 30、回复 12/秒、回复延迟 1 秒、无敌帧 0.3 秒。
  冲刺是**所有路线通用**的生存手段，保证三条路线都能风筝。
- 实现草食虫（40/8/3.0）巡逻与掠食虫（70/14/4.5）追踪。
- 实现敌人接触伤害，同一敌人 0.8 秒伤害间隔。
- 实现精英敌人（250/22/4.2）与冲撞技能（伤害 38 / 冷却 7 秒）。
- 将 2 个构筑模块转换为玩家属性（微选择不参与生物阶段属性计算）。
- 实现放电能力（科技统治型路线专属能力）。
- 实现精英战前满血。
- 实现胜利 / 失败结算，失败可选重试本阶段（保留构筑）或重开整局。

验收：
- 生物阶段能完整游玩，时长落在 10 到 12 分钟。
- 不同构筑路线的玩家属性或能力不同，且满足 Spec §14 的可测指标。
- **三条纯路线均可击败精英敌人**；任一条打不过则调整精英生命值后重测。
- 三条纯路线击败精英的耗时差异 ≥ 30%。
- 击败精英后进入总结，显示主导路线。
- 失败后可重试本阶段或重开整局。

## 10. 开发顺序

推荐顺序：
1. 建立 `FirstPlayableRunData` 和阶段状态机。
2. 从 `GameApp` 进入 First Playable。
3. 实现细胞阶段移动、吞噬（体积判定）、受伤、胜负。
4. 实现细胞阶段 3 选 1 微选择与路线倾向计分。
5. 实现波次刷新与「进化」按钮（玩家自主决定进化时机）。
6. 实现构筑数据、定价和 6 选 2 付费构筑 UI。
7. 实现生物阶段玩家、体力冲刺、敌人、构筑属性继承。
8. 实现 HUD、阶段结算、失败重开。
9. 补路线差异和精英敌人。
10. 按 Spec §14 的可测指标做一次完整验收（含三路线各跑一遍）。

不要先做：
- 正式美术。
- 完整配置表。
- 文明 RTS。
- 多场景资源加载。
- 复杂 AI。
- 完整存档。

## 12. 已确认的开发前提

以下均已确认，无需再问：

技术前提：
- 细胞阶段使用 **3D 平面**白模（基础几何体，颜色区分）。
- 输入使用 **键鼠 WASD**，带惯性（加速度 12 / 阻力 4）。
- 第一版**全部放在 `main.unity` 内**运行，流程稳定后再拆 `CellStageScene` / `CreatureStageScene`。

设计决定（2026-08-04）：
- FP 目标时长 **25 到 30 分钟**（非 45-60）。
- **生物质 = 货币**（器官阶段购买模块），**进化点 = 门票**（达 100 解锁进化，不消耗）。
- 细胞阶段 4:30 加入**一次 3 选 1 微选择**，构成三段继承链的第一段。
- 构筑**槽位 2 个 / 模块 6 个**，保证纯路线构筑可达。
- 进化点达门槛后**不强制跳阶段**，由玩家决定何时进化（留场越久生物质越多，但威胁递增）。
- `适应度` 资源已从首版移除。

所有玩法数值以 `First_Playable_Spec.md` §7 调参表为唯一来源，本文档中的数值仅为摘录。
两者若有冲突，以 Spec 为准。
