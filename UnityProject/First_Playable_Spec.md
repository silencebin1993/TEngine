# 文明织造 First Playable 开发规格

## 1. 目标

First Playable 的目标不是展示完整八阶段，而是验证项目最核心的承诺：

`细胞阶段的构筑选择 -> 器官/组织阶段形成结构差异 -> 生物阶段转化为可感知的生存或战斗优势`

目标时长：45 到 60 分钟。

覆盖阶段：
- 细胞阶段
- 器官/组织阶段
- 生物阶段

不覆盖：
- 远古竞争阶段
- 文明崛起阶段
- 大明势力登场
- 废土重建阶段
- 星海扩张阶段
- 宇宙终局阶段

## 2. First Playable 产品承诺

玩家从一个弱小细胞开始，通过吞噬、规避和构筑选择，让生命体逐步形成明确路线，并在生物阶段看到这些早期选择带来的能力差异。

这一版本必须让玩家明白三件事：
- 早期选择不是临时加成，而会进入下一阶段。
- 三条路线的体验确实不同。
- 阶段切换不是换小游戏，而是同一生命链条的升级。

## 3. 核心循环

短循环：
`移动 -> 获取资源/吞噬目标 -> 避开威胁 -> 获得进化点`

中循环：
`选择构筑 -> 完成阶段目标 -> 继承构筑结果 -> 进入下一阶段`

First Playable 完整流程：
`细胞求生 -> 选择器官/组织方向 -> 生物阶段验证能力 -> 结算本局路线`

## 4. 三阶段范围

### 4.1 细胞阶段

目标：验证最基础的移动、吞噬、规避和进化点获取。

玩家操作：
- 控制单个细胞移动。
- 吞噬比自己弱小或可吞噬的目标。
- 避开更强的捕食者或危险区域。
- 收集进化点。

核心资源：
- `生命值`
- `生物质`
- `进化点`

胜利条件：
- 在限定时间内积累足够进化点。
- 或完成指定吞噬数量。

失败条件：
- 生命值归零。
- 或限定时间内未达到进化门槛。

必须实现：
- 玩家细胞移动。
- 可吞噬目标。
- 威胁目标。
- 生命值变化。
- 生物质/进化点获取。
- 阶段结算与进入器官/组织阶段。

### 4.2 器官/组织阶段

目标：验证构筑选择和路线分化。

玩家操作：
- 在有限选项中选择器官/组织模块。
- 根据当前资源做取舍。
- 确认构筑后进入生物阶段。

核心资源：
- `进化点`
- `构筑槽位`

构筑规则：
- 玩家最多选择 3 个构筑模块。
- 每个模块必须归属一条原型路线。
- 构筑结果会在生物阶段转化为属性或能力。

首版构筑模块：
- `吞噬口器`：提高吞噬效率，偏吞噬扩张型。
- `厚壁细胞层`：提高生命值和容错，偏吞噬扩张型。
- `感知纤毛`：提高探测范围和移动操控，偏功能特化型。
- `协同神经束`：提高技能冷却或特殊动作效率，偏功能特化型。
- `原始放电囊`：提供短距离攻击能力，偏科技统治型。
- `能量导流组织`：提高资源转化效率，偏科技统治型。

胜利条件：
- 完成构筑并进入生物阶段。

失败条件：
- First Playable 中该阶段不设置硬失败，只允许玩家在有限资源下做不完美选择。

必须实现：
- 构筑选择界面。
- 至少 6 个构筑模块。
- 构筑槽限制。
- 构筑结果数据保存。
- 构筑结果传入生物阶段。

### 4.3 生物阶段

目标：验证前两阶段选择是否在实战中可感知。

玩家操作：
- 控制小型生物移动。
- 应对敌对生物或环境威胁。
- 使用由构筑带来的能力优势。
- 完成一次生存或战斗目标。

核心资源：
- `生命值`
- `体力`
- `适应度`

胜利条件：
- 击败阶段精英敌人。
- 或在压力环境中存活到指定时间并抵达目标区域。

失败条件：
- 生命值归零。

必须实现：
- 生物形态玩家单位。
- 至少 2 种普通敌人。
- 1 个精英敌人或终局压力源。
- 构筑模块转化为实际属性/能力。
- 生物阶段结算界面。

## 5. 三条原型路线的最小差异

### 5.1 吞噬扩张型

体验关键词：更大、更硬、更能吃。

细胞阶段倾向：
- 更容易通过吞噬获得生物质。
- 更能承受碰撞风险。

器官/组织阶段倾向：
- 选择生命值、吞噬效率和体型相关模块。

生物阶段体现：
- 更高生命值。
- 近距离压制能力更强。
- 容错更高，但机动性较弱。

### 5.2 功能特化型

体验关键词：更灵活、更依赖组合、更吃操作。

细胞阶段倾向：
- 更容易规避危险。
- 更依赖路线选择和时机判断。

器官/组织阶段倾向：
- 选择感知、移动、冷却和协同模块。

生物阶段体现：
- 移动与特殊动作更强。
- 能通过操作避开正面对抗。
- 生存上限高，但失误惩罚更明显。

### 5.3 科技统治型

体验关键词：更远、更准、更偏后期。

细胞阶段倾向：
- 早期较弱，但资源转化效率更高。

器官/组织阶段倾向：
- 选择放电、能量导流和远程输出模块。

生物阶段体现：
- 获得短距离攻击或范围打击能力。
- 更适合提前处理危险。
- 近身容错较低。

## 6. UI 需求

必须有：
- 主菜单入口。
- 阶段目标显示。
- 生命值显示。
- 生物质/进化点显示。
- 构筑选择界面。
- 阶段结算界面。
- First Playable 结束总结界面。

暂不做：
- 完整图鉴。
- 科技树总览。
- 大地图。
- 多文明外交界面。
- 复杂背包。
- 多结局展示。

## 7. 数据与配置

首版数据对象：
- 玩家基础属性。
- 敌人基础属性。
- 构筑模块配置。
- 阶段目标配置。
- 资源获取配置。

建议最小配置表：
- `StageConfig`
- `EvolutionModuleConfig`
- `EnemyConfig`
- `PlayerFormConfig`

配置优先级：
1. 先硬编码打通流程。
2. 再把构筑模块和敌人参数抽到配置。
3. 最后再考虑完整 Luban 表结构。

## 8. 明确不做

First Playable 不做以下内容：
- 文明 RTS 完整系统。
- 大明王朝势力。
- 废土阶段。
- 星海阶段。
- 宇宙终局。
- 完整科技树。
- 完整存档系统。
- 多结局。
- 支线事件。
- 复杂外交。
- 开放世界地图。
- 大量敌种。
- 正式美术资源。

## 9. 验收标准

First Playable 通过标准：
- 玩家可以从细胞阶段进入器官/组织阶段，再进入生物阶段。
- 细胞阶段至少有吞噬、受伤、资源获取和失败。
- 器官/组织阶段至少有 6 个可选构筑模块。
- 生物阶段能明显体现至少 3 条路线的差异。
- 玩家能完成一次 45 到 60 分钟以内的完整前三阶段体验。
- 失败后可以重新开始。
- 阶段切换时，前一阶段选择会真实影响后一阶段。

## 10. 最高风险

设计风险：
- 三阶段仍然像三个小游戏，而不是一条生命成长链。

制作风险：
- 过早把生物阶段做成完整动作游戏，导致范围膨胀。

内容风险：
- 构筑模块数量增加太快，导致路线差异无法验证。

控制原则：
- 先验证 3 条路线是否真的有体感差异。
- 每阶段只做一个核心目标。
- 每条路线只做两个代表模块。
- 生物阶段只做一个最终压力测试。
