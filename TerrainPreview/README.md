# 《地球归还》无缝地形试验场

这是独立的视觉预览工程，使用 Unity 6000.3.17f1 / Built-in RP。
代码和资源连接到同一个 worktree，完全不读取或写入 Claude 正在开发的战役工程。

## 打开与体验

最方便的入口：双击本目录的 `打开地形试玩.cmd`，无需打开游戏主工程。
可以点「河谷全景」「楼墟聚落」「断桥岩谷」切换观察点，改种子后点「生成」。
新版加入工业核心、四处仓储地块、储罐、道路、管线、分层楼墟、断桥和高岩壁。
点「切换 Orbis 地形对比」可以在同一场景观察原生四叉树地形。高度数据准备时原地面保持显示。
Orbis 对比区为 1024×1024 米，地貌采用 1 米高度采样；离开这个区域会恢复连续地图。

打开本目录的 Unity 工程，再打开 `Assets/GameRes/Raw/TerrainLab/Scenes/TerrainLab.unity`，按 Play。
WASD 移动，右键转动镜头，滚轮前后，Q/E 升降，Shift 加速，空格回到谷地，Tab 隐藏面板。
面板可以更换种子、显示区块边界、关闭场景件和连接废墟。

菜单「地球归还 → 地形素材管理」可以编辑连接模块网格、四边接口编号、允许角度、出现权重、坡度、离地偏移和环境色板。
相邻接口必须同号，0 表示无连接。连接库不超过 63 个旋转变体。

## 实现边界

- 连续世界坐标采样：同一个点不受访问顺序、区块位置或生成线程影响。
- 高度、颜色、法线从同一个场函数得到，区块两边一致。
- 混合细节等级：每条区块边都使用相同的 4 米世界坐标锚点。细边顶点对齐这条折线，因此异步切换细节时也不依赖邻块同时完成。网格内部仍有 1/2/4 米细节等级。
- 材质使用世界坐标 UV，不为每块地形重新开始纹理。
- 地表由连续高度场生成。建筑采用六面连接、竖向支撑、立面族匹配与有限回溯的 WFC。
- 建筑地块和道路先规划，再生成楼层与屋顶；家园仓库入口接入支路。建筑部件按区块合并网格。
- Orbis 的泊松采样用于草丛分布，并过滤道路、建筑和水下位置，检查相邻区块的最小间距。
- Orbis 岩土贴图用于地表与风化材质，按坡度进行世界坐标三面投影。
- 对比模式直接运行导入库的四叉树细分、Burst 网格任务与渲染系统；适配器位于预览工程 OrbisBridge。
- 废墟片区按世界种子和片区坐标独立求解；片区外接口封闭。跨区块的片区只解同一结果，各模块按中心位置归属唯一地块。一个模块的权重分配给所有允许的角度，开启更多角度不会自动提高其总概率。
- 背景任务最多 2 个，主线程每帧最多上传 2 个区块。生成的网格、材质和对象都有释放路径。
- Blender 源文件：`UnityProject/Assets/GameRes/Art/Terrain/pcg_terrain_kit.blend`；每个部件独立 FBX，位于 `Raw/TerrainLab/Models`。

## 主线接入说明

预览使用可调的连续地貌演示源，不替换战役的 `WorldGenMath`、种子、资源分布、寻路或存档。
生产接入由现有世界生成器输出不可变、线程安全的采样快照，实现 `ITerrainField`，再调用 `TerrainStream.SetField(snapshot, seed)`。演示用的废墟选址只在演示地貌源上启用；生产剧情锚点和废墟选址留给主线提供。
当前主线可走/可建地的高度为 0；视觉接入必须保留这一契约，不能把预览丘陵直接用于现有机器和建筑。
预览完整交付不等于 FG8-GEN-02 领地、室内和剧情锚点已完成。

## 证据

自动几何检查、连接求解检查和真实 Play 截图位于原工作台的 `production/qa/evidence/pcg-terrain-lab/`。
观感由用户试玩评判，自动检查只证明接缝、确定性和连接约束。

## 重建与素材制作

此预览工程的代码、地形素材和 Orbis 依赖连接到同 worktree 的正式源代码与 GameRes，避免维护两份实现。
如果重新检出工程，先初始化 `UnityProject/Assets/GameRes` 内容子模块，再执行 `PreparePreview.ps1`；它只创建缺失链接和对应的元数据，不覆盖已有目录。
Orbis 原始资源备份于本地内容仓的 `Art/Terrain/.ThirdParty/Orbis_Terrains`，按用户已取得的授权使用；隐藏备份目录不参与主工程导入，仅通过预览工程链接使用。GitHub 代码仓不收录该库源码、演示素材、Unity 恢复场景或试玩构建产物。
通过「地球归还 → 地形 → 建立测试场景」重新建立场景和运行验收；通过「生成独立试玩版」重建 Windows 试玩包。
Blender 中运行 `TerrainKitSource.py` 可更新基础 11 个部件；运行 `TerrainDetailSource.py` 可更新新增 19 个建筑与环境部件。
两份脚本仅修改本工具拥有的对象，分别导出 FBX；完成后保存当前源文件。
默认接口格宽为 4 米；更换格宽时需要同步模型端点。管理窗口的连接检查会验证实际模型边界，而不只验证接口编号。

技术依据：[WFC 作者算法说明](https://github.com/mxgmn/WaveFunctionCollapse)、[Unity 6.3 实例颜色与批量绘制](https://docs.unity3d.com/6000.3/Documentation/Manual/gpu-instancing-per-instance-properties.html)。

复用来源、许可与性能比较边界详见 `Assets/GameRes/Raw/TerrainLab/THIRD_PARTY.md`。

## 本轮验证

连续地图：8 个种子、32 处接缝、32 处细节等级边界、192 处异步边界组合、40 次连接求解通过。
新增建筑：10 次确定性拼装、竖向支撑、屋顶封口、立面族和四处仓库入口连接通过。
Orbis：全景、移动到近景、切换种子均正常；原生网格顶点与地貌源误差小于 1 毫米。
泊松分布：相邻四块地形的最小间距和重复生成结果通过。

本机 RTX 4070、1600×900、各视角静止测量 4 秒，两种后端都约 200 FPS。
全景下连续后端 169 个地形网格 / 91,136 三角；Orbis 55 个网格 / 120,128 三角，覆盖更远地表。
两者细节策略和范围不同，这次数据不足以判断完整游戏中谁更快。
默认试玩仍限制 120 FPS；对比测试暂时取消 Unity 的限制。
这是本地视觉试验场，当前资产仍偏低多边形，尚未达到概念图的写实破损密度。
